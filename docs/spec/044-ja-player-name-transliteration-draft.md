# 044 — 日文玩家名音譯（片假名）與日韓共同前端

狀態：**DRAFT**（2026-10-01）
日期：2026-10-01
Issue：#35
前置：規格 037（中文音譯器，同型做法）、038（玩家名判定與顯示）、040（多語框架）、042（日文）、036（譯名表）。
後續：045 韓文玩家名音譯（共用本規格 §3.1 至 §3.3 的前端）。

## 1. 為什麼要做

使用者決定（2026-09-29）：日文模式的玩家名用片假名音譯，格式同中文「譯名(英文)」，窄欄只顯示譯名。規格 042 §3.7、043 讓 `PlayerNames` 在 ja、ko 停用（`playersOff=no-transliterator`），
玩家名維持英文，語言本身不失效。本規格補上日文的音譯器與接線，並把日文、韓文共用的「英文名到音素」前端定義一次。

## 2. 證據（已證實，除非標明）

- 接線點很小：`nameTransliterator` 介面只要 `Transliterate(name string, gender translit.Gender) (string, translit.Tier, bool)`（`apps/buckrogers/player_name.go`），
  `NewPlayerNames(tr, names)` 先查該語言的名字表（`ChineseFor`，ja、ko 各自載入各自的 `name-glossary.<lang>.tsv`），查不到才呼叫音譯器。
  ECL 路徑把結果組成 `譯名(英文)`，放不下時降段（只譯名、再退回英文），不管語言（`ecl_text.go` 玩家名分支）。目前只有 zh-TW、zh-CN 在 `live_lane.go` 設定音譯器。
- 專案音譯詞典（`text/translit-names.tsv`）的 85 個英文名全在 CMU 發音詞典（`text/cmudict/cmudict.dict`）內；名字表中不在 CMUdict 的 12 個字（`TURABIAN`、`HOLZERHEIN` 等）由名字表本身處理，不經音譯器。
- 日文字型字集（`font/charset.ja.txt`，6,686 字）含片假名 U+30A1 至 U+30F6（90 個中除 `ヷ` 至 `ヺ` 四個外全含）、`ー`（U+30FC）、`・`（U+30FB）；現行字型子集（`font/characters.ja.txt`）只含其中 78 個片假名，
  音譯輸出要保證渲染，字型子集必須先含全部可能輸出的字（做法同規格 037 §3.4 的 `translit-chars`）。
- 日文名字表（`text/name-glossary.ja.tsv`）寫多字名用 `・`，例 `アレクサンダー・ウィリアムズ`；韓文用空白（見規格 045）。
- 原版角色名可含數字、空白、`.`、`?`，也可只有一個字元（規格 037 §2，phase-244）；名字最長 15 字元（規格 038 §3.1）。
- 日文片假名沒有單一官方的英語轉寫標準；本規格的規則是專案自訂（依內閣告示《外来語の表記》的音韻對應與常見人名慣例整理），由專案詞典與固定測試名單校準，**母語者未校對**（§5）。

## 3. 契約

### 3.1 介面與載入（日韓共用，Go，通用層 `xlate/translitjk`）

- `Load(textDir, lang string) (*Transliterator, error)`，`lang` 為 `ja` 或 `ko`；`Transliterate(name string, g translit.Gender) (out string, tier translit.Tier, ok bool)`，`g` 不使用（假名與諺文沒有性別用字）。
  `Tier` 沿用 `translit.Tier`（`dict` ＞ `cmudict` ＞ `spelling`）。純函式、決定性、可多 goroutine 並行使用；不寫檔、不進存檔。
- 名字先轉大寫、以空白切成字；**任一字含 A–Z、`'`、`-` 以外的字元時整名 `ok=false`**；單一字母的字整名 `ok=false`；多個連續空白視為一個；整名沒有任何字時 `ok=false`（同規格 037 §3.1）。
- 含 `-` 的字：各段分別走完整查找，結果依原位置連接；連接符號見各語言規格（ja §3.4）。`'` 查詞典與 CMUdict 時保留原拼寫，拼寫後備時先去掉。
- 輸出每個字元都必須在該語言的允許字集內（§3.5）；否則整名 `ok=false`。
- CMU 發音詞典只載入一份（以路徑為鍵、進程內共用）；載入失敗時只讓該語言的玩家名停用（`playersOff`），語言本身照常運作。

### 3.2 每個字的查找順序（日韓共用）

1. 專案詞典 `text/translit-names.<lang>.tsv`：欄位 `english`、`translation`、`basis`；`english` 全大寫、不含空白；人工審定或機器草擬後審定，可放慣用譯名。命中即為 `dict`。
2. CMU 發音詞典：取該字**第一個**讀音（ARPAbet，帶重音數字），走各語言的音素到字規則。命中為 `cmudict`。
3. 拼寫後備：字母組合轉近似 ARPAbet 音素（輔音雙字母 `ch sh th ph ck ng gh wh qu kn wr`，元音字母組，詞尾不發音的 e 使前一個元音讀長音），再走同一組音素到字規則。標 `spelling`，品質最差，供診斷區分，仍照常顯示。
   後備產出為空（例如只含 `h`）整名 `ok=false`。`tier` 取各字中最低的來源等級。

### 3.3 音素前端（日韓共用）

- ARPAbet 39 音素；元音帶重音數字（0、1、2）。重音 1、2 為「有重音」，0 為「無重音」。
- 元音與拼寫對應：為了區分 `AA` 讀 a 或 o、無重音 `AH0` 的字母，前端把音節內的元音音素與單字的**元音字母組**（連續的 `a e i o u y`）依序對齊；兩邊數量相同時，每個元音音素得到對應的字母（`a`、`e`、`i`、`o`、`u`、`y`），不同時不給字母。
  後端只在規則明列時才用這個字母（`AA`、`AH0`、`AO` 的少數情形），沒有字母時走預設。
- 音節邊界：元音為核，其前的輔音串歸該音節的頭（`NG` 例外：永遠是前一音節的尾）；詞尾輔音串歸最後一音節的尾。後端規則以「元音之後、是否緊接元音」判斷輔音的角色（頭或尾），不另外做重音位置判斷。
- `R` 在元音前是頭；在元音後、輔音或詞尾前是「元音的 r 色彩」（`AA R`、`ER` 等），由各語言後端依自己的規則處理（日文拉長、韓文省略）。

### 3.4 日文：音素到片假名

**單位。** 先把音素串切成拍（mora）：頭輔音串的最後一個輔音與元音合成一拍，其前的輔音各自成一拍並補母音（§3.4.3）；尾輔音依 §3.4.3 成拍。

**3.4.1 元音。**

| 音素 | 片假名（元音列） | 備註 |
|---|---|---|
| `IY` | イ列＋`ー` | `Lee` リー |
| `IH` | イ列 | |
| `EY` | エ列＋`イ` | `Kate` ケイト |
| `EH` | エ列 | |
| `AE` | ア列；`K`、`G` 之後為 `キャ`、`ギャ` | `Kathy` キャシー、`Sam` サム |
| `AA` | ア列；拼作 `o` 時為オ列 | `Scott` スコット |
| `AH` | 有重音：ア列；無重音：依對應字母 `a`→ア、`e`→エ、`i`→イ、`o`→オ、`u`→ア，無字母→ア | |
| `AO` | オ列＋`ー` | `Paul` ポール |
| `OW` | オ列＋`ー` | `Joe` ジョー |
| `UW` | ウ列＋`ー` | `Lou` ルー |
| `UH` | ウ列 | |
| `AW`、`AY`、`OY` | ア列＋`ウ`、ア列＋`イ`、オ列＋`イ` | |
| `ER` | ア列＋`ー`（吃掉後面的 r） | `Peter` ピーター |

「X 列」指與頭輔音合成的拍，例如 `T`＋`IY` 為 `ティー`，`S`＋`EY` 為 `セイ`。

**3.4.2 輔音（頭輔音＋元音列，括號為例外格）。**

`K` カ キ ク ケ コ；`G` ガ ギ グ ゲ ゴ；`S` サ シ ス セ ソ；`Z` ザ ジ ズ ゼ ゾ；`T` タ ティ トゥ テ ト；`D` ダ ディ ドゥ デ ド；`N` ナ ニ ヌ ネ ノ；`HH` ハ ヒ フ ヘ ホ；`B` バ ビ ブ ベ ボ；`P` パ ピ プ ペ ポ；
`M` マ ミ ム メ モ；`R`、`L` ラ リ ル レ ロ；`F` ファ フィ フ フェ フォ；`V` バ ビ ブ ベ ボ（不使用 `ヴ`）；`W` ワ ウィ ウ ウェ ウォ；`Y` ヤ イ ユ イェ ヨ；`SH` シャ シ シュ シェ ショ；`CH` チャ チ チュ チェ チョ；
`JH`、`ZH` ジャ ジ ジュ ジェ ジョ；`TH` サ シ ス セ ソ（`th` 視同 `s`）；`DH` ザ ジ ズ ゼ ゾ。每列依 ア イ ウ エ オ 的順序。`Y`＋`IY` 為 `イー`，`Y`＋`UW` 為 `ユー`，`W`＋`UW` 為 `ウー`。

**3.4.3 尾輔音與輔音串（補母音）。** 不接元音的輔音各自成拍：`T`、`D` 補 `ト`、`ド`；`CH`、`JH` 補 `チ`、`ジ`；`SH` 補 `シュ`；`F` 補 `フ`；其餘補ウ列（`ク ス ブ グ ル ム プ ズ`）。
`N` 在尾或輔音前為 `ン`；`M` 在詞尾為 `ム`、在輔音前為 `ン`；`NG` 在 `K`、`G` 前為 `ン`，其餘為 `ング`。

**3.4.4 元音後的 r 與促音。**

- `AA R`、`AO R`、`OW R` 為元音列＋`ー`；`EH R` 為 `エア`；`IH R`、`IY R` 為 `イア`；`UH R`、`UW R` 為 `ユア`；`AE R` 為 `アー`；`ER` 見 3.4.1。`R` 在元音前時是頭輔音（`ラ` 行）。
- 促音 `ッ`：有重音的短元音（`AE EH IH AH AA UH`）後接**音節尾**的 `K`、`P`、`T`、`CH`、`JH`、`D`（詞尾或接輔音前）時，在該輔音拍前加 `ッ`（`Jack` ジャック、`Ted` テッド）。兩個元音之間的輔音不加（`Betty` ベティ）。
- `ー` 不接在 `ン`、`ッ` 之後，不連續兩個；詞首不出現 `ッ`、`ー`、`ン`。

**3.4.5 組成。** 多字名以 `・`（U+30FB）連接；連字號的各段同樣以 `・` 連接。`tier` 取各字最低。

### 3.5 允許字集與字型

- 日文允許字集 = 片假名 U+30A1 至 U+30F6 ∪ {`ー`、`・`} ∪ 專案詞典全部用字；專案詞典 lint：每個 `translation` 的字都要在允許字集內且字型字集（`charset.ja.txt`）含之。
- 工具 `tools/translit_jk.py chars --lang ja` 產生 `text/translit-chars.ja.tsv`（一列一字，`key`、`translation`、`source`，進正式 catalog），字型子集因此固定包含這些字。規格 042 §3.2 把 `translit-chars` 列為「不產生 ja 檔的家族」（指不與 zh-TW 的漢字允許字集一一對應），本規格新增的是 ja 自己的允許字集檔，`lang_check.py` 仍照 `no_files` 跳過該家族的對照。
- 字型子集重建與 manifest 雜湊重記，依規格 043 的註記。

### 3.6 接線與顯示

- `live_lane.go`：`LangJa`（與規格 045 的 `LangKo`）在 `PlayerNames` 設定處載入 `translitjk`，成功才 `NewPlayerNames` 並 `SetPlayerNames`；失敗只設 `playersOff`。
- 顯示格式、降段、窄欄只譯名、名字註記階層：完全沿用規格 038 與 036，不改。日文名字比中文長（`ROARKE` 為 4 個全形字，zh-TW 為 2 個），寬度不夠時依既有降段落到只譯名，再落到英文。
- ECL 的 `譯名(英文)` 以半形 `(` `)` 組成，與 zh-TW 相同；名字註記單位涵蓋整個 `譯名(英文)`。
- 名字表命中優先於音譯（`ChineseFor`），玩家取名與名字表人物同名時顯示名字表譯名（規格 038 §3.2）。

## 4. 不做什麼

- 判斷字串是不是玩家名、各畫面怎麼顯示（規格 038）。
- 非英語名字的專門規則（照英語處理）、日文名字的漢字寫法、長音與促音的多種慣用寫法並存（只出一種）。
- 手冊段落、母語者校對（§5）。

## 5. 驗收

1. 單元測試：§3.4 每個表格列與每條規則至少一個樣本；三層查找各有命中樣本；含數字或標點的名字（`A 1.?`、`R2D2`）與單一字母名（`Z`）回 `ok=false`；含撇號或連字號的名字（`O'BRIEN`、`MARY-JANE`）正常；允許字集外的輸出回 `ok=false`；決定性；輸出不含 `ッ`、`ー`、`ン` 開頭或 `ーー`。
2. 固定測試名單與期望輸出（人工審定後入庫）：`ROARKE`、`CELESTE`、`FLAVIUS`、`JANELLE`、`PIERRE`、`NICOLE STEELE`，專案詞典的代表名（`ALEXANDER`、`JENNIFER`、`MICHAEL`、`WILLIAM`），
   以及與 NPC 或 ECL 短詞同形的 `BUCK`、`WILMA`、`PORT`、`EXIT`，另加輔音串、促音、元音後 r、`TH`、`W`、`Y`、`NG` 的各類名字（約 60 個，名單與期望值入 `docs/` 前先過兩位獨立審查者）。
3. 專案詞典 `text/translit-names.ja.tsv`：85 個英文名（與 `translit-names.tsv` 的 `english` 同集合），草擬後逐列審定，`basis` 記 `machine-reviewed`；lint 通過。
4. 字型：`translit-chars.ja.tsv` 與 `characters.ja.txt` 重建零缺字；`ja_check.sh`、`lang_check.py` 通過。
5. 離線與同狀態：日文通道的玩家名在隊伍欄、戰鬥欄、ECL 敘事顯示 `カタカナ(ENGLISH)` 或降段結果；非日文語言的收據、重播與零成本回歸不變；以前後對照收據（舊 runner 加舊資料對新 runner 加新資料）列出 ja 變動的畫面，其餘語言逐位元相同。

## 6. 開放項目

| 項目 | 消除條件 |
|---|---|
| 音素到片假名規則是專案自訂，慣用寫法有多種（`ヴ`、`ー` 與 `イ` 的長音、`ティ` 與 `チ`），母語者未校對 | 母語者校對固定名單與詞典；規則逐條調整並回寫 §3.4 |
| 拼寫後備品質差，原版名字多為英文常見名或幻想名 | 專案詞典逐步覆蓋；`spelling` 等級的名字在診斷計數 |
| 名字比中文長，窄欄與表格退回英文的比例 | 驗收第 5 點的收據量測各畫面實際降段情形；必要時另訂縮短規則 |
