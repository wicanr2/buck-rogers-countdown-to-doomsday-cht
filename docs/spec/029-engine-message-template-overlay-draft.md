## 1. 為什麼要做

戰鬥與探索中大量文字不是 ECL 劇本，而是引擎在執行期把固定片段與名字、數字接起來：

- 經 `0763:056C` 輸出（戰鬥右欄、事件）：`<名字> makes his tactics roll.`、
  `Hitting for <n> points of damage`、`<武器> (<n>)`、`<名字> leads <名字>.`。
- 經 dispatcher `0763:0424` 輸出：`Hitpoints`、`AC`、`can't go there`、
  `Move/Attack, Move Left = <n>`、座標列 `<x>,<y> <方位> <時間>`。

這些片段以 Pascal 字串存在 `GAME.OVR`、`START.EXE`；組合方式散在程式各處，
無法靜態列舉全部句子。本規格以「片段序列」為翻譯單位。

### 2.2 分解

1. **詞界**：位置 p 是詞界，當 p = 0、p = len(s)，或 s[p−1] 與 s[p] 不同時為 ASCII 字母。
   片段 s[i:j) 只在 i、j 都是詞界時可用。
2. **最短長度**：長度小於 3 的片段只在整串等於該片段時採用。
3. **全大寫片段不用**：只含大寫字母、空白與標點的片段不參與分解（引擎片段是大小寫混合；
   玩家名字、怪物名、ECL 字串是全大寫）。這保證全大寫的名字不會被片段吃掉。
   例外：整串恰等於某片段時（如戰鬥右欄的 `AC`），以該片段為唯一 signature。
4. **物品名先認領**：物品名在執行期由物品單字表（`DS:1CE2` 起，每筆 21 位元組的
   string[20]，54 筆；見 phase-260）的單字以空白串成。分解前先找出「由物品單字連成、
   以單一空白分隔、兩端落在詞界」的最長連串（大小寫須完全相同；多字單位如兩字詞組
   視為一個單位）。連串有兩個以上單位，或只有一個單位但緊接 ` (` 加數字時，
   標為物品空位 `I`。物品空位的中文 = 整段查 `text/item-phrase.zh-TW.tsv`
   （可選覆寫）；沒有則逐單位查 `text/item-word.zh-TW.tsv` 直接串接（中文修飾語在前、
   名詞在後，與英文語序相同）。任一單位缺譯文則整串退回英文。
5. 在剩下的部分，取片段總長最大的切法；同分取片段數最少者。相鄰空位合併。

signature 以片段 key、一般空位 `_`、物品空位 `I` 組成；物品空位不與相鄰一般空位合併。
模板 catalog 命中才畫，否則退回英文。

### 2.3 輸出點與呈現

- `0763:056C`：規格 027 未命中（含缺譯文）時，改走本規格；命中則比照規格 027
  的呼叫期間、排版、遮罩、接續與失效規則。
- dispatcher `0763:0424`：只處理呼叫端在白名單 `text/engine-dispatch-callers.tsv`
  （`caller`、`note`）內的事件。白名單只收已量到、且不屬既有家族（主選單、名冊、角色頁、
  技能頁、身體圖示、手冊、加入後選單）呼叫端的位址；載入時若與既有家族的呼叫端重疊即失敗。
  初版白名單取第二百五十八階段表列的遊戲內呼叫端。
  與既有家族共用的名稱欄呼叫端另列 `text/engine-dispatch-name-callers.tsv`：只在整串
  恰為怪物名時畫中文（既有家族以精確雜湊認領字串，怪物名不在其 catalog 內）。呈現範圍是原版事件的列與 `[欄, 欄 + 原文長度)`，譯文須放得下；
  遮罩與失效沿用既有 dispatcher 家族的 guarded return 與相交寫入規則。

### 2.4 片段串接（預設）與模板（覆寫）

- `text/engine-fragment.zh-TW.tsv`：每個片段的中文。signature 命中模板時用模板；
  否則若所有片段都有中文，依原順序串接：片段換成中文、物品空位換成中文物品名、
  一般空位原樣保留（空位自帶的空白也保留）。
- 空白規則（判斷依據是執行期當次整串的片段原文，只在 watcher 內暫存，不進 catalog）：
  片段譯文一律不含頭尾空白（翻譯指令明定，合併工具檢查）。片段原文以空白開頭、
  且前一段是一般空位、該空位最後一個字元是英數字時，在譯文前補一個半形空白；
  片段原文以空白結尾、且後一段是一般空位、該空位第一個字元是英數字時，在譯文後補一個
  半形空白。空位自己已帶空白時不再補，所以不會重複。中文與中文之間不加空白。
  例：`FLAVIUS` + ` makes ` → `FLAVIUS 進行`；`Bolt Gun` + ` (100)` → `爆能槍 (100)`。
- 任一片段缺中文且無模板時，整串退回英文。
- 模板用在語序必須調換的句子，是例外不是常態。signature 元素可寫 `*`，對應任一段
  （片段、物品空位或一般空位）；譯文的 `{n}` 依序引用模板中所有非片段 key 的元素
  （`_`、`I`、`*`）對應段的中文。沒有 `*` 的模板優先比對（修訂 2026-09-26）。

### 2.6 表格列的最後一欄對齊（修訂 2026-09-26；兩輪審查後 READY）

- 整串以「非空白字元＋兩個以上空白＋最後一個不含空白的欄位」結尾時（例：
  `Laser Pistol (10)                  335`、`Personal funds:      1000`），視為表格列：
  前段（去掉尾端空白後）照 §2.2–§2.4 翻譯，不另立機制；最後一欄原樣保留，中間補空白
  使總長度等於原文長度，最後一欄因此留在原本的欄位。失敗時：
  1. 前段依 §2.4 翻不出來 → 改對整串照 §2.4 翻譯（修訂 2026-09-27：`Pooled funds:           0`
     的片段是整串含空白，前段單獨查不到，原本整串翻得出來，phase-271）；整串也翻不出來則退回英文。
  2. 前段翻得出來、但加一格空白後放不下 → 直接退回英文，不改走整串。
- 最後一欄只在是數字、或數字與 `,`、`/`、`(`、`)`、`%` 組成時才適用；否則照 §2.4 處理。

### 2.6.1 與既有家族的讓位（修訂 2026-09-26，角色頁樣本）

- 原規則沿用規格 028 §3.4：合成時其他家族改動了本頁任一列的像素，整頁不畫。
  角色頁的欄名（舊家族）與值（本家族）同在一列，整頁因此被跳過（phase-266 補記）。
- 改為逐列、只看本列的原文格：某一列在 `[欄, 欄 + 原文長度)` 範圍內的像素已被其他家族
  改動時，只跳過該列；其他列照畫。判斷用「已合成的畫面」與「原版畫面放大」逐像素比較，
  與原規則相同，只是範圍縮小。
- 只要像素與原版不同即算改動，不論舊家族畫了完整文字，或只是重畫底色、清空：這是刻意
  選擇，§2.5 的互斥完全依賴這條。
- 判斷範圍 `[欄, 欄 + 原文長度)` 與本家族實際繪製的格一致：兩者讀的是同一次 dispatcher
  呼叫的同一組參數，譯文長度恆等於原文長度（不足補空白）。
- 規格 028 的水平選單維持整頁讓位，不受此修訂影響。

### 2.9 ECL 字串經 dispatcher 印出（修訂 2026-09-26；覆審後 READY）

- ECL 的挑人指令（例如「WHO FALLS ON GRENADE?」「WHO SHOOTS?」）把 ECL 字串加一個尾隨空白，
  交給 dispatcher 從第 24 列印出（呼叫端 `OVR:2BA60:101E`，已列共用呼叫端；phase-269）。
  規格 027 的 ECL catalog 以整串雜湊比對，含尾隨空白的字串對不上。
- 規則：dispatcher 字串先依 §2.8、§2.6、§2.4 的順序處理；都翻不出來時，去掉尾端空白後
  若與 ECL catalog 某則原文逐位元相同、且該則有譯文，採用該譯文，後面補回原本的尾端空白數；
  長度超過原文則退回英文。只去尾端空白，不去開頭空白、不改大小寫。
- 只用於 dispatcher 路徑；`0763:056C` 敘事窗本來就用 ECL catalog。所以這一步放在
  dispatcher watcher 的進入處理中、`Translate` 失敗之後，不放進共用的 `Translate`。
- 「尾端空白」只指 0x20，不含其他字元。
- 介面：dispatcher watcher 新增一個 ECL catalog 參照（setter），live runtime 載入時把
  規格 027 的 catalog 一併交給 dispatcher watcher；沒有 ECL catalog 時略過這一步。
- 同一個呼叫端（例如 `OVR:2BA60:101E`）可能印出「Items: 」這類引擎字串，也可能印出
  ECL 挑人提問；兩者依字串內容區分（先 §2.8／§2.6／§2.4，再 ECL 精確比對），不依畫面情境。

### 2.10 被自動換行拆開的片段（修訂 2026-09-27；拆點修訂覆審後 READY）

- 引擎把較長的訊息依寬度換行，一個片段拆成兩次 dispatcher 呼叫、印在相鄰兩列
  （例：`  No injuries were successfully` 在第 3 列、`treated.` 在第 4 列，呼叫端 `0763:1282`；
  phase-271）。兩段各自都不是完整片段，§2.4 翻不出來。
- 規則（在 §2.8、§2.6、§2.4、§2.9 都失敗之後）：
  1. 第一段 S1 翻不出來時，暫存（S1、列、欄、呼叫端），這一次不畫。catalog 只有雜湊，
     不做前綴比對。
  2. 下一次 dispatcher 進入來自同一呼叫端、列號加一、字串 S2 也翻不出來時，依序以
     S1＋一個空白＋S2、S1＋S2 的整串雜湊查片段 catalog（與 §2.4 相同的整串查法）；
     命中且有譯文時，把譯文拆成兩段，前段放 S1 的列與欄、後段放 S2 的列與欄，一次畫兩列。
     前段盡量放滿 S1 的格數（放不超過 len(S1) 個字），剩下的放後段；後段放不下就整組退回英文。
     譯文在前段就放得下時，後段為空白（遮住原版第二列的英文）。（修訂 2026-09-27：原本依英文
     長度比例拆點，實測把「傷勢」拆在兩列，phase-271。）
  3. 其他任何 dispatcher 進入、或呼叫期間外對 S1 所在列 `[欄, 欄＋len(S1))` 的 A000 寫入，都清除
     暫存。這個檢查獨立於已畫行的失效檢查：畫面上沒有任何已畫行時也要做（dispatcher watcher
     的影像寫入處理不能因為「沒有已畫行」就提早返回，須同時看暫存是否存在）。
  4. 兩列一次畫時，兩列共用第二次呼叫的呼叫期間與返回驗證；S1 那一列在第二次呼叫期間內
     不受外部寫入檢查（與單行時同一套規則），這是刻意接受的空窗：第一次呼叫與第二次進入
     之間若有外部寫入，依第 3 點暫存已被清除，不會畫。
- 只處理拆成兩段的情形；三段以上不處理。

## 3. 不做什麼

- 不改原版字串、不寫 DOS 記憶體。
- 不猜未收錄的句型；未命中一律顯示原版英文。
- 不翻譯玩家自訂名字。

## 4. 驗收

1. 單元測試：分解（詞界判定式、短片段、全大寫片段不用、多詞專名認領、最大覆蓋）、
   模板套用、空位翻譯、未命中、dispatcher 白名單外不處理、白名單與既有家族重疊時載入失敗。
2. 靜態：片段 catalog 重建逐位元相同；模板引用的片段 key 都存在。
3. 原版同狀態：戰鬥開場（戰術判定、武器欄、選單）與一次命中傷害訊息，
   2×／3× 差異只在各訊息遮罩內。
4. 覆蓋率報告：自動遊玩收集的整串中，模板命中比例；另列「片段命中但相鄰空位只有
   0–1 字元」的疑似切碎案例，以及「同一片段出現在多個相異 signature」的清單，
   供人工複核語序（必要時加模板）。清單留 ignored 工作區。
5. 單元測試：空白規則四種情況（前補、後補、空位自帶空白不重複、中文相鄰不加）。
6. §2.5：共用呼叫端不屬既有家族時載入失敗；與白名單或名稱清單重疊時載入失敗；
   §2.6.1：舊家族已畫的列不畫、其他列照畫；純底色改動也讓位（合成測試）。
   多影格穩定性：在角色頁與 Hq 選單連續擷取多個影格，讓位判定一旦成立就持續成立，
   不在影格之間來回切換。
7. §2.6：表格列偵測（兩個以上空白＋最後一欄字元集）、最後一欄留在原欄位、前段翻不出來時
   改試整串（整串也不行才退回英文）、前段放不下時退回英文、最後一欄含字母時不適用。
8. §2.8：四個方位替換；格式不符（三位數、缺時間、小寫方位、多空白）照 §2.4；缺 key 或
   譯文非一字時載入失敗；座標列不命中 §2.6；探索畫面 A/B 的座標列顯示中文方位。
9. §2.9：含尾隨空白的 ECL 字串命中並補回空白；開頭空白或大小寫不同時不命中；
   譯文加尾端空白超過原文長度時退回英文；
   §2.4 能翻時不走 §2.9；太空港手榴彈場景 A/B 的提問顯示中文。
10. §2.6 修訂：前段翻不出來、整串可翻時用整串譯文。§2.10：兩段拼回唯一片段時畫兩列；
    不同呼叫端、列號不連續、拼不回、中間有其他進入時不畫；兩次進入之間有外部寫入 S1 列
    （且畫面上沒有其他已畫行）時不畫；整句在前段放得下時全放前段、後段補空白（不把詞拆開）；
    前段放滿、後段放不下的退回。
11. §2.1 明列短片段（2026-09-27 修訂）：
    - 單元測試：整串 `'s` 譯為「的」；`CELESTE's`、`CELESTE's Gear` 不切出 `'s`；
      `'s weapon is reloaded` 仍整段命中；`'S` 不命中；Go 與 Python 參考分解器對同組向量結果相同。
    - 靜態：抽取工具核對 `GAME.OVR:187675` 的長度位元組為 2、內容為 `'s`，不符就失敗；
      catalog 以同一工具重建逐位元相同。
    - 原版同狀態 A/B：物品畫面差異只在 `'s`、`Gear`（第 1 列）與 `Ready Item`（第 3 列）的原文格內；兩個名字長度不同的角色
      之間切換，不殘留「的」。

## 5. 第二輪審查未解項的處理（2026-09-26）

- 物品名：改為物品單字表模型（§2.2 第 4 步）。
- 字典範圍：第 4 步只用物品單字與詞組，不用 028 候選檔。

原未解紀錄：

- 物品名由詞表單字組成（如兩字武器名），`GAME.OVR` 只有單字條目，整段名稱不在任何字典內；
  §2.2 第 4 步對物品名不生效。需先逆向物品資料的詞表索引格式，建立「物品名詞組」字典。
- 規格 028 的項目候選檔是全字串盤點，混入引擎樣板片段；§2.2 第 4 步若直接用它，
  會把樣板句誤判成專名。第 4 步的字典必須限定為物品名與怪物名，不得沿用 028 候選檔。
- 混合大小寫的玩家自訂名字仍可能被片段吃掉（次要）。

解決前本規格維持 DRAFT，不實作。
