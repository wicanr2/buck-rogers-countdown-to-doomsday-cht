# 039 — 覆繪中的英數字改為半形

狀態：**DRAFT**（2026-09-29）
日期：2026-09-29
Issue：#34
前置：規格 031（原版英數字形，本規格取代其字形部分）、027、028、029、030、005、034、036、038、
010–017、022、001／018／020／021（選單類）、dosgolem 215（動作列）、239（改寫判斷）。
證據：本機盤點（2026-09-29，唯讀）；字型墨跡量測見 §2。

## 1. 為什麼要做

使用者決定（2026-09-29）：覆繪中的英文與中文字大小要配合。現況每個英數字佔一個原版 8×8 格（2× 為 16 像素寬），
並用原版 8×8 字形放大，英文顯得又大又長（例：「卡頓•特必安(CARLTON TURABIAN)」）。改為半形：字高與中文相同、
寬度一半，兩個半形字佔一個中文字寬。

使用者同日的細部定案：
- 字形用覆繪字型（發行版 Unifont、本機倚天）內的 8×16 半寬 ASCII，不再用原版 8×8 字形。
- 3× 半形字放大 1.5 倍成 12×24，填滿半格。
- 表格最後一欄的數字與座標列也改半形（接受與退回英文的原版列對不齊）。
- 空白、間隔號 `•`、水平選單項目間的分隔都算半格。

## 2. 證據

- 字型（已證實，Docker 內唯讀掃描本機兩份工作字型）：倚天 top-pad GOLEMFNT 的 ASCII 墨跡在 16×16 的
  x[4,11]、y[2,14]（`tools/eten_font.py` 把 8×15 每列左移 4、上補兩列）；Unifont 子集的 ASCII 墨跡在 x[5,11]、
  y[1,15]（`tools/catalog_font.py` 把 8×16 每列左移 4）。兩者取第 4–11 欄即為完整 8×16 半寬字模。
  `•` 的墨跡位置：未量（§3.2 要求工具驗證）。
- 版面（已證實，讀程式）：xlate 的 stamp 以 `X + i*CellW` 定位每個 rune，`CellW` 可為 4（2× 為 8 像素、
  3× 為 12 像素）；遊戲層已有逐段拆 stamp（說明頁）與 ASCII 前進 4 的先例（動作列）。xlate 是多個專案共用的
  通用層。
- 含英數字的覆繪家族（已證實，catalog 統計＋讀程式）：ECL 敘事、水平選單、引擎 dispatcher（含座標列、表格、
  隊伍名）、手札與手札面板、劇情第 1／2／6 頁、手冊 2× 與 3×（E1）、手冊英文列、主選單與加入後離開提示
  （`DOS`）、動作列。執行期另帶入玩家名與 NPC 加註、ECL 接續原文、引擎片段空位。
- 動作列現況（強推論，未實跑）：ASCII 助記字母以 `CellW=4` 畫 16×16 字模且位移後超出格寬，可能被裁掉一半。

## 3. 契約

### 3.1 寬度單位

- 半形單位＝4 邏輯像素（原版 8×8 格的一半）。半形字元：U+0020–U+007E 與 U+2022（`•`），各佔 1 單位；
  其他字元佔 2 單位（一個原版格）。
- 補位（把一列補滿到原版右緣或原文格數）與內容空白分開：補位用 U+3000（2 單位，`drawGlyphs` 不畫）；
  補到奇數單位時，最後以一個 U+0020 補 1 單位。內容中的 U+0020 是 1 單位。
- 所有容量、換行、欄位計算改以單位計；原本「N 格」的上限換算為「2N 單位」。

### 3.2 半形字模

- 由覆繪用的 16×16 字型衍生「半形衍生字型」：對每個半形字元取第 4–11 欄、第 0–15 列，得 8×16 字模。
  名稱為底字型名稱加 `.half8x16`。
- 3× 另衍生 12×24：以最近鄰取樣放大 1.5 倍（目的 x 取來源 ⌊2x/3⌋、y 取 ⌊2y/3⌋），名稱加 `.half12x24`。
- 字型工具（`tools/catalog_font.py`、`tools/eten_font.py`）在建置時驗證：每個半形字元的墨跡完全落在第 4–11 欄；
  任一字不符即建置失敗。
- 中文與其他全形字元的字模、放置、3× 22×22 衍生都不變。
- 規格 031 的原版 8×8 字形不再用於任何覆繪家族（§4）。

### 3.3 版面模型：按字寬拆 stamp

- 遊戲層新增共用函式：把一列文字拆成「同寬連續段」，每段一筆 stamp。半形段 `CellW=4`、用半形衍生字型；
  全形段 `CellW=8`、用原字型。段的 X 依累積單位計算（X＝起點＋單位×4）。
- xlate 通用層不改。
- 2×：半形段 `GlyphScale=1`、`GlyphX=0`、`GlyphY=0`（8×16 填滿 8×16 像素半格）。
  3×：半形段用 12×24 字型、`GlyphX=0`、`GlyphY=0`。
- 每個 rune 的前景色照各家族現行規則（例如 028 的熱鍵色），拆段不改變顏色歸屬。
- 同一列的段共用原本的失效與讓位範圍（§3.5）。

### 3.5 失效、讓位與快照

- ECL、水平選單、dispatcher、手札的失效在 watcher 層以原版 8×8 文字格判斷，不變。
- dispatcher 逐列讓位的像素範圍改以原版格數（`EngineDispatchLine.Width`）計，不再用 stamp 格數。
- 以 `Layer.Frame` 格指紋失效的家族（選單類、加入後選單、動作列、無 style 的手冊）：半形段的指紋格為 4×8；
  規格 239「有效錨定格 ≤ 2」改為以原版 8×8 格換算（兩個半形格算一格）。
- 快照：半形衍生字型有 `Name` 並登記進 font registry。

### 3.6 被取代或修改的既有條文

- 031：§3.2 的 16×16 原版字形衍生與 §3.4 劇情家族換字形，由本規格取代；原版字形表的搜尋（§3.1）不再用於
  字形，保留與否由實作決定並在收據註明。
- 027 §3（每字一格）、§3.4（起始列寬度）；028（項目間一格空白、總寬）；029 §2.3、§2.6、§2.6.1、§2.8、§2.10
  （字數等於格數）；030（36 欄、684 格、標題 38 格）；036、038 §3.3／§3.4（一字一格、可用格）；005（36 rune 硬切、
  3× 14 像素前進）；034（36 欄、字數上限）；010–017、022 的 ASCII 字形條文；dosgolem 215、239 的格數語意：
  皆改為依本規格以單位計。

## 4. 不做什麼

- 原版自己畫的英文（退回英文的字串、數值欄、玩家輸入、刻意保留英文的欄位）不改。
- host 前端的說明頁與設定面板（已是半格或 host 字型）不在本規格範圍。
- xlate 通用層的混寬 stamp（第二期整併另訂）。
- 多語（規格 040）。

## 5. 驗收

1. 字型工具：兩份字型的半形字元墨跡檢查（含 `•`）；合成負例（墨跡越界）建置失敗。
2. 單元測試：單位計算與拆段（純英文、純中文、混排、奇數長、內容空白與補位）；2× 與 3× 半形字模像素
   （含 1.5 倍取樣對照）；各家族容量邊界；熱鍵色逐 rune 不變；dispatcher 讓位範圍；選單換字無殘段；
   動作列助記字母完整。
3. 靜態回歸（Docker 內）：ECL、水平選單、引擎片段、手札在單位制下的溢出數、036 退路層級、038 候選、
   手札頁數與換頁點、手冊 39 題排列與 034 英文列題數，與現況列出差異清單（只記數量與 key，不輸出手冊內容）。
4. 同狀態 A/B（2×、3×）：027、028、029（含座標列與表格）、030、劇情第 1／2／6 頁、005（含 E1）、034、038、
   選單「離開至 DOS」、動作列。原版記憶體、indexed、palette 雜湊不變；像素差異只在含半形字的覆繪列。
   phase254 七條回歸以新一輪為基準並列出差異點。
5. 前端截圖：敘事、水平選單、全寬隊伍表、手札、劇情第 1 頁、座標列各一張 2×，另 3× 一張，供使用者確認。
