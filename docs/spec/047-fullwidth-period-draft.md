## 1. 為什麼要做

原版把句子的一部分分開畫：`DECK `、數字、句點、後半句各是一次呼叫，或把數字與句點當成同一個引擎欄位（`38.`）。
中文、日文的譯文本身用全形句號 `。`，但這個句點是原版畫的、不在任何 catalog 裡，現行規格 027 §3.7 把它「照原樣」接進排版，所以畫面是：

- zh-TW `你們身處第5.你們要往哪裡去？`、`位於第8.`、`編號 38.`
- ja `デッキ5.どこへ行く？`、`場所はデッキ8.`

半形句點貼在數字後面，後面沒有空白，也不是中文排版的句號。zh-CN 與 zh-TW 同型，ja 同型；韓文本來就用半形句點，不在本規格。

## 3. 契約

### 3.1 適用語言與語言怎麼進 watcher

zh-TW、zh-CN、ja。ko 不變（韓文用半形句點）。`zz`（測試語言）、`en` 不變：`zz` 保留為差分測試的未改動對照。空字串語言碼視為 zh-TW（與 `readLangTSV`、`EngineTextFiles.lang()` 一致）。

- ECL 層：`EclTextCatalog` 新增 `lang` 欄位，`LoadEclTextCatalogLang` 載入時設定（空字串正規化為 zh-TW；`LoadEclTextCatalog` 固定傳 zh-TW），並提供 nil 安全的 `fullStop()`：`lang` 為 zh-TW、zh-CN、ja 時為真。判定與排版 profile 無關（zh-TW、zh-CN、zz 的 profile 都是 nil，不能用 `layout == nil` 當閘門），也不看字型有沒有 `。`：ko 字型沒有 U+3002，閘門必須以語言碼判定。不需改 `live_lane.go` 的接線：每個語言通道載入自己的 ECL catalog。
- 引擎層：沿用規格 046 §3.1 的 `EngineTextCatalog.lang`（永遠是正規化後的語言碼）。
- `eclFixture` 等既有測試夾具預設 zh-TW，因此「沒碰的語言不變」的對照組要用 `LangTest` 另建夾具。

### 3.2 ECL：單獨的句點呼叫（修訂規格 027 §3.7，僅限 §3.1 的語言）

條件（全部成立）：

1. 本次呼叫在 ECL catalog、引擎片段、玩家名都未命中，進入規格 027 §3.7 的 passthrough（`ObserveEntry` 的 miss 分支且 `p != nil`）。旗標非零或游標在視窗外（fresh）的呼叫在此之前已移除本窗的頁，`p == nil`，不處理；玩家名分支（`isPlayer`）不處理，即使音譯失敗後落入 miss 分支。
2. `e.Original` 逐位元等於 `.` 或 `. `（不去頭尾空白；證據只有這兩個字串）。

動作：以 `。` 取代原文，不補空白（`. ` 的尾端空白也不顯示：中文與日文在 `。` 後不加空白，名字直接接在後面，規格 027 §3.1 已接受名字與中文之間沒有空白）。`key` 仍為 `passthrough`（名字註記階層的閘門不變，`。` 不套名字註記）；`Stats.Misses`、`Passthrough`、`Hits` 的計數與改動前相同，另計 `EclTextStats.FullStop`：它計入符合條件 1、2 而進入本節處理的每一次呼叫，不論最後畫出 `。` 或退回原文；`FullStopDropped` 是其中退回原文者，畫出 `。` 的次數等於 `FullStop` 減 `FullStopDropped`。退回後的排版仍溢出時，`Overflows` 照改動前的規則計一次，`FullStop` 與 `FullStopDropped` 各計一次。

「放不下」的定義：先以 `。`（2 單位）排版，下列任一成立視為放不下，改排原文原樣（`.` 或 `. `，即改動前的結果）並計 `EclTextStats.FullStopDropped`：

- (a) 排版失敗（`fits` 為假）；
- (b) 排版成功但結束列不等於起點列（`。` 被換到下一列的列首：排版函式對單獨一個 2 單位字剩 1 單位時是換列而不是失敗，而全形句讀不放行首，規格 027 §3.4）。

兩次排版從同一個起點（列、欄）算，重試不改變頁狀態（比照規格 046 §3.4 的 `attempt`）。改排後的結果就是改動前的結果，包含它自己換列或溢出：本規格不降低也不增加本呼叫的溢出。起點欄已是列首（規格 027 §3.4 的左欄換列）時 `。` 隨該規則落在列首，視為放得下，並在驗收偵測列首 `。` 的次數（§3.6 第 5 點 (d)）。

裸 `.` 原本佔 1 單位、`。` 佔 2 單位，所以其後的續接呼叫起點右移 1 單位（`. ` 前進 2 單位，不變），後續呼叫可能因此多換一列或溢出；「不使頁失效」只保證本呼叫，後續溢出以 §3.6 第 5 點 (c) 的溢出數與 (g) 的頁尾餘列對照驗收。

`p == nil`（前面是未翻譯、原版英文的文字）：不處理，句點與英文一起由原版畫。其他呼叫（原文不只一個 `.`、`...`、`!`、`?`、含字母的）不處理：證據只支持單獨的 `.`。前一個畫出的字元已是終止標點時再來單獨 `.`，不特別處理（結果為 `。。`，改動前為 `。.`；資料沒有這種情形）。

### 3.3 引擎範本欄位（延伸規格 046 §3.3，僅限 zh-TW、zh-CN）

欄位值（來源 `_`，經 `monsterSlot` 轉換並去頭尾空白後）符合 `^[0-9]+\.$`（數字加單一句點）時：

- zh-TW、zh-CN：去掉句點，不論欄位在範本的哪個位置。「被去掉句點的欄位」以範本字串內實際出現 `{i}` 的欄位為準（與規格 046 的逐 placeholder 掃描一致）；範本未引用的欄位（四個語言的 `tpl.logbook` 都不引用 `{0}`）即使是數字加句點也不去掉、不觸發補 `。`，實作在 `ReplaceAll` 前以 `strings.Contains(t, "{i}")` 判斷。全部欄位填完且至少一個欄位被去掉句點時，結果不以 `。！？」』…` 結尾就補 `。`；沒有欄位被去掉時不補。終止標點集不含半形 `.!?`：現有五個範本中只有 `tpl.logbook` 以欄位收尾，該欄是數字；`monsterSlot` 的輸出可能以半形 `!`、`?`、`,` 結尾，若日後有範本以怪物名欄位收尾，終止標點集需重新檢視。
- ja、ko：不變（規格 046 §3.3）。現有 ja 範本沒有任何欄位在末尾（`tpl.logbook` 是 `、日誌{1}番に記録した`），沒有資料支持撤掉 ja 的「後面還有字元」條件，所以不擴大；ja 的範本只有 ECL 單獨句點（§3.2）受本規格影響。

實作：zh-TW、zh-CN 不改道 `fillTemplateKoJa`，沿用現行逐欄 `ReplaceAll`，只在取欄位值處去句點並記錄，迴圈後做終止標點檢查；沒有數字句點欄位的字串走與改動前逐位元相同的程式，差集由構造保證。ja、ko、zz 與其餘語言碼走改動前的程式。
重複引用同一欄位的範本：載入規則不變（ko、ja 拒載，zh-TW、zh-CN 不拒載，每次出現各自處理，結果相同）。

先例：`monsterSlot` 已在 zh-TW、zh-CN、ja 把怪物名後的 `.` 換成 `。`、ko 保留 `.`（規格 029 §2.1、046 §3.7）；本規格把同一慣例延伸到 zh 的範本欄位與三個語言的 ECL 單獨呼叫。
引擎 dispatcher（`0763:0424`）也走同一個 `Translate`，所以同樣受影響；資料（§2.1）沒有數字加句點的 dispatcher 字串。

非範本的引擎串接（`translateLine` 的一般串接）不處理：證據（§2.1、§2.2）沒有這種字串。

### 3.4 譯文配合（zh-TW 與由它產生的 zh-CN）

三條譯文以 `第` 收尾，加上 §3.2 之後會讀成「第5。」，語意殘缺。改成不需要後綴的寫法，數字直接接在 `甲板` 後面：

| key | 現值 | 新值 |
|---|---|---|
| `ecl.2.32.03956` | `艙壁上的模板數字顯示，你們身處第` | `艙壁上的模板數字顯示，你們身處甲板` |
| `ecl.2.32.09000` | `你們身處第` | `你們身處甲板` |
| `ecl.2.33.08985` | `你們踏上新出現的平台，位於第` | `你們踏上新出現的平台，位於甲板` |

數字與 `甲板` 之間沒有空白（數字是 passthrough 呼叫，句首補空白的機制只有 ko 有，規格 046 §3.4），與同批 C 型範本的 `編號 38。`（範本內寫了空白）不同，已知取捨，見 §5。`ecl.4.66.08710`、`ecl.4.66.08952` 不改，見 §5。
依規格 027 §3.1，主句譯文要列出後接碎片再改：三條的後接見 §2.5（03956 觀察 72 次，09000 與 08985 各觀察 1 次，後接皆為數字與 `.`）。`甲板` 結尾對「後接不是數字」的呼叫不通，`第` 結尾同樣不通，所以不退步。
新舊譯文都只是把原文的「甲板」詞放回片段內，沒有把意思搬到別的片段，符合 `workplace/ecl-l10n/INSTRUCTIONS.md`。
zh-CN 由生成器重產（規格 041），並更新 `text/zh-CN-term-review.tsv` 的審閱帳本列（`ecl.2.32.03956` 綁現行 zh-TW 譯文的雜湊，改字後 `zh_cn_convert.py --check` 會失敗；另兩條若觸發新的詞組套用，以 `--check` 為準補列）。`第` 改 `甲板` 兩岸相同；ja、ko 不改。
`甲`、`板`、`。` 已在三個語言的字集內，字型本身不重建；但 `workplace/current-font/*.json` 的 manifest 記錄 `ecl-text.zh-TW.tsv` 的整份雜湊，要重記（規格 043 的註記：先重建到新目錄與現行字型比位元組，相同時只換 manifest）。
`workplace/ecl-l10n/done/batch-*.tsv` 的批次檔仍含舊值，合併工具對「已存在正式檔的譯文」保留正式檔，除非批次檔有新值；重跑合併前要同步改批次檔，避免三條譯文被蓋回。
`。` 不來自任何譯文列（runtime 合成），字型子集由譯文產生；三個語言的字集必須含 `U+3002`，列為字集檢查項（缺字會讓整層跳過，規格 046 §3.7 同型）。

### 3.5 不做

- 不處理 ko；不處理英文模式。
- 不處理其他標點的獨立呼叫（`!`、`?`、`,`、`...`），沒有證據。
- 不處理一般串接（非範本）的數字句點。
- 不把 `。` 寫進 catalog 或事件檔：原版這個句點不是 ECL 字串（呼叫端是 `0B4A` 的 runtime 印字），事件檔以雜湊為鍵，加一個 `.` 的鍵會讓它在每個視窗命中、包含前面是原版英文的情形。
