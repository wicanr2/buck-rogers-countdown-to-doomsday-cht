## 1. 為什麼要做

規格 056 的縮小字模由 16×16 底字型以面積規則縮成正方形。ja 的 L2 全形字模在 2× 是 8×8、在 3× 是 11×11，濁點與半濁點在這個大小消失，不同的假名衍生成同一個字模：

| 倍率 | L2 全形字模 | 字模相同的組（名字字元集內） |
|---|---|---|
| 2× | 8×8（現行） | `ィ`／`ォ`、`ブ`／`プ`、`ボ`／`ポ`（3 組） |
| 3× | 11×11（現行） | `カ`／`ガ`、`ケ`／`ゲ`、`サ`／`ザ`、`ホ`／`ボ`（4 組） |

日文玩家名是片假名音譯（規格 044），濁音、半濁音與清音是不同的音。使用者要求 ja 的 L2 字模把這些字分開。本規格保證的是「字模互異」，不等於實機可讀（§4、§6）。

## 2. 證據

已證實（讀程式，dosgolem `bba48d9`；量測在 Docker 內重跑，腳本 `workplace/phase323/runexp.sh`，輸出、方法與審查者獨立重算見 `docs/re/phase-323-shrink-distinct-evidence.md`）：

- 字元集：`text/translit-chars.ja.tsv` 的允許字集與 `text/name-glossary.ja.tsv` 的譯名用字（規格 056 §5.1 靜態檢查所用字元集），其中全形且來源字模有墨者 88 個（片假名、小假名、`ー`、`・`；無平假名與漢字）；來源字模位元組相同的字 0 組。
- 面積規則（門檻 1/2）在不同目標尺寸下，這 88 字衍生後字模相同的組數，以及 31 個清濁對（`カガ` 到 `ボポ`，含 `ハバ`／`ハパ`／`バパ` 三向與 `ウヴ`）中差異像素最少的對：

| 目標尺寸（寬×高） | 相同組數 | 清濁對最小差異像素數（點名） |
|---|---|---|
| 2× L1 12×12、3× L1 16×16（現行 L1） | 0、0 | 1（`シジ`、`ハバ`，2× L1）、未量（3×） |
| 2× L2 8×8（現行） | 3 | 0（`ブプ`、`ボポ` 相同） |
| 3× L2 11×11（現行） | 4 | 0（`カガ`、`ケゲ`、`サザ`、`ホボ` 相同） |
| 8×12 | 0 | 1（`ブプ`、`ボポ`） |
| 8×13 | 0 | 1（`ベペ`） |
| **8×14** | 0 | **2**（`ビピ`、`ブプ`、`ベペ`、`ボポ`） |
| 8×16 | 0 | 2 |
| 10×10 | 0 | 未量 |
| 10×12 | 1（`ヘ`／`ベ`） | 未量 |
| 11×14 | 0 | 2 |
| **3× 11×16** | 0 | **2**（`ブプ`、`ボポ`） |

- 清濁對的差異像素都落在字模框上半部右半（濁點所在處）：8×14 與 11×16 的 31 對全部成立；現行 8×8 有 `ブプ`、`ボポ` 相同，現行 11×11 有 4 對相同，且 `セゼ`、`ウヴ` 的差異不在上半部右半。
- 對照圖（`workplace/phase323/out/sheet-ja.png`，強推論）：高度加大後 `ガギグゲゴ` 的濁點為獨立像素，與 `カキクケコ` 可分；8 像素寬的片假名整體仍粗糙（`セ` 近似 `ヒ`、`テ` 近似 `ヲ`），本規格不處理（§6）。
- 半形的影響：全形字模變高後，半形英文（2× 4×8、3× 6×12）與全形的高度比由 1:1 變成約 4:7（2×）與 3:4（3×）；本規格有意不動半形（§4）。
- 現行程式：`shrinkMetrics` 只有一個 `FullGlyph`（正方形）；等級表 `shrinkLevels` 全語言共用，讀取點為 `placeText`、`layoutPlayerName`、`layoutEclTextLevel`、`eclRowTextShrink`、`Sync`；`NewEclTextOverlay(font, scale)` 不帶語言；`EclTextPage` 不帶語言；衍生字型的快取鍵只含底字型、等級編號與倍率；靜態檢查（`TestShrinkFontAvailability`）對字模相同只 `t.Logf` 報告。

未知（本規格不量）：縮小字在實機的可讀性；日文玩家名的實際字元分布。

## 3. 契約

### 3.1 範圍

- 只改 ja 通道（`LangJa`）的 L2：2× 與 3× 的全形字模高度與位置。ja 的 L1、半形字模、`W_s`、版面、試排順序、計數都不變。zh-TW、zh-CN、ko 的輸出不變（ko 見規格 058）。
- 不改譯文、`text/`、字型檔、名字表、音譯規則（規格 044）。

### 3.2 通用機制（規格 058 沿用）

1. **語言載體與表的來源。** 等級表依語言覆寫：`shrinkLevelsFor(lang)` 回傳該語言的等級表，沒有覆寫的語言（含 `""`、zh-TW、zh-CN、測試語言）回傳規格 056 的 `shrinkLevels`。語言的唯一來源是 `EclTextCatalog` 的語言（`""` 視同 zh-TW，與既有的 `fullStop()`、`zhDeckSpace()`、`ko()` 相同）：
   - watcher 以其目錄的語言取表；`LayoutProfile` 不載語言。
   - `EclTextPage` 新增欄位 `Lang`，由 watcher 建頁時填入（等於它的目錄語言）；`eclRowTextShrink`、`eclRowText`、`Sync` 以 `shrinkLevelsFor(p.Lang)` 取表，`NewEclTextOverlay(font, scale)` 的簽名不變。watcher 與 overlay 因此在構造上讀到同一張表，換語言（F4）不重建任何表。
   - 純函式 `layoutEclTextLevel`、`layoutPlayerName`、`shrinkUnitUnits` 把表（或單一等級規格）當參數接收，不讀全域；`placeText` 與 `ObserveEntry` 傳入 watcher 的表。上述函式的全部呼叫點（含測試、凍結副本的對照呼叫、`ecl_shrink_invariant_test.go`）同步改簽名。
   - 規格要求觀察點：watcher 與 overlay 各有一個取表的小函式（命名由實作定，例如 `levels()`），測試用它斷言，並另以實際 `Sync` 產生的 stamp 驗證（§5.1）。
2. **等級規格與表。** `shrinkSpec` 含：`Level`（編號，1 或 2）、`FullLP`、`HalfLP`、各倍率的 `shrinkMetrics`（§3.2 第 3 點）、`Thr`（§3.2 第 4 點），全為整數欄位（可比較）。`Shrink` 欄位與 `NameShrunk`、`PlayerShrunk` 的索引仍是等級編號。每張表必須含 L1 與 L2。
3. **幾何關係式**（取代 056 §3.2 的方形與半形高規則；R = 8 × 倍率 k，c0 = L0 的全形內縮，k = 2 為 0、k = 3 為 1）：
   - 全形格寬 `FullCell` = `FullLP` × k；半形格寬 `HalfW` = `HalfLP` × k。
   - 全形字模寬 `FullGlyphW`、高 `FullGlyphH`，0 < `FullGlyphW` ≤ `FullCell`，0 < `FullGlyphH` ≤ R − c0。內縮 `FullInset` = ⌊(`FullCell` − `FullGlyphW`) / 2⌋。
   - 全形 `GlyphY` = R − `FullGlyphH` − c0；全形字模框下緣與 L0、L1 相同（k = 2 為列內第 15 列、k = 3 為 22）。
   - 半形字模高 `HalfH` 與 `HalfGlyphY` = R − `HalfH` 取表值，0 < `HalfH` ≤ R；半形字模框下緣為列底（k = 2 為 15、k = 3 為 23）。
   - 預設表（056）符合這些關係式並且另有 `FullGlyphH` = `FullGlyphW`、`HalfH` = `FullCell`；語言表不要求後兩條。
4. **衍生門檻 `Thr`。** `Thr = n/d`：目標像素有墨面積 × d ≥ n × 面積才點亮。只作用於全形字模的衍生；半形字模永遠用 1/2。零值（`d` = 0）視為 1/2，正規化只在一處（取得等級規格的函式）；合法值為 0 < n ≤ d。056 §3.3 的保底規則（整個字全空且來源有墨時點亮有墨面積最大的像素）照舊適用。預設與本規格的 ja 等級都用 1/2。
5. **衍生字型的快取鍵與名稱**含完整的等級規格（尺寸、門檻、`FullLP`、`HalfLP`），字型名稱含尺寸與門檻，供診斷輸出辨識。
6. **測試輔助。** `withShrinkLevels(t, ...)`（空表關閉縮小）替換預設表並同時清空所有語言覆寫，替換後全語言讀這張表；新增 `withLangShrinkLevels(t, lang, ...)`，只替換單一語言（`t.Cleanup` 還原），讓測試能讓 ja 或 ko 暫時用 056 的舊表。
7. **以 zh-TW 目錄加 ko 或 ja 排版設定的既有測試夾具**（`eclPlayerWatcher` 加 `SetLayout(layoutKo)`、`koPlayerCall` 等）會讀預設表。這些測試一律改以對應語言的目錄建構（`eclFixtureLang(t, LangKo, ...)`），保留的 zh-TW 目錄案例標明為控制組；清單由實作者在 diff 中列出，§5.9 驗收。

### 3.3 ja 的等級表

L1 與規格 056 相同。L2 如下（`FullLP` 4、`HalfLP` 2、`W_s` 公式不變）：

| 倍率 | 格寬 | 全形字模 寬×高 | 內縮 | 全形 `GlyphY` | `Thr` | 半形字模 | 半形 `GlyphY` |
|---|---|---|---|---|---|---|---|
| 2× | 8 | 8×14（056：8×8） | 0 | 2（056：8） | 1/2 | 4×8（不變） | 8（不變） |
| 3× | 12 | 11×16（056：11×11） | 0 | 7（056：12） | 1/2 | 6×12（不變） | 12（不變） |

- 單元寬度 `W_s` = ⌈(4F + 2H) / 4⌉，與 056 相同（F 為全形字數，H 為半形字數）。
- 選 2× 8×14 而不是 8×12，是因為 8×12 有 `ブ`／`プ`、`ボ`／`ポ` 只差 1 個像素（一個像素分辨半濁音與濁音），8×14 的清濁對最少差 2 個像素，與 3× 11×16 一致；兩者在證據表中都是 0 組相同。

### 3.4 不變量

1. ja 通道在新舊等級表下，所有呼叫的 `EclTextLine`（`Row`、`Col`、`Text`、`Shrink`）、`endRow`、`endCol` 與各計數逐位元組相同；差異只在繪製：ja L2 全形 stamp 的 `GlyphY` 與衍生字型。
2. zh-TW、zh-CN、ko 通道的版面與繪製與規格 056（`bba48d9`）相同：其衍生字型（全形與半形，所有等級與倍率）的逐字模位元組與 `bba48d9` 相同；版面對 `bba48d9` 逐位元組相同（以 056 已有的凍結副本摘要與 `text/` 語料差異驗證）。ko 在規格 058 實作前不變。
3. ja 的 L1 與半形欄、其他通道的等級表不被改動，載入順序與 F4 切換不影響任何通道的表（無共用可變狀態）。

### 3.5 靜態可用性檢查的新硬性條件

規格 056 §5.1 的靜態檢查（`TestShrinkFontAvailability`，已接入 `tools/package.sh` 的 `smoke_shrink`，必須在同一個測試函式內）加：

1. 「全形字模兩兩不同」的比較抽成可呼叫的函式（輸入：字型、字元集、等級表、倍率；輸出：字模相同的組清單）。對每個通道的字型（zh-TW 另含本機倚天）、倍率（2×、3×）、該語言表的每個等級，名字字元集中全形（`isHalfwidth` 為假且非空白）且來源字模有墨的字，衍生後兩兩不同。來源字模位元組相同的兩個字不要求，清單列出。
2. 失敗時測試失敗、打包失敗，訊息列出相同組的字，不只計數；不自動移除等級。允許的處置只有：(a) 不動 `FullLP`、`HalfLP`，只調整該語言表的字模高度或 `Thr`（版面不變，只需重跑 §5 的字模驗收）；(b) 調整 `FullLP`、`HalfLP`（版面改變，修訂本規格並重審）；(c) 移除該等級（修訂規格並重審）。禁止為了通過檢查改譯文、縮減 `translit-chars` 允許字集或改名字表（AGENTS.md：字型子集由正式譯文重建，不得為遷就缺字而改譯）。
3. 衍生後全空的字（056 §3.3 保底後只剩來源缺字）：該等級從使用該表的語言移除，取代 056 的「對全語言一起移除」。
4. 防空過：每個語言的表必須含 L1 與 L2（斷言）；字元集的全形字數有下限（ja ≥ 88、ko ≥ 2,128、zh-TW 與 zh-CN 各 ≥ 336）；表為空或字元集載入失敗時測試失敗而不是通過。
5. 負向對照（證明比較函式有效）：用規格 056 的 ja L2 表跑同一函式，必須回報 2× 3 組、3× 4 組；用合成字型造一對必相同的字，必須回報。
6. 半形字元的相同組維持只報告（phase-322 §4.2 的 `H`／`M`、`1`／`l` 等）。
7. 輸出各語言各等級的「全形字模相同組數」與清濁對最小差異像素數，驗收時相同組數全為 0。zh-TW（Unifont、倚天）與 zh-CN 的全形相同組已量為 0（phase-322 §4.2 的清單全為半形），驗收時重記。

## 4. 不做什麼

- ja 的 L1、半形字模、`W_s`、試排順序；其他語言。
- 半形英文字母的相同組（`H`／`M`、`0`／`O`、`1`／`l`、`[`／`|`）：所有語言共有，另案。全形變高後半形與全形的高度比改變，是有意保留；2× 的半形 4×12 在證據中為 0 組相同，可在另案評估。
- 實機可讀性：本規格只保證字模互異與清濁對的差異像素數，不宣稱讀者看得出。
- 灰階或抗鋸齒；手札；視窗整窗退英文。

## 5. 驗收

環境變數閘門的測試以 `-v` 確認 PASS，SKIP 不算；收據（輸出、字型 SHA-256、`text/` 與 dosgolem commit）記入 phase 文件。完成後規格標為「限縮 CONFORMED：機制（表、衍生、版面不變量、繪製）」；實機可讀性與後期名字路徑維持未知，AGENTS.md「只有同狀態收據覆蓋的路徑才稱已中文化」不變（先例：規格 055、056）。

1. 表與機制單元測試：
   - ja 的 L2 數值逐格比對（§3.3）；`TestShrinkLevelTable` 的幾何關係檢查改寫為 §3.2 第 3 點的關係式，對 `{預設表, ja 表, ko 表}` 各跑一次；ja 的 L1 與半形欄、zh 預設表逐格等於 056。
   - 取表一致：以 `LangJa` 目錄建構 watcher，斷言 watcher 取表為 ja 表、其建的頁面 `Lang` 為 `ja`；實際 `Sync` 並比對 stamp 的 `CellW`、`CellH`、`GlyphX`、`GlyphY`、字型尺寸，證明 overlay 用的是 ja 表（不只讀取觀察點）；zh-TW 目錄的 watcher 與頁面讀到 056 的表。
   - 同一個 `LiveRuntime` 載入 zh-TW、zh-CN、ja、ko 之後，輪流以各通道排版與繪製，結果與單獨載入相同（無載入順序或 F4 污染）。
   - `shrinkLevelsFor`、`withShrinkLevels`、`withLangShrinkLevels` 的語意；表缺等級時 `Sync` 的處理（現行單元靜默消失）有測試並符合規格 056 §3.6 的描述。
