# 057 — 日文縮小字模的獨立字形（濁音、半濁音與清音可分）

狀態：**DRAFT**（2026-10-03，待獨立審查）
日期：2026-10-03
Issue：無（#38 已關閉；本規格接續規格 056 的使用者回饋）
決定：使用者 2026-10-03 看過規格 056 的收據後要求：「ja L2 濁音有獨立字體，カ 和 ガ 要能區分」「依照語言開對應規格」。本規格處理日文；韓文見規格 058。
前置：規格 056（名字單元縮小，限縮 CONFORMED）、039（半形）、040／042（多語通道與日文排版）、044（日文玩家名音譯）。
取代：056 §3.2 的 ja 欄（只取代 ja 通道 L2 的全形字模；L1、半形、其他語言不動）。056 的對應處加註指向本規格。

## 1. 為什麼要做

規格 056 的縮小字模由 16×16 底字型以面積規則縮成正方形。ja 的 L2 全形字模在 2× 是 8×8、在 3× 是 11×11，濁點與半濁點在這個大小消失，不同的假名衍生成同一個字模：

| 倍率 | L2 全形字模 | 字模相同的組（名字字元集內） |
|---|---|---|
| 2× | 8×8 | `ィ`／`ォ`、`ブ`／`プ`、`ボ`／`ポ`（3 組） |
| 3× | 11×11 | `カ`／`ガ`、`ケ`／`ゲ`、`サ`／`ザ`、`ホ`／`ボ`（4 組） |

日文玩家名是片假名音譯（規格 044），濁音與清音是不同的音。使用者要求 ja 的 L2 字模把這些字分開。

## 2. 證據

已證實（讀程式，dosgolem `bba48d9`；量測在 Docker 內重跑，腳本 `workplace/phase323/runexp.sh`，輸出與方法見 `docs/re/phase-323-shrink-distinct-evidence.md`）：

- 字元集：`text/translit-chars.ja.tsv` 的允許字集與 `text/name-glossary.ja.tsv` 的譯名用字，其中全形且來源字模有墨者 88 個（規格 056 §5.1 的靜態檢查所用字元集，去掉半形）。
- 面積規則（056 §3.3：目標像素有墨面積 × 2 ≥ 面積時點亮）在不同目標尺寸下，這 88 字衍生後字模相同的組數：

| 目標尺寸（寬×高） | 組數 | 說明 |
|---|---|---|
| 2× L1 12×12、3× L1 16×16 | 0 | 現行 L1 |
| 2× L2 8×8（現行） | 3 | `ィォ`、`ブプ`、`ボポ` |
| 3× L2 11×11（現行） | 4 | `カガ`、`ケゲ`、`サザ`、`ホボ` |
| 2× 8×12 | 0 | 寬度不變、高度取 L1 的 12 |
| 3× 11×16 | 0 | 寬度不變、高度取 L1 的 16 |
| 2× 8×10 | 1 | |
| 2× 10×10、3× 11×14 | 0 | |

- 對照圖（`workplace/phase323/out/sheet-ja.png`）：8×12 時 `ガギグゲゴ` 的濁點為獨立的像素，與 `カキクケコ` 可分；8×8 時濁點縮成與筆畫相連或消失。8 像素寬的片假名整體仍粗糙（例如 `セ` 近似 `ヒ`），本規格不處理（§6）。
- 現行程式：`shrinkMetrics` 只有一個 `FullGlyph`（正方形）；等級表 `shrinkLevels` 是全語言共用；`NewEclTextWatcher`、`NewEclTextOverlay` 不帶語言；靜態檢查（`TestShrinkFontAvailability`）只檢查衍生後不全空，字模相同只列報告。

未知（本規格不量）：縮小字在實機的可讀性；日文玩家名的實際字元分布。

## 3. 契約

### 3.1 範圍

- 只改 ja 通道（`LangJa`）的 L2：2× 與 3× 的全形字模高度與位置。ja 的 L1、半形字模、`W_s`、版面、試排順序、計數都不變。zh-TW、zh-CN、ko 通道的輸出不變（ko 見規格 058）。
- 不改譯文、`text/`、字型檔、名字表、音譯規則（規格 044）。

### 3.2 通用機制（規格 058 沿用）

1. 等級表可依語言覆寫。`shrinkLevelsFor(lang)` 回傳該語言的等級表；沒有覆寫的語言（含 `""`、zh-TW、zh-CN、測試語言）回傳規格 056 的 `shrinkLevels`。`Shrink` 欄位與 `NameShrunk`、`PlayerShrunk` 的索引仍是等級編號（L1 為 1、L2 為 2），不是表內位置。
2. 同一通道的一切讀取點用同一張表：watcher 的試排（`placeText`、`layoutPlayerName`、`layoutEclTextLevel`）、單元寬度 `W_s`、`eclRowTextShrink` 的 slot 寬度、`Sync` 的缺字與 stamp、衍生字型。watcher 依其目錄的語言取表；overlay 依建構它的通道語言取表；兩者的語言在通道載入時一次決定，之後不變。換語言（F4）不重建表。
3. 全形字模是矩形：寬 `FullGlyphW`、高 `FullGlyphH`（規格 056 的 `FullGlyph` 即 `FullGlyphW`，056 的等級 `FullGlyphH` = `FullGlyphW`）。內縮 = ⌊(格寬 − `FullGlyphW`) / 2⌋；底對齊：全形 `GlyphY` = R − `FullGlyphH` − L0 全形內縮（2× 為 0、3× 為 1），R = 8 × 倍率。半形的規則不變。
4. 等級規格可帶衍生門檻 `Thr = n/d`（預設 1/2）：目標像素的有墨面積 × d ≥ n × 面積才點亮；規格 056 §3.3 的保底規則（整個字全空且來源有墨時點亮有墨面積最大的像素）照舊適用。預設值下輸出與規格 056 相同。本規格的 ja 等級用預設。
5. 衍生字型的快取鍵含完整的等級規格（尺寸與門檻），不能只用等級編號與倍率。
6. 取代 056 §3.2 中「`shrinkLevels` 全語言共用」一句：預設表全語言共用，語言覆寫另列。測試替換等級表的 helper（056 §5.8）要同時清空語言覆寫（空表關閉所有語言的縮小）。

### 3.3 ja 的等級表

L1 與規格 056 相同。L2 如下（`FullLP` 4、`HalfLP` 2、`W_s` 公式不變）：

| 倍率 | 格寬 | 全形字模 寬×高 | 內縮 | 全形 `GlyphY` | 半形字模 | 半形 `GlyphY` |
|---|---|---|---|---|---|---|
| 2× | 8 | 8×12（056：8×8） | 0 | 4（056：8） | 4×8（不變） | 8（不變） |
| 3× | 12 | 11×16（056：11×11） | 0 | 7（056：12） | 6×12（不變） | 12（不變） |

- 全形字模的下緣與 L1、L0 相同（2× 為列內第 15 列、3× 為 22）；字模框頂端 2× 在第 4 列、3× 在第 7 列。
- 全形字模仍由 16×16 底字型以面積規則（`Thr` 1/2）衍生；半形字模仍由 8×16 半形字型衍生（056 §3.3）。

### 3.4 不變量

1. ja 通道在新舊等級表下，所有呼叫的 `EclTextLine`（`Row`、`Col`、`Text`、`Shrink`）、`endRow`、`endCol` 與各計數逐位元組相同；差異只在繪製：ja L2 全形 stamp 的 `GlyphY` 與衍生字型。
2. zh-TW、zh-CN、ko 通道的版面與繪製與規格 056（`bba48d9`）相同（ko 在規格 058 實作前不變）。
3. 通道載入前後，其他通道的等級表不被改動（無共用可變狀態被 ja 覆寫汙染）。

### 3.5 靜態可用性檢查的新硬性條件

規格 056 §5.1 的靜態檢查（`TestShrinkFontAvailability`，已接入 `tools/package.sh`）加一條，對所有語言（不只 ja）適用：

- 對每個通道的字型（zh-TW 另含本機倚天）、倍率（2×、3×）、該語言等級表的每個等級，名字字元集中**全形**且來源字模有墨的字，衍生後的字模兩兩不同。例外：來源字模位元組相同的兩個字不要求（任何縮小都無法分開），清單列出。
- 不通過時測試失敗、打包失敗；不自動移除等級（移除會改變版面，由人決定）。
- 半形字元的相同組維持只列報告（規格 056 §4.2 的 `H`／`M`、`1`／`l` 等）。
- 檢查另外輸出各語言各等級的「全形字模相同組數」，驗收時應全為 0。

## 4. 不做什麼

- ja 的 L1、半形字模、`W_s`、試排順序；其他語言。
- 半形英文字母的相同組（`H`／`M`、`0`／`O`、`1`／`l`、`[`／`|`）：所有語言共有，另案。
- 片假名在 8 像素寬的整體可讀性（`セ` 近似 `ヒ`）：見 §6 第 1 點。
- 灰階或抗鋸齒；手札；視窗整窗退英文。

## 5. 驗收

環境變數閘門的測試以 `-v` 確認 PASS，SKIP 不算；收據（輸出、字型 SHA-256、`text/` 與 dosgolem commit）記入 phase 文件。

1. 等級表與機制單元測試：ja 的 L2 數值逐格比對（§3.3）；其他語言的表等於 056（逐格）；`shrinkLevelsFor` 的覆寫與預設；watcher 與 overlay 取同一張表（建構 ja 的 watcher 與兩個 presenter 的 overlay，斷言三者讀到的 L2 相同；zh-TW 讀到 056 的 L2）；快取鍵含規格（同一底字型、同等級編號、不同規格得到不同字型）。
2. 衍生已知答案：小尺寸的矩形目標（例如 4×4 對 3×2 逐點驗算，`Thr` 1/2）；`Thr` 非預設的案例（1/3 與 1/2 的差異像素）；保底規則在矩形目標上的案例。
3. 濁音可分：ja 字型（正式 `buckrogers-ja.golemfnt`）上，名字字元集的全形字在 2×／3× 的 L1、L2 兩兩不同；並另列清濁三組的明確斷言：`カ`行與`ガ`行、`サ`行與`ザ`行、`タ`行與`ダ`行、`ハ`行、`バ`行、`パ`行、`ウ`與`ヴ`，每一對的衍生字模不同，且差異像素至少有一個落在字模框的上半部右半（濁點與半濁點所在處）。
4. 版面不變量（§3.4 第 1 條）：`text/` ja 語料與合成語料（沿用規格 056 §5.3 第一層的語料與抽樣）以新舊 ja 等級表各跑一次 `placeText`、`layoutPlayerName`，逐位元組相同（含 `Shrink`）。
5. trace A/B：A 為 `bba48d9`，B 為實作 commit，沿用 `workplace/phase322/ab056.sh`，逐位元組相同。
6. 重播閘門與全套件：`TestReplayPhase257Windows`、`TestReplayPhase257EngineDispatch` 為 PASS；全套件 0 FAIL；與基準 `bba48d9` 的 SKIP 差異只有新增的環境變數閘門測試。
7. 合成截圖：沿用 `TestShrinkSyntheticShots`，ja 的 2×、3× L2 各一張；ja 玩家名改用含濁音的名字（至少一個含 `ガ`／`ギ`／`ブ` 一類濁音或半濁音的片假名名字，由音譯規則產生，由測試斷言字串含濁音字），斷言頁面等級為 2。
8. 突變：在乾淨匯出上實際套用並記錄 FAIL。至少涵蓋：ja L2 高度改回等於寬（8×8、11×11）；`GlyphY` 用舊值；表覆寫失效（ja 用預設表）；overlay 不取語言表（ja 的 overlay 用預設表）；watcher 不取語言表；門檻改 `>`；快取鍵不含規格；靜態檢查不比較全形字模；靜態檢查把全形字模相同當作只報告。
9. 既有測試：凡斷言 056 的 ja L2 數值者改為新數值，並保留 zh-TW 的原斷言（控制組）。
10. 實作 commit 的 diff 不含 `text/`、`font/`；`tools/package.sh` 的產物清單不變。

## 6. 開放項目

1. 片假名在 8 像素寬仍粗糙（`セ`／`ヒ` 類似）。若使用者要更清楚，可把 ja 的 L2 全形格寬改成 5 邏輯像素（10 像素，與規格 058 的 ko 相同），代價是 ja 的 L2 比現行寬約 1 個半格（`W_s` 公式的係數 4 改 5）。本規格維持格寬 8。
2. 半形英文字母的相同組（所有語言）：另案。
3. 規格 058 與本規格共用 §3.2 的機制；實作順序為先本規格再 058，兩份各自驗收。
