## 1. 為什麼要做

規格 056 的 ko L2 全形字模在 2× 是 8×8、在 3× 是 11×11，不同音節衍生成同一個字模。名字字元集（`text/translit-chars.ko.tsv` 與 `text/name-glossary.ko.tsv` 的譯名用字，全形且來源字模有墨者 2,128 個）內：

| 倍率 | L2 全形字模 | 字模相同的組數 | 對數 |
|---|---|---|---|
| 2× | 8×8（現行） | 312 | 1,229 |
| 3× | 11×11（現行） | 142 | 147 |

使用者提到的 315 組是 phase-322 靜態檢查的合計：312 組諺文音節，加上半形英文相同組 3 組（`0`／`O`、`1`／`l`、`[`／`|`）。本規格處理 312 組；半形的 3 組維持（另案，§4）。

相同的多是發音不同的音節，例如 2×：`게`／`계`、`네`／`녜`、`겍`／`곅`；3×：`갠`／`갱`（終聲 ㄴ／ㅇ）、`독`／`톡`（初聲 ㄷ／ㅌ）。諺文讀音用來告訴玩家名字怎麼唸，縮小後讀音變了就是顯示錯誤。本規格保證「字模互異」並為易混的音素家族設下最小差異像素數的下限；互異不等於實機可讀（§4、§6）。

## 2. 證據

已證實（讀程式，dosgolem `bba48d9`；量測在 Docker 內重跑，腳本 `workplace/phase323/runexp.sh`，輸出、方法與審查者獨立重算見 `docs/re/phase-323-shrink-distinct-evidence.md`）：

- 字元集：2,128 個全形字，皆為預組音節（無字母 Jamo）；來源字模位元組相同的字 0 組。整個正式 ko 字型的 2,423 個有墨音節，選定組合同樣是 0 組。
- 不同目標尺寸與門檻（目標像素有墨面積 ≥ n/d 才點亮）下字模相同的對數（名字字元集；完整格表見 phase-323 §4）：

| 目標（寬×高） | 門檻 1/2 | 門檻 2/5 | 門檻 1/3 |
|---|---|---|---|
| 2× 格寬 8：8×8（現行 L2） | 1,229 | 1,229 | 1,229 |
| 2× 8×12 | 180 | 180 | 103 |
| 2× 8×13、8×14、8×15、8×16 | 422、151、122、17 | 25、103、122、17 | 24、108、122、17 |
| 2× 7×12 | 數個門檻為 0，但字形破碎（見下） | | |
| 2× 格寬 10：10×10 | 52 | 89 | 145 |
| 2× 10×12 | 84 | 92 | **0** |
| 2× 10×14 | **0** | 37 | 38 |
| 2× 12×12（L1，現行） | 0 | 0 | 0 |
| 3× 11×11（現行 L2） | 147 | 0 | 0 |
| 3× 14×16 | 0 | 0 | 0 |
| 3× 15×16 | 0 | 0 | **0** |
| 3× 16×16（L1，現行） | 0 | 未量 | 未量 |

- 結論一：維持 4 邏輯像素的格寬（2× 的 8 像素）時，寬 8 的字模最少仍有 17 對相同（8×16 或數個門檻），沒有 0 對；0 對只出現在寬 7 的字模（7×12，門檻 3/7 至 1/3），審查者畫圖確認字形破碎（平均有墨像素 24.5，對 10×12 門檻 1/3 的 38.3）。所以要做到互異且可讀，格寬必須加到 5 邏輯像素（2× 為 10 像素）。
- 結論二：互異不夠，要保留 `ㅔ`／`ㅐ` 的雙豎筆。對照圖（`workplace/phase323/out/sheet-ko.png`，強推論）：8×8 的 `셀` 近似 `샐`；10×14 與 10×16 門檻 1/2 的 `셀` 少了一筆而像 `설`，字模雖互異，讀音讀錯；10×12 門檻 1/3 的 `셀레스트`、`플라비우스`、`마리온` 可讀，筆畫較粗，與 12×12（L1）接近。所以選降低門檻（多點亮），不選加高字模。
- 結論三：3× 在 15 像素格選 15×16 門檻 1/3。審查者量測（名字字元集 2,128 字）：

| 3× 候選 | 相同對 | 差 1 個像素的對數 | 差 2 | 終聲 `ㅁ`／`ㅇ` 最小差異 |
|---|---|---|---|---|
| 16×16 門檻 1/2（現行 L1） | 0 | 0 | 370 | 3 |
| 14×16 門檻 1/3 | 0 | 219 | 633 | 1 |
| 14×16 門檻 1/2 | 0 | 84 | 645 | 2 |
| **15×16 門檻 1/3** | 0 | **0** | 233 | 3 |
| 15×16 門檻 1/2 | 0 | 38 | 370 | 3 |

  14×16 門檻 1/3 的 219 對差 1 像素中有 182 對是終聲 `ㅁ`／`ㅇ`（`감`／`강`），與要解決的問題同類；15×16 沒有這個情形。名字字元集字模的最左欄皆無墨（2,128 字中 0 個），15 寬字模與相鄰字不會相黏。
- 2× 的距離：10×12 門檻 1/3 有 286 對差 1 個像素，現行 L1 12×12 有 280 對；兩者相當。來源 16×16 本身就有 370 對只差 2 個像素。

## 3. 契約

### 3.1 範圍

- 只改 ko 通道（`LangKo`）的 L2：邏輯像素格寬、2× 與 3× 的全形字模與衍生門檻。ko 的 L1、半形字模與 `HalfLP`、試排順序、計數不變。其他語言不變（ja 見規格 057）。
- 不改譯文、`text/`、字型檔、名字表、音譯規則（規格 045）、讀音續接（規格 054）。

### 3.2 機制

使用規格 057 §3.2 的通用機制（語言載體、等級規格與表、幾何關係式、`Thr`、快取鍵、測試輔助、夾具改建構）。本規格的實作以規格 057 的實作為前提；ko 的 L2 `Thr` 用於全形字模，半形字模維持 1/2。

### 3.3 ko 的等級表

L1 與規格 056 相同。L2 改為：`FullLP` 5（056：4）、`HalfLP` 2（不變）。單元佔用 `W_s` = ⌈(5F + 2H) / 4⌉（F 為全形字數、H 為半形字數；056 為 ⌈(4F + 2H) / 4⌉）。

| 倍率 | 全形格寬 | 全形字模 寬×高 | 內縮 | 全形 `GlyphY` | `Thr` | 半形字模 | 半形 `GlyphY` |
|---|---|---|---|---|---|---|---|
| 2× | 10（056：8） | 10×12（056：8×8） | 0 | 4（056：8） | 1/3 | 4×8（不變） | 8（不變） |
| 3× | 15（056：12） | 15×16（056：11×11） | 0 | 7（056：12） | 1/3 | 6×12（不變） | 12（不變） |

- 字模寬等於格寬（內縮 0），字模最左欄皆無墨（§2），不會與相鄰字相黏。
- 全形字模下緣與 L1、L0 相同（2× 為列內第 15 列、3× 為 22）。
- 邏輯格寬 5 在 2× 為 10 像素、3× 為 15 像素，兩個 presenter 共用同一個 `W_s`（版面與 presenter 無關，056 §3.3）。
- 影響：同一個單元的 ko L2 寬度比規格 056 的 L2 多約 F/4 個半格（4 個音節多 1 個半格）；新 L2 的 `W_s` 仍小於 L1（(6F + 3H) − (5F + 2H) = F + H ≥ 4）。原本只在 056 L2 放得下的呼叫，可能在新 L2 放不下而繼續降段；放得下的呼叫只會少不會多（新 `W_s` 不小於 056 的 L2；審查者在 24 萬筆隨機排版中未見相反情形，但單調性不是證明，由 §3.4 第 3 條與 §5.4 驗證）。

### 3.4 不變量

對每個呼叫，用「同一份程式、ko 通道換回 056 的 L2 表」（`withLangShrinkLevels`）得到舊輸出，與新輸出比較，依舊版採用的版面分類：

1. 舊版採用 L0 或 L1，或舊版整個降段或溢出（包含 L2 也放不下）：新輸出（`EclTextLine`、`endRow`、`endCol`、各計數）逐位元組相同。
2. 舊版採用 L2：
   - 2a. 新版仍採 L2：單元的 `Text` 與 `Shrink` 相同；`Col`、`endCol` 與後面各行的 `Col` 隨 `W_s` 變寬而不同，以獨立算式（5F + 2H，進位）重算並逐一比對；
   - 2b. 新版改採後續版本（只加第一次、不加、只中文、英文，或帶空白版本失敗後的不帶空白版本，記 `SpaceDropped`）：逐一落點列筆數；
   - 2c. 其他：必須為 0。
3. 新版採用 L2 而舊版未採用：必須為 0（單調性）。2c 或第 3 條非 0 時，停止實作並修訂規格。
4. zh-TW、zh-CN、ja 通道的版面與繪製與規格 056（`bba48d9`）相同；ko 的 L1、半形衍生字型的逐字模位元組與 `bba48d9` 相同。
5. ko 通道的 watcher 與頁面的 `Lang`、overlay 取同一張 ko 表（規格 057 §3.2 第 1 點）。

### 3.5 靜態檢查

使用規格 057 §3.5 的硬性條件與處置（含防空過與負向對照）：ko 字型、2×／3×、L1／L2，名字字元集全形字衍生後兩兩不同（2,128 字）。本規格驗收時全為 0 組。

## 4. 不做什麼

- ko 的 L1、半形、`HalfLP`、試排順序；其他語言。
- 半形英文字母的相同組（所有語言共有，另案）：使用者提到的 315 組中的 3 組。全形字模變高後半形與全形的高度比改變（2× 8:12、3× 12:16），是有意保留。
- 音譯規則、讀音續接、助詞解析。
- 實機可讀性；灰階或抗鋸齒；手札；視窗整窗退英文。
- 換掉 Unifont 字型來源（規格 050）。

## 5. 驗收

環境變數閘門的測試以 `-v` 確認 PASS，SKIP 不算；收據（輸出、字型 SHA-256、`text/` 與 dosgolem commit）記入 phase 文件。完成後規格標為「限縮 CONFORMED：機制（表、衍生、版面不變量、繪製）」；實機可讀性與後期名字路徑維持未知，AGENTS.md「只有同狀態收據覆蓋的路徑才稱已中文化」不變。

1. 表與機制單元測試：ko 的 L2 數值逐格比對（§3.3）；`W_s` 公式（F、H 的組合與進位，`FullLP` 5、`HalfLP` 2）；ko 的 L1、半形欄與 zh 預設表逐格等於 056；`TestShrinkLevelTable` 的幾何關係檢查對 ko 表跑；取表一致（以 `LangKo` 目錄建構 watcher，頁面 `Lang` 為 `ko`，實際 `Sync` 的 stamp 比對）；ja、zh-TW 通道不受 ko 表影響。
2. 音節互異（正式 `buckrogers-ko.golemfnt`）：名字字元集 2,128 字，2×／3×、L1／L2 兩兩不同（規格 057 §3.5 的比較函式，ko 的 L2 為 0 組）；負向對照：用 056 的 ko L2 表回報 2× 312 組、3× 142 組。
3. 易混家族下限（凍結值，取 §2 的表）：2× L2 的各家族最小差異像素數 ≥ 1、2、2、17、2、8、3、3（依表的順序），3× L2 ≥ 2、3、3、34、3、13、5、4；並明列規格 §1 的代表組（`게`／`계`、`네`／`녜`、`겍`／`곅`、`갠`／`갱`、`독`／`톡`）在 L2 字模不同。另有已知答案的點陣快照：`셀` 在 2× 10×12 門檻 1/3（`ㅔ` 的兩根豎筆保留，與 `설` 不同）。
