# 058 — 韓文縮小字模的音節可辨（L2 不得有不同音節同形）

狀態：**DRAFT**（2026-10-03，待獨立審查）
日期：2026-10-03
Issue：無（#38 已關閉；本規格接續規格 056 的使用者回饋）
決定：使用者 2026-10-03 看過規格 056 的收據後要求：ko 在 2× L2 有 315 組音節字模相同，不同意，需要完善韓文（諺文）的顯示；並要求依語言開對應規格。本規格處理韓文；日文見規格 057。
前置：規格 057（通用機制 §3.2：語言覆寫的等級表、矩形字模、衍生門檻、靜態檢查的硬性條件）、056、043（韓文排版）、045（韓文玩家名）、054（讀音續接）。
取代：056 §3.2 的 ko 欄（只取代 ko 通道 L2；L1、半形、其他語言不動）。056 的對應處加註指向本規格。
解讀：使用者的「發音」指玩家名與譯名的諺文讀音在縮小後仍可讀（音節彼此可分）。音譯規則（規格 045）與讀音續接（規格 054）不改。若使用者指的是音譯規則本身，需另案。

## 1. 為什麼要做

規格 056 的 ko L2 全形字模在 2× 是 8×8、在 3× 是 11×11，不同音節衍生成同一個字模。名字字元集（`text/translit-chars.ko.tsv` 與 `text/name-glossary.ko.tsv` 的譯名用字，全形且來源字模有墨者 2,128 個）內：

| 倍率 | L2 全形字模 | 字模相同的組數 | 對數 |
|---|---|---|---|
| 2× | 8×8（現行） | 312 | 1,229 |
| 3× | 11×11（現行） | 142 | 147 |

相同的多是發音不同的音節，例如 2×：`게`／`계`、`네`／`녜`、`겍`／`곅`；3×：`갠`／`갱`（終聲 ㄴ／ㅇ）、`독`／`톡`（初聲 ㄷ／ㅌ）。諺文讀音用來告訴玩家名字怎麼唸，縮小後讀音變了就是顯示錯誤。

## 2. 證據

已證實（讀程式，dosgolem `bba48d9`；量測在 Docker 內重跑，腳本 `workplace/phase323/runexp.sh`，輸出與方法見 `docs/re/phase-323-shrink-distinct-evidence.md`）：

- 字元集：2,128 個全形字（來源字模位元組相同的字 0 組，所以任何縮小原則上都可能分開）。
- 不同目標尺寸與門檻（目標像素有墨面積 ≥ n/d 才點亮）下字模相同的對數：

| 目標（寬×高） | 門檻 1/2 | 門檻 2/5 | 門檻 1/3 |
|---|---|---|---|
| 2× 8×8（現行） | 1,229 | 1,229 | 1,229 |
| 2× 8×12 | 180 | 180 | 103 |
| 2× 10×12 | 84 | 92 | **0** |
| 2× 10×14 | 0 | 37 | 38 |
| 2× 12×12（L1，現行） | 0 | 0 | 0 |
| 3× 11×11（現行） | 147 | 0 | 0 |
| 3× 14×16 | **0** | 0 | **0** |
| 3× 16×16（L1，現行） | 0 | 未量 | 未量 |

  （2× 10×14 在門檻 1/2 為 0 對，但見下一條。未量的格表示該組合沒有被選用的理由，不影響結論。）
- 字模之間的距離（兩字模不同像素數，名字字元集的所有對）：來源 16×16 有 370 對只差 2 個像素；現行 L1 2× 12×12 有 280 對差 1 個像素；本規格的 2× 10×12 門檻 1/3 有 286 對差 1 個像素、3× 14×16 門檻 1/3 有 219 對；現行 L2 2× 8×8 有 1,229 對差 0 個像素（相同）。2× 的新 L2 與現行 L1 相當（286 對對 280 對）；3× 的現行 L1 沒有差 1 像素的對（16×16 保留來源的細節），新 L2 有 219 對，仍然互異。
- 對照圖（`workplace/phase323/out/sheet-ko.png`，同一組譯名在 2× 的五個候選）：8×8 的雙豎筆（`ㅔ`、`ㅐ`）糊成一筆，`셀` 近似 `샐`；8×12 較清楚但仍有相同組；10×14 門檻 1/2 的 `셀` 少了一筆而像 `설`，字模雖不同但讀音讀錯；10×12 門檻 1/3 的 `셀레스트`、`플라비우스`、`마리온` 都可讀，筆畫較粗；12×12（L1）最清楚。結論：字模互異還不夠，要保留 `ㅔ` 一類的雙筆，所以降低門檻（多點亮）比加高字模可靠。
- 3× 的 15 像素格（5 邏輯像素）、14×16 字模在門檻 1/2 與 1/3 都是 0 對。
- 現行程式的限制見規格 057 §2（等級表全語言共用、字模為正方形、衍生門檻固定）。

未知（本規格不量）：實機可讀性；ko 玩家名的實際字元分布。

## 3. 契約

### 3.1 範圍

- 只改 ko 通道（`LangKo`）的 L2：邏輯像素格寬、2× 與 3× 的全形字模與衍生門檻。ko 的 L1、半形字模與 `HalfLP`、試排順序、計數不變。其他語言不變（ja 見規格 057）。
- 不改譯文、`text/`、字型檔、名字表、音譯規則（規格 045）、讀音續接（規格 054）。

### 3.2 機制

使用規格 057 §3.2 的通用機制（語言覆寫的等級表、矩形字模、衍生門檻 `Thr`、快取鍵、通道一致性）。本規格的實作以規格 057 的實作為前提。

### 3.3 ko 的等級表

L1 與規格 056 相同。L2 改為：`FullLP` 5（056：4）、`HalfLP` 2（不變）。單元佔用 `W_s` = ⌈(5F + 2H) / 4⌉（F 為全形字數、H 為半形字數；056 為 ⌈(4F + 2H) / 4⌉）。

| 倍率 | 全形格寬 | 全形字模 寬×高 | 內縮 | 全形 `GlyphY` | `Thr` | 半形字模 | 半形 `GlyphY` |
|---|---|---|---|---|---|---|---|
| 2× | 10（056：8） | 10×12（056：8×8） | 0 | 4（056：8） | 1/3 | 4×8（不變） | 8（不變） |
| 3× | 15（056：12） | 14×16（056：11×11） | 0 | 7（056：12） | 1/3 | 6×12（不變） | 12（不變） |

- 內縮 = ⌊(格寬 − 字模寬) / 2⌋；3× 的 15 格放 14 寬字模，右側空 1 像素。
- 全形字模下緣與 L1、L0 相同（2× 為列內第 15 列、3× 為 22）。
- 邏輯格寬 5 在 2× 為 10 像素、3× 為 15 像素，兩個 presenter 共用同一個 `W_s`（版面與 presenter 無關，056 §3.3）。
- 影響：同一個單元的 ko L2 寬度比規格 056 的 L2 多約 F/4 個半格（4 個音節多 1 個半格）。原本只在 056 L2 放得下的呼叫，可能在新 L2 放不下而繼續降段（只加第一次、不加、只中文、英文）；放得下的呼叫只會少不會多（新 L2 的 `W_s` 不小於 056 的 L2）。

### 3.4 不變量

1. ko 的呼叫中，L0 或 L1 就放得下的，輸出（`EclTextLine`、`endRow`、`endCol`、各計數）與規格 056 逐位元組相同。
2. 與規格 056 的 ko 輸出不同的呼叫，只能是：舊版採用 L2、新版因 `W_s` 變寬而放不下，改採後續的退路；新版 `Shrink` 為 2 的呼叫，其 `W_s` 以 5/2 邏輯像素公式計。比對時列清單與筆數。
3. zh-TW、zh-CN、ja 通道的輸出不變。
4. ko 通道的 watcher 與兩個 presenter 的 overlay 取同一張 ko 表（規格 057 §3.2 第 2 點）。

### 3.5 靜態檢查

使用規格 057 §3.5 的硬性條件：ko 字型、2×／3×、L1／L2，名字字元集全形字衍生後兩兩不同（2,128 字）。本規格驗收時全為 0 組。

## 4. 不做什麼

- ko 的 L1、半形、`HalfLP`、試排順序；其他語言。
- 半形英文字母的相同組（所有語言共有，另案）。
- 音譯規則、讀音續接、助詞解析。
- 灰階或抗鋸齒；手札；視窗整窗退英文。
- 換掉 Unifont 字型來源（規格 050）。

## 5. 驗收

環境變數閘門的測試以 `-v` 確認 PASS，SKIP 不算；收據（輸出、字型 SHA-256、`text/` 與 dosgolem commit）記入 phase 文件。

1. 等級表單元測試：ko 的 L2 數值逐格比對（§3.3）；`W_s` 公式（係數 5 與 2，含 F、H 的組合與進位）；ko 的 L1、半形與其他語言逐格等於規格 056；watcher 與 overlay 取同表。
2. 音節可分（正式 `buckrogers-ko.golemfnt`）：名字字元集 2,128 字，2×／3×、L1／L2 兩兩不同；並明列規格 §1 的代表組（`게`／`계`、`네`／`녜`、`겍`／`곅`、`갠`／`갱`、`독`／`톡`）在 L2 的字模不同。
3. 母音對：`셀`／`설`、`게`／`거`、`계`／`겨`、`개`／`가`、`내`／`나`、`헤`／`허`、`애`／`아`、`에`／`어`、`네`／`너`、`레`／`러`、`페`／`퍼`、`제`／`저` 每一對在 2×、3× 的 L2 字模不同，且差異像素至少有一個落在字模框的右半部（母音所在處）。
4. 版面不變量（§3.4）：`text/` ko 語料與合成語料（沿用規格 056 §5.3 第一層）以新舊 ko 等級表各跑一次，分類並列筆數：相同、舊版 L2 改為後續退路（預期）、其他（必須為 0）。
5. trace A/B：A 為 `bba48d9`（或規格 057 的實作 commit），B 為本規格的實作 commit，沿用 `workplace/phase322/ab056.sh`；重播中縮小為 0，逐位元組相同。
6. 重播閘門與全套件：兩個重播閘門 PASS；全套件 0 FAIL；SKIP 差異只有新增的環境變數閘門測試。
7. 合成截圖：沿用 `TestShrinkSyntheticShots`，ko 的 2×、3× L1 與 L2 共四張重拍，各列 SHA-256。
8. 突變：在乾淨匯出上實際套用並記錄 FAIL。至少涵蓋：ko L2 `FullLP` 改回 4；字模改回 8×8／11×11；`Thr` 改回 1/2；`Thr` 改成 1/4；`GlyphY` 用舊值；ko 通道不取語言表；快取鍵不含規格；靜態檢查不比較全形字模；`W_s` 公式的 F 係數用 4。
9. 既有測試：斷言 056 的 ko L2 數值或寬度者改為新值，保留 zh-TW 的原斷言。
10. 實作 commit 的 diff 不含 `text/`、`font/`；`tools/package.sh` 的產物清單不變。

## 6. 開放項目

1. 門檻 1/3 讓筆畫變粗（多點亮）。若使用者要更細，可在 3× 改門檻 1/2（14×16 同為 0 對），2× 沒有其他 0 對的組合。
2. ko 的 L2 比 056 寬約 F/4 個半格，會讓少數呼叫多降一段；若使用者要保持原寬，需接受 8 像素格寬下音節仍有相同組（180 對以上），與本規格的目標衝突。
3. 半形英文字母的相同組（所有語言）：另案。
