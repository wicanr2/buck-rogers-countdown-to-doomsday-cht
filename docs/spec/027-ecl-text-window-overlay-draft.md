# 027 — ECL 敘事窗通用覆繪（內容雜湊）

狀態：**READY**（2026-09-26 獨立審查兩輪後）
日期：2026-09-26
前置：[第二百五十四階段盤點](../re/phase-254-in-game-text-inventory.md)、
[第二百五十五階段印字程序](../re/phase-255-ecl-text-window-printer.md)、
規格 011–017、022（逐頁劇情家族，本規格取代其擴充方式，不改其已 CONFORMED 範圍）。
審查：2026-09-26 獨立審查，五項阻擋已於本版回應（見 §3.3–§3.5、§5）。

## 1. 為什麼要做

遊戲本體的敘事文字全部出自 ECL 劇本，不重複 2,531 則。逐頁一份規格、逐行釘
事件序列的做法無法擴到全遊戲（使用者 2026-09-26 定案改用內容雜湊）。

原版把整則 ECL 字串交給同一支印字程序 `0763:056C`，由它斷字、換行、翻頁、逐字
延遲輸出。這支程序的進入點拿得到整串原文與視窗矩形，是識別與覆繪的單一攔截點。

## 3. 契約

### 3.1 catalog

- `text/ecl-text-events.tsv`：`event_key`、`original_length`、`original_sha256`、
  `sources`（`ECLn:block:offset` 以 `;` 分隔，同文多處只列一筆 key）。
  不存原文。由 ignored 工作區的靜態抽取工具產生，重跑要逐位元相同。
- `text/ecl-text.zh-TW.tsv`：`key`、`translation`、`source`。沿用既有 TSV 驗證：
  唯一 key、NFC、無控制字元、雙向覆蓋（未翻譯的 key 允許缺席，見 3.5）。
- 識別鍵是 `(original_length, original_sha256)`。同一雜湊只能對應一個 key。

### 3.2 識別

- 只在 `CS:IP = 0763:056C` 讀取參數與字串。不限定呼叫端；呼叫端只記錄。
- 視窗矩形須滿足原版檢查（左欄、右欄、底列 ≤ 39，頂列 ≤ 24），另加本規格的
  `left ≤ right`、`top ≤ bottom ≤ 24`；不符就不動作，並清除該視窗既有呈現。
- 以字串的長度與 SHA-256 查 catalog。原文只在 watcher 內暫存到雜湊完成。
- 同時讀游標 `(DS:5F3E, DS:5F3F)`，依 §2 規則算出原版實際起點：
  旗標非零或游標在視窗外 → 左上角；否則沿用游標。

### 3.3 呼叫期間

- 一次命中的呼叫從 `0763:056C` 進入開始，到驗證過的返回為止：
  當前 `CS:IP` 等於進入時堆疊上的返回位址，`SS` 相同，`SP = 進入 SP + 4 + 12h`。
- 呼叫期間原版在視窗內的所有 A000 寫入（逐字 glyph、翻頁清窗）都是這次呼叫的
  輸出，不觸發失效。翻頁清窗與入口清窗走同一支 `0763:110F`、同一寫入位址
  `0CF4:1B3A`，本規格不以位址區分兩者，而以「是否在命中呼叫期間」區分：
  入口清窗發生在識別之後、屬於呼叫期間；呼叫期間外的清窗一律失效。
- 信任邊界：呼叫期間內與視窗相交的寫入全部視為本次輸出，包含理論上可能的中斷
  驅動寫入。這是刻意簡化；遇到反例時再收緊。
- 呼叫期間若出現另一次 `0763:056C` 進入（巢狀或重入），整個視窗失效。

### 3.4 呈現

- 命中時立即建立一筆呈現：整則譯文一次畫出，不隨英文逐字出現。
- 中文游標：
  - 新的一頁（旗標非零或原版游標在視窗外）→ 左上角；
  - 旗標 0 但視窗沒有有效呈現（前一則未命中而顯示英文）→ 原版游標位置，
    遮罩從該列開始，不遮上方英文（2026-09-26 A/B 發現後修訂，見 phase-256）；
  - 接續字串（旗標 0 且視窗有有效呈現）：原版進入游標在左欄 → 上一筆中文結尾的
    下一列左欄；否則接在上一筆中文結尾之後（此分支尚無執行期樣本，CONFORMED 前補）。
- 排版：每個字元一格（8×8 邏輯像素）。拉丁字母、數字連續成詞不拆行；
  全形句讀不放行首（放不下就連同前一字換行）。
- 遮罩區：視窗內「本頁第一筆呈現的起始列」（上一條的例外為原版游標列）到底列、左欄到右欄的整塊矩形，
  以視窗背景色填滿後畫字。原版在這塊區域的英文（含翻頁後的後續頁）都被遮住。
  遮罩不得超出視窗矩形（右界是右欄結束，不含邊框）。
- 譯文超出遮罩區可用列數：不畫、記一次 overflow、整個視窗失效，退回英文。
  這是刻意背離規格 011 的 fail-closed：通用家族允許分批翻譯與排版例外，
  原版英文比錯位的中文安全。
- 英文翻頁時中文不跟著翻頁：整則中文在第一頁就全部顯示，玩家在後續英文頁的
  按鍵等待期間看到同一份中文。中文密度約為英文兩倍以上，單頁可容納整則。

### 3.5 失效

一律「整個視窗的中文呈現一起清除」，退回原版畫面：

1. `0763:056C` 進入且旗標非零（新的一頁；命中時隨即建立新呈現）。
2. `0763:056C` 進入但 catalog 未命中、或譯文缺席。
3. 呼叫期間外，A000 寫入與遮罩區相交。
4. overflow、重入、參數不合法。
5. 執行不連續（restore、observer fault）。

### 3.6 分批

catalog 有、譯文缺的 key 視同未命中。允許譯文分批進版，未完成的顯示原版英文。

### 3.7 多視窗與未命中接續（修訂 2026-09-26，戰鬥右欄樣本）

- 戰鬥右欄同時有數個視窗（例如頂列 7–9 的武器行、頂列 11–21 的行動訊息），都經
  `0763:056C`。呈現以「視窗矩形」為單位各自維護：每個矩形一頁，§3.3–§3.5 的規則
  只作用在該矩形的頁上。
- 失效以「列」為單位（修訂 2026-09-26，戰鬥 A/B：行動訊息視窗頂列 11–21 印完
  「Attacks」後，原版以頂列 13–16 的新視窗印傷害訊息，並在第 17–21 列另有寫入；
  第 11 列的「Attacks」原版仍在畫面上）：
  - 新的一頁（旗標非零或游標在視窗外）建立時，其他頁中落在此矩形列範圍內、且欄範圍
    相交的列一律移除（原版即將清除並重畫那幾列）。
  - 呼叫期間外的 A000 寫入只移除它所在的那一列。
  - 列被移除後該列不再遮罩，原版像素照常顯示；即使寫入只涵蓋該列部分欄位也整列移除
    （寧可露出英文，不遮住原版新畫的內容）。
  - 一頁中所有含譯文的列都被移除時，整頁移除。
- 旗標 0 的接續字串在 catalog 與規格 029 都未命中時，不使該頁失效，改把原文照原樣
  （拉丁字母）接進排版，保持整頁連續；這讓「攻擊」之後的玩家名字不會把前面的中文清掉。
  旗標非零的未命中仍照 §3.5 使該頁失效、顯示原版英文。

## 4. 不做什麼

- 不處理 `0763:0424` dispatcher 的引擎字串、`37F1:03xx` 指令列、隊員名、座標列。
  它們另立規格。
- 不改原版斷字、翻頁、延遲、按鍵等待。
- 不把譯文寫進 DOS 記憶體或 VRAM。
- 規格 010–017、022 的逐頁家族涵蓋的字串，在本規格 CONFORMED 前不放進
  `ecl-text.zh-TW.tsv`，避免兩個家族畫同一則。本規格在開場路徑 CONFORMED 後，
  另案把那些字串移入本 catalog 並從 `LiveRuntime` 拆除逐頁家族。

## 5. 驗收

1. 單元測試（合成）：命中、未命中、清窗旗標、游標接續、overflow、四種失效。
2. 靜態：catalog 重建逐位元相同；譯文驗證通過；字型覆蓋全部譯文字元。
3. 原版同狀態：phase104 control state 起 280M–400M，runner 並行驅動，
   2×／3× 的非覆繪區像素與 baseline 相同，覆繪區只出現在已呈現列。
4. 正常玩家路徑：至少一次接續字串（旗標 0，phase-255 的 402.6M–407.5M 事件）、
   一次離開敘事畫面、一次存檔後讀檔回到同一位置，畫面不殘留中文。
5. 翻頁：找到一則需要翻頁的字串並量到執行期行為後補驗；未量到前，規格只宣稱
   翻頁由 §3.3 的呼叫期間規則處理，不宣稱已驗。
