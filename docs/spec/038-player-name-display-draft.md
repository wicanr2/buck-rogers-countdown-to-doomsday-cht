# 038 — 玩家角色名的判定與各畫面顯示

狀態：**DRAFT**（2026-09-29）
日期：2026-09-29
Issue：#33
前置：規格 037（音譯器）、036（NPC 譯名與加註）、027（ECL 敘事窗）、029（引擎訊息與名稱呼叫端）；
證據 `docs/re/phase-281-party-records.md`、phase-244／255／263／266／273／274。

## 1. 為什麼要做

使用者決定（2026-09-29）：玩家角色名在寬欄顯示「音譯中文(英文)」，窄欄只顯示中文。本規格定義「哪個字串是
玩家名」以及第 1 期接通的畫面；音譯本身見規格 037。

## 2. 證據

- 角色記錄 259 位元組：名字 +0x00（Pascal 字串，≤15 字元）、性別 +0x26（0 男、1 女），已證實（phase-281，含
  性別因果實驗）。
- 目前隊伍：從 `DS:4EC5` 的 far pointer 出發，沿記錄 +0xFF 走「隊員數」筆；隊員數在 `[DS:3BCC]+0x33E`。戰鬥中
  怪物串在同一條鏈的隊員之後，隊員數仍是 6（已證實）。記錄在 heap，位址隨路徑改變（已證實）。
- 名單變動（已證實，隊伍選單）：移除、移除排頭、加回、讀檔都會改鏈或隊員數。劇情入隊、死亡是否改動：未知。
- 名冊（全部已建角色）只在磁碟 `.WHO`，不常駐記憶體（強推論）。
- 輸出路徑、可用格數與現行覆繪行為見 phase-274 與規格 029 §2.1（現行：玩家名保持英文）。

## 3. 契約

### 3.1 隊伍名單快照

- 在每個 host frame 的第一個 `BeforeStep`，以及每次名稱相關 dispatcher／`056C` 進入時，讀 `DS`（hook 當下的
  資料段，不寫死）→ `DS:4EC5` → 沿鏈讀前 N 筆（N＝`[DS:3BCC]+0x33E`，上限 8；任何指標為 0000:0000 或超出
  記憶體即停止並以已讀部分為準），得到 (名字, 性別) 清單。
- 讀取只用無副作用的讀（`StepView.Read8／16`），不寫入。
- 名單內容改變時，所有以玩家名為依據的覆繪在下一次失效檢查時重算（與各家族既有失效規則相同）。
- 名冊畫面（ADD 清單、全寬名冊）的名字不在隊伍鏈上：本規格不處理（第 3 期另訂）。

### 3.2 玩家名的判定與優先序

- 一個字串被視為玩家名，當且僅當它與快照中某個名字完全相同（位元組相等，原版為大寫 ASCII）。
- 優先序（高到低）：
  1. 路徑本身已知是名字欄位（§3.3 的名稱呼叫端與敘事的單獨名字）且字串在快照中 → 玩家名。
  2. 字串在快照中，但出現在 ECL 或引擎的一般文字查表位置（例如玩家取名 `PORT`、`EXIT`，而原版印出的正是 ECL
     短片段）→ **不視為玩家名**，照現有 catalog 查表。理由：這些位置的字串來自原版文字資料，與玩家名同形只是巧合；
     只有名字欄位路徑能確定是玩家名。
  3. 玩家名與規格 036 的 NPC 譯名同形（例如取名 `BUCK`）：在名字欄位路徑用玩家名音譯；在一般文字中照 036。
- 性別取快照中該名字的性別；同名多人時取第一筆。

### 3.3 第 1 期顯示

| 路徑 | 顯示 | 規則 |
|---|---|---|
| ECL 敘事（`056C`）中玩家名以拉丁字接入的位置（027 §3.7 的句中名字） | 「中文(英文)」 | 以規格 036 §3.3 的加註機制處理：名字替換為「中文(英文)」單元，三段退路（完整 → 只中文 → 原英文），不可拆行 |
| ECL 單獨名字（`0B79` 旗標 1、名字本身即整筆輸出） | 「中文(英文)」 | 視為命中：以名字單元建立呈現，後句旗標 0 續印依 027 §3.4 接續規則；放不下時退只中文、再退英文 |
| 探索隊伍欄、戰鬥右欄的一般列（`235A`） | 只中文 | 畫在原名的格內（029 名稱呼叫端的原文格規則）；中文格數 ≤ 原名格數才畫，否則留英文 |

- 音譯失敗（037 `ok=false`）一律留英文。
- 所有顯示只在覆繪層；不改原版記憶體、存檔或比對。

### 3.4 第 2 期（證據補齊後修訂本規格才施工）

- 隊伍欄行動者（`21DE`）與挑選游標（`0388`）：與 `235A` 共用同一次「是否畫中文」的判斷結果（以名字為鍵快取），
  三種反白一致，避免游標移動時中英切換。前置：兩者的 unit 證據。
- 角色頁名字欄（20 格）：「中文(英文)」≤ 20 格畫完整，否則只中文。前置：名字列的清除與重繪證據。
- 延伸格（「中文(英文)」超出原名格數）只能用在已證實原版會先清成底色的區域（隊伍欄 `21B7` 清欄 17–38、戰鬥右欄
  `04D2`／`0AAC` 清列 1–21、欄 23–38），並同步擴大失效與讓位範圍；本期不做。

### 3.5 受影響的既有規格條文

- 029 §2.1「玩家自訂的角色名不在字典內，保持原樣」：第 1 期的 `235A` 一般列與敘事名字改為依本規格顯示；
  029 其餘條文不變。
- 027 §3.1 短片段「視同未命中」與 §3.4 起始欄：單獨名字改為命中後，phase-274 的 `CELESTE ATTACKS.` 類收據
  改變，屬預期；重做並寫新基準。
- 027 §3.7 句中名字以拉丁字接入：改為 036 的加註單元。

## 4. 不做什麼

- 命名畫面的逐字回顯（`0763:09AF`／`0943`）。
- 名冊、物品頁標題、治療表、`leads`／`Save` 句、戰鬥訊息嵌名句（第 3 期，各自補證據後另訂）。
- 以中文輸入名字；寫入存檔。

## 5. 驗收

1. 單元測試：名單快照（正常、指標為 0、隊員數大於鏈長、戰鬥中含怪物的鏈只取前 N 筆）；判定優先序三條；
   `235A` 格數判斷；敘事單元的三段退路。
2. 同狀態 A/B：phase254 七條回歸；phase-274 敘事樣本重做（新基準）；戰鬥右欄與探索隊伍欄各一次，差異只在名字格。
3. 名單變動：以 phase-281 的移除／加回狀態，確認快照更新後覆繪隨之改變。
4. 前端端到端：隊伍欄與戰鬥右欄顯示音譯中文；敘事中「中文(英文)」。
5. 取名與 ECL 短片段同形（例如 `PORT`）時，一般文字仍照 catalog（合成單元測試）。
