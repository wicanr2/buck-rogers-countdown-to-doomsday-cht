## 3. 契約

### 3.1 隊伍名單快照

- 只在名稱相關 dispatcher（`0763:0424`）與 `056C` 進入時取快照，不在任意指令邊界讀。以 hook 當下 `DS` 讀資料段
  的先例是 `056C`（讀 `DS:5F3E／5F3F`）與水平選單；`0424` 進入時 DS 為資料段見 phase-284 §3（5,241 筆皆 `0EC0`）。
  快照由 live runtime 以當次 `StepReader` 建好，作為參數傳給 `EclTextWatcher` 與 `EngineDispatchWatcher`
  （後者目前拿不到記憶體）。讀 `DS`（不寫死）→ `DS:4EC5` → 沿鏈讀前 N 筆
  （N＝`[DS:3BCC]+0x33E`；N 為 0 時為空名單，大於 6 時整份捨棄（phase-281 只見隊員 0–5）；任何指標為 0000:0000 或超出記憶體即整份捨棄），
  得到 (記錄 seg:off, 名字, 性別) 清單。
- 內容防呆：名字長度位元組必須為 1–15，且每個字元在 0x20–0x7E；任一筆不合格即捨棄**整份**快照，沿用上一份
  合格快照（開機後尚無合格快照時視為空名單）。理由：hook 當下的 `DS` 若不是資料段，讀到的是「非空、未越界但
  整批錯誤」的鏈，只查指標擋不住。
- 性別位元組 0 → Male、1 → Female，其他值 → Unknown（037 以中性用字音譯）。
- 讀取只用無副作用的讀（`StepView.Read8／16`），不寫入。
- 快照變更不回頭改已畫的覆繪；之後的新呼叫才用新快照。舊覆繪照各家族既有失效規則（原版重畫、寫入重疊）移除。
- 名冊畫面（ADD 清單、全寬名冊）的名字不在隊伍鏈上：本規格不處理（第 3 期另訂）。

### 3.2 玩家名的判定

判定依路徑使用不同的結構訊號（phase-284），不以「字串與快照同形」單獨成立。

- 戰鬥右欄（dispatcher `0763:0424`，呼叫端 `OVR:2BA60:235A`，起始欄 23）：字串指標（`args[1]:args[0]`）的
  seg:off 等於快照中前 N 筆之一的記錄位址，**且**當下字串與該筆快照名字位元組相等 → 該隊員的玩家名（記錄空間會
  重用，沿用舊快照時只比位址不夠）；不在前 N 筆（含排在隊員之後的怪物記錄）→ 照現行查怪物名表（`monsterSlot`）。已證實：1,507 筆全部直指鏈上記錄，隊員與怪物以 index 分開，同名怪物各指
  自己的記錄。因此玩家名與怪物名同形時不會互相誤判。
- ECL 敘事（`056C`）：只在呼叫端（`EclTextEntry.Return` 是原始位址，以 overlay 對照換成 CodeKey，比照 dispatcher）為 `OVR:00904:0B79`／`0B4A` 時判定；其他 `056C` 呼叫端
  （引擎訊息等）的運算元表是上一條 ECL 指令的舊值，一律照現行。字串指標一律是共用緩衝 `DS:6EDC`，不能用指標
  判定。`056C` 進入時以 hook 當下 `DS` 讀第 1 運算元型別 `[DS:6D9A]` 與位址 `[DS:6DDA]`（高）／`[DS:6E1A]`（低）：
  - 型別 `0x80`（位元組碼內嵌的字面文字）→ 一律不是玩家名，照 catalog。玩家取名與 ECL 短片段同形（例如 `PORT`）
    時由這條排除。機制已證實，同形樣本未見，屬強推論。
  - 型別 `0x81` 且位址在白名單、整串與快照中某個名字位元組相等 → 玩家名。白名單：
    - `7C00`：直取 `[DS:4EC1]` 指向的記錄 +0x00（已證實）；另要求 `[DS:4EC1]` 的 seg:off 在快照前 N 筆內
      （戰鬥中可能指到怪物記錄），否則照現行；性別取該記錄。
    - `7BA4`：通用字串變數，寫入點已證實；印出樣本 34 筆皆名字，但原始紀錄也見過非名字內容（前導空白的
      ` ONLY`）。保留在白名單是靠整串比對，接受「玩家名與該變數字詞同形」的殘餘風險（限本次涵蓋畫面，假說）；
      性別取第一筆同名記錄。
  - 其他 `0x81` 位址（例如裝過 `BELOW`、`GIRL`、`HIM` 的 `7B90`、`7BB8`；寫入者未追的 `7BCC`，樣本 1 筆為名字）即使內容相等也照現行。
    理由：這些變數也裝代名詞、字詞與「文字＋名字」合成句，玩家取名 `HIM` 時會誤判，也會破壞 027 的接句。
  - 其他型別 → 照現行。
- 判定為玩家名時，中文取法：名字與 036 譯名表某列 `english` 位元組相等 → 用該列 `chinese`（例如取名 `BUCK`
  得「巴克」，劇情 NPC 入隊後也維持 036 譯名）；否則用 037 音譯。
- 判定順序：玩家名命中時先於 027 catalog 與 029 的查找（取名 `PORT` 經白名單變數印出時，不被短片段搶走）。
- 性別：戰鬥右欄取指到的記錄；ECL 依上列白名單規則。同名不同性別時 `7BA4` 取第一筆，屬已知限制。
- 空字串永遠不是玩家名（創角期 `37F1:235A` 的空字串呈現維持原登記）。

### 3.3 第 1 期顯示

| 路徑 | 顯示 | 規則 |
|---|---|---|
| ECL 敘事（`056C`）中玩家名以拉丁字接入的位置（027 §3.7 的句中名字） | 「中文(英文)」 | 名字以獨立的 `056C` 呼叫（型別 `0x81` 變數）進入，整次呼叫內容就是名字，不做子字串搜尋。只沿用 036 §3.3 的排版：「中文(英文)」是不可拆單元，三段退路（完整 → 只中文 → 原英文）；前兩段另建單元呈現（不用 036 的 catalog 譯文變體函式），第三段走既有 passthrough |
| ECL 單獨名字（`0B79` 旗標 1、名字本身即整筆輸出） | 「中文(英文)」 | 依 §3.2 判定後視為命中：以名字單元建立呈現，後句旗標 0 續印依 027 §3.4 接續規則；放不下時退只中文、再退英文 |
| 戰鬥右欄（`OVR:2BA60:235A`，起始欄 23；列不限，紀錄已見 1／10／12／15／16） | 只中文 | 畫在原名的格內（029 名稱呼叫端的原文格規則）；字數（一字一格，`•` 也算一格；與 029 相同）≤ 原名字元數才畫，否則留英文。音譯用字與 `•` 必在字型子集（037 允許字集已進 catalog） |

- 起始欄來源：dispatcher `0763:0424` 的 `args[5]`（`SS:SP+14`）低位元組，`engine_dispatch.go` 現行即用它判斷欄位，已證實。
  phase257 紀錄中 `235A` 在欄 23 只出現在戰鬥右欄（強推論；太空戰鬥、交易、訓練畫面未巡查，未知）。
- 退路範圍：原版把名字切成獨立呼叫，一次 `ObserveEntry` 的內容要嘛整筆是名字、要嘛是一般文字，不會同時有
  036 的 NPC 加註與玩家名單元，因此兩種三段退路各自在自己的呼叫內進行，不需合併順序。`EclTextStats` 另加
  「玩家名降為只中文」「玩家名退回英文」兩個計數，與 036 的「加註降級」分開。
- 名字命中後，旗標 0 的後句若未命中（例如所有格 `'S …`），畫面會是「中文(英文)」接原版英文後句；屬已知限制，
  記在 phase-274 重做的收據。
- 經非白名單變數（例如 `7BCC`）印出的名字留英文，同一段敘事可能中英並存；屬已知限制，同樣記在收據。
- 欄位條件：同一個 CodeKey `OVR:2BA60:235A` 也用於探索隊伍欄（欄 17）、全寬隊伍表與 `Pick Character`（欄 1）、
  角色頁標題（欄 8）、物品頁標題（欄 1）。第 1 期只在呼叫當下的起始欄為 23 時視為玩家名；其他欄照現行（玩家名
  保持英文），但下一條例外。實作要在名稱呼叫端加入「起始欄」條件，不能只靠 CodeKey 註冊。
- 同一呼叫端在欄 1／8／17 現行對任何字串做怪物名查表，玩家取名等於怪物名時會畫成怪物中文（既有問題）。第 1 期
  一併修正：指標指到快照中的隊員記錄（且內容相等）時不做怪物名查表，保持英文。phase-284 §2 已證實欄 8／17 的指標直指記錄；
  欄 1 的 `235A` 未取樣，指標不在快照時照現行。
- 探索隊伍欄移到第 2 期：同一格會由 `235A`（一般）、`21DE`（行動者）、`0388`（游標）輪流重畫，只接 `235A`
  會讓行動者與游標列中英切換。

- 音譯失敗（037 `ok=false`）一律留英文。
- 所有顯示只在覆繪層；不改原版記憶體、存檔或比對。
