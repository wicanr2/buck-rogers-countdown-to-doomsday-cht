# 040 — 多語框架與 F4 語言切換

狀態：**DRAFT**（2026-09-30）
日期：2026-09-30
Issue：#35
前置：規格 039（半形英數字）、036／037／038（名字）、005／034（手冊）、030（手札）、027–029、010–017、022、
dosgolem 241（前端輸入）。後續：041 簡體、042 日文、043 韓文、044／045 日韓音譯器（各自另訂）。
證據：本機盤點（2026-09-30，唯讀）；原版 F4 用途量測 phase-294（進行中，READY 前必須完成）。

## 1. 為什麼要做

使用者決定（2026-09-29、09-30）：
- 前端 F4 循環切換 繁體 → 簡體 → 英文 → 日文 → 韓文 → 繁體；英文＝關閉覆繪、顯示原版。
- 簡體用 OpenCC 詞彙級轉換；日韓以英文原文為源、繁中為語境參考批次翻譯；日韓手冊題段落從繁中段落轉譯。
- 缺譯顯示原版英文；語言記住上次選擇、首次為繁體、`-lang` 參數可覆寫；一個發行包帶全部語言。
- 日韓模式的名字格式同中文「譯名(英文)」。

本規格只定義框架（第一期）：語言通道、檔名、字型、F4 與英文模式、設定檔、驗證失敗處理。
各語言的譯文內容與音譯器由後續規格處理；本期只有繁體與英文兩個可用選項。

## 2. 證據

- 覆繪是純觀察（已證實）：LiveRuntime 只讀原版記憶體，覆繪在輸出合成時疊加；英文模式直接輸出原版放大畫面即可。
- Catalog 檔名在 Go 與 Python 端都寫死 `.zh-TW.tsv`（已證實，盤點列出位置）；`post_join_menu` 把譯文 SHA-256 釘成常數。
- key 格式與語言無關（語意 key、原文雜湊前綴、ECL 位置、手札編號），events 檔帶原文長度，可作各語言的格數預算
  （已證實）；英文原文只在 ignored `workplace/`。
- 家族分兩類（已證實，讀程式）：
  - A 類（watcher 以原文雜湊與呼叫端辨識，presenter 帶譯文）：選單類、技能離開、加入後提示與選單、動作列、
    身體圖示、手冊、劇情逐頁。
  - B 類（watcher 產出依譯文排版的頁面與游標接續）：ECL 敘事窗、水平選單、引擎 dispatcher、手札。
- 字型（已證實）：Unifont 17.0.05 完整涵蓋平假名、片假名、諺文音節、GB2312、JIS X 0208；Unifont 主字型漢字取自
  文泉驛，另附 `unifont_jp`（日文字形）；倚天 Big5 缺諺文、缺 GB2312 漢字 2,380 個、JIS 漢字 1,039 個。
- 原版是否使用 F4：靜態掃描未見比對 3Eh（強推論不用）；動態量測見 phase-294。

## 3. 契約

### 3.1 語言代碼與檔案

- 語言代碼：`zh-TW`、`zh-CN`、`en`、`ja`、`ko`。`en` 沒有 catalog。
- 譯文檔：`text/<family>.<lang>.tsv`，key 集合與 `zh-TW` 同一套（可缺列，缺譯依 §3.5）。
- Go 與 Python 端所有寫死 `.zh-TW.tsv` 的載入、驗證、合併、字型工具改為接受語言參數；預設 `zh-TW`，
  既有 zh-TW 行為與收據不變。
- `post_join_menu` 的譯文 SHA 釘選改為每語言一個登記值（登記表在 `text/`），或改為載入時驗證格式而不釘雜湊；
  二擇一在實作時決定並寫回本節。
- 各語言專用的名字表欄位（036 譯名表的譯名、037 允許字集等）由後續語言規格定義；本期只保證載入介面可接受。

### 3.2 語言通道（lane）

- 一個觀測分派（現有 `BeforeStep` 與各 hook）服務所有已啟用語言；共用狀態（原版字形表搜尋、overlay 正規化、
  隊伍快照、劇情進度、手冊題進行中狀態）只有一份，不分語言。
- A 類家族：watcher 一份；presenter 由「每倍率一個」擴為「每語言 × 每倍率一個」，每次 Apply 對所有已啟用語言套用。
- B 類家族：每個已啟用語言各一個 watcher，由同一個 hook 事件餵入；各自的 generation、reset 與統計分開計。
- 合成（Compose）只使用目前語言的 presenter；切換語言不清空、不重建任何 watcher 或 presenter，切換後第一次合成前
  對新語言做一次同步追上 generation。
- 字型：每個語言一份 GOLEMFNT（與其半形衍生字型，規格 039）。`zh-TW` 本機完整版用倚天、發行版用 Unifont；
  `zh-CN`、`ko` 用 Unifont；`ja` 用 `unifont_jp`（授權確認前不進發行包）。

### 3.3 英文模式

- 合成輸出逐位元組等於原版 `ScaleIndexedRGBA`；截圖同。
- 手札面板在英文模式不顯示，`LogbookTurn` 回 false（PgUp／PgDn 照送原版）；規格 034 英文摘錄面板不畫。
- 說明頁與視窗標題在英文模式使用繁體中文（前端 UI，非原版畫面）。
- 英文模式下所有 watcher 照常觀測，切回其他語言時畫面即時正確。

### 3.4 F4 與設定

- F4 加入前端保留鍵（規格 241 §3.3 表格同步修改），每按一次切到下一個**已啟用**語言；自動模式腳本新增 `lang`
  動作（前端功能鍵須在自動模式實際觸發過一次才算驗收）。
- 已啟用語言：`en` 恆啟用；其他語言在其 catalog 全部通過載入驗證、且字型存在時啟用。本期只有 `zh-TW` 與 `en`。
- 設定檔：使用者資料目錄下 `settings.json`，只存 `{"lang": "<代碼>"}`；讀寫失敗不致命（讀失敗用繁體、寫失敗只記錯誤）。
  啟動優先序：`-lang` 參數 ＞ 設定檔 ＞ `zh-TW`。指定的語言未啟用時退為 `zh-TW` 並記錯誤。
- 說明頁列出 F4 與目前語言；`docs/release/讀我.txt` 同步。
- F4 改前端保留的前提：phase-294 量測顯示原版各畫面不使用 F4。若量到有用，本節改為另選鍵並回到審查。

### 3.5 缺譯與驗證失敗

- 缺譯（某語言的 catalog 缺某 key）：該字串顯示原版英文，與現行 zh-TW 查無譯文一致。
- 某語言載入驗證失敗（版面、字型缺字、格式）：該語言從 F4 循環移除，記錄語言、檔案、key 與原因；不影響其他語言，
  也不讓遊戲無法啟動。`zh-TW` 驗證失敗維持現行行為（啟動失敗），因為它是預設語言與既有收據的基準。

## 4. 不做什麼

- 簡體、日文、韓文的譯文、斷行規則、名字與音譯（041–045）。
- 語言影響遊戲狀態或存檔：語言只影響輸出畫面；存檔、比較、原版語意路徑不受影響。

## 5. 驗收

1. 單元測試：檔名參數化（`zh-TW` 預設不變）；lane 結構（A 類一個 watcher 多語 presenter、B 類每語言 watcher）；
   切換不重建；英文模式合成等於原版；`LogbookTurn` 英文模式回 false；設定檔讀寫失敗與優先序；
   某語言驗證失敗時移出循環；合成用的字型隨語言切換。
2. 回歸：只有 `zh-TW` 與 `en` 時，phase254 七條回歸與既有各家族收據（以規格 039 最新基準）逐位元組不變。
3. 切換正確性：固定腳本在 ECL 敘事窗、水平選單、手札面板開啟、手冊題進行中四個時點各按 F4 一輪（`zh-TW`→`en`→`zh-TW`），
   每個時點的畫面與「一開始就用該語言」的同格畫面逐位元組相同。
4. 原版不受影響：同腳本插入多次 F4 與不插入，`owner.Digest()` 相同（證明 F4 未送進原版、語言不改機器狀態）。
5. 效能：以一個測試用假語言（`zh-TW` 內容複製為第二語言）量 1 lane 與 2 lane 在固定腳本、`-clock 50` 下的每格 CPU，
   記錄增量並估 4 語言；啟動時間同量。
6. 前端：自動模式觸發一次 F4（`lang` 動作）並截圖確認切換與說明頁。
