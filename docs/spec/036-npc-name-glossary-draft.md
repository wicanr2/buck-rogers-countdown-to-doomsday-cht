## 1. 為什麼要做

使用者決定（2026-09-29）：具名人物在寬的文字區顯示「中文(英文)」，窄欄只顯示中文。現行譯文有 8 組
人名不一致，也有錯譯（開場第 6 頁把原文 `CARLTON TURABIAN` 寫成錯拼的英文；手札第 48 則把普通名詞
*the orphan* 譯成人名）。

## 3. 契約

### 3.1 譯名表 `text/name-glossary.tsv`

- 欄位：`english`（原版大小寫，ECL 為全大寫）、`english_mixed`（手札等混合大小寫來源的寫法，可空）、
  `chinese`（正式中文名）、`kind`（full／short，全名或單稱）、`person`（同一人物的識別碼）、
  `basis`（`printed:<頁或位置>` 中文印刷手冊、`xinhua` 新華社式音譯、`nickname` 意譯綽號）、`note`。
- 譯名基準（使用者定案）：中文印刷手冊有的沿用；沒有的用新華社式音譯。印刷手冊的依據要在本機以
  手冊 OCR／crosswalk 核對並記在 `basis`，核不到的一律不得標 `printed`。
- 間隔號統一為 `•`（U+2022）。
- 例外清單 `text/name-glossary-exclude.tsv`：含人名字樣但不是人名的中文片語（店名等），比對時整段跳過。
- lint（`tools/name_glossary.py lint`）：同一 `person` 的 `chinese` 在所有 `text/*.zh-TW.tsv` 只准出現表中的
  寫法；舊寫法（例如同一人的第二種譯法）一律報錯；新增字要在字型子集。

  Holzerhein 各種寫法）。Zane 依基準（印刷手冊無此名）用新華社式「贊恩」，ECL、怪物名（`monster-name`）與
  水平選單（`hmenu`，共用雜湊 key `a4da3f4fffd1`）一起改。
- 手札譯文裡既有的全形「（English）」人名註記移除，改由 §3.3 在執行期統一加註。
- 手冊段落（`manual.zh-TW.tsv`）只做中文收斂；既有的「（English）」註記保留原樣，不移除、不在執行期加註
  （版面固定且涉及查詢題）。

### 3.3 執行期加註（顯示層）

- 加註規則：在「寬家族」的譯文中，找到譯名表的 `chinese`（最長優先、跳過例外片語、已緊接 `(` 的不重複加），
  在其後插入 `(` + 英文 + `)`，英文用該家族的原版大小寫（ECL 用 `english`，手札用 `english_mixed`，空則用
  `english`）。每次出現都加。
- 加註片段（中文名＋`(`＋英文＋`)`）在換行時視為一個不可拆的單元；單元本身比一行寬時才在英文的空白處斷開。
- 寬家族與退路（三段）：每次出現都加 → 同一人物只加第一次 → 不加。
  - ECL 敘事窗（027）：`ObserveEntry` 以同一組游標起點與接續狀態（`fresh`、起始欄、視窗參數）依序嘗試三段排版，
    第一個放得下的採用；三段都超出才照 027 的 overflow 退回英文。`EclTextStats` 新增「加註降級」（依段計數）
    與既有「整窗退回」分開。
  - 手札面板（030）：在載入 catalog 時（`LoadLogbookCatalog` 多收譯名表）一次排出三段版本，取第一個 ≤ 3 頁者快取；
    執行期不再處理字串。靜態掃描結果（各則採用哪一段）寫入 phase 文件。
  - 手札標題列（「手札第 N 則：標題」，上限 38 格，現行程式超出時會直接截斷）獨立選段：取三段中第一個整列 ≤ 38 格者；
    連不加註都超過 38 格的標題在靜態驗證就失敗，不進正式檔；`LogbookOverlay` 加防呆，標題超寬時記錯誤、不截斷畫出。
  - ECL 的「只加第一次」以單次 `ObserveEntry` 的譯文為範圍，不跨呼叫累計；同一頁由多次接續組成時，
    各次呼叫各自判斷，屬已知行為。
  - 固定劇情逐頁（010／015）：頁內換行是預先斷好的，不在執行期加註；§3.2 直接把加註寫進該兩行的譯文並
    重新斷行，通過該頁行寬驗證才生效。
- 窄家族不加註：怪物名、引擎訊息與片段（029）、水平選單（028）、手冊段落、各 UI 畫面。
- 加註只影響顯示，不進任何比對、雜湊、存檔或原版語意路徑。

### 3.4 字型

- 新譯名用字（新華社式音譯新增的字）經正式 catalog 進字型子集；加註的英文走原版 ASCII 字模（規格 031）。

## 4. 不做什麼

- 玩家角色名（規格 037）。
- 手冊段落加註、怪物名與選單加註。
- 無名敵人種類。

## 5. 驗收

1. `tools/name_glossary.py lint` 對全部 catalog 通過；`apply --dry-run` 清單經人工抽審，無誤替換（特別是店名與
   含人名字樣的片語）；「因已緊接括號而不加註」的位置也列出核對。
2. 單元測試：加註的最長優先、例外跳過、已有括號不重複、大小寫依家族、加註單元不拆行、ECL 三段退路（含接續狀態
   不因重試改變）、手札本文三段退路與標題獨立選段；靜態掃描全部手札標題 ≤ 38 格。
3. 同狀態 A/B：phase254 七條回歸與既有 ECL、手札 A/B 重跑；差異只能出現在人名處（加註或收斂後的中文），
   逐一核對；開場第 6 頁與第 1 頁重做 A/B；含 Zane 的水平選單與怪物名遭遇畫面各一次同狀態 A/B。
   ECL 主句的人名收斂依規格 027 §3.1 接句規則，列出執行期記錄的後接碎片並確認都接得通。
   手冊段落收斂後，核對規格 005 的 39／39 收據是否涉及被改的段落，涉及者重跑。
4. 前端端到端：到含 Buck Rogers／Turabian 的敘事、手札至少各一則，截圖確認加註；戰鬥或選單中同名人物只顯示中文。
5. 字型重建後零缺字；一般版外洩掃描照常通過。
