# 037 — 玩家角色名的自動音譯與顯示

狀態：**DRAFT**（2026-09-29）
日期：2026-09-29
Issue：#33
前置：規格 036（譯名表與加註）、027（ECL 敘事窗）、029（引擎訊息與名稱呼叫端）、024／031（字型）。

## 1. 為什麼要做

使用者決定（2026-09-29）：玩家建立角色時照原版輸入英文名，遊戲內顯示時改成「中文(英文)」，中文部分
自動音譯（新華社英語姓名譯名風格）；窄欄只顯示中文。存檔與遊戲邏輯只認英文。

## 2. 證據與未知（本機盤點，報告不入庫）

- 名字上限 15 字元（已證實，phase-244）。
- 輸出路徑（已證實，規格與 phase 文件；可用格數以 8 像素格計）：
  - 名字單獨一次 dispatcher 呼叫：探索右側隊伍欄（列 4–9、欄 17，17 格；一般列 `235A`、行動者 `21DE`、
    挑選游標 `0388`）；戰鬥右欄（`235A`，欄 23，16 格）；角色頁（列 1、欄 8，20 格）；全寬隊伍表（欄 1，33 格）；
    物品頁標題、治療結果表、名冊（`37F1:15BD`／`175D`／`1856`）。現行覆繪一律保留英文。
  - 名字經 `0763:056C`（ECL 敘事）：單獨名字（`0B79` 旗標 1，後句旗標 0 續印）與句中名字（以拉丁字接入，027 §3.7）。
  - 名字嵌在 dispatcher 單串：`<名字> leads <怪物>.`、`Save <名字>?`、戰鬥的 tactics roll、`is hit FOR`、
    `gains experience`。
  - 命名時逐字回顯（`0763:09AF`／`0943`）：不動。
- 未知：角色記錄中名字欄位的位置（沒有證據）；`21DE`、`0388` 的 unit；物品頁 `Gear` 是否隨名字長度移動；
  存檔詢問後綴右側的寫入者；治療表的 unit。

## 3. 契約

### 3.1 音譯器（通用層 `xlate/translit`，資料在本 repo `text/`）

- 輸入：一個名字（ASCII，原版大小寫，≤ 15 字元，可含空白分隔多個字）。逐字音譯後以 `•` 連接。
- 查找順序（每個字）：
  1. 專案詞典 `text/translit-names.tsv`（英文字 → 繁中，人工審定；可參考 Wikidata 的 CC0 名字項目，逐筆審）；
  2. CMU 發音詞典（BSD 式授權，隨發行包附全文與授權）取音素，依 §3.2 對到譯音表；
  3. 拼寫規則後備：字母組合 → 近似音素 → 譯音表。
- 譯音表 `text/translit-table.tsv`：由中文維基「外語譯音表／英語」人名表轉錄並轉繁體，CC BY-SA 4.0，
  獨立檔，附出處、修改說明與授權全文（`text/LICENSE-translit-table.md`）；不照搬新華社手冊或 GB/T 表。
- 輸出用字只能來自譯音表與專案詞典；兩者的全部用字經一份正式 catalog（`text/translit-chars.zh-TW.tsv`，由工具產生）
  進字型子集。音譯結果若含字型沒有的字即視為失敗，退回英文。
- 決定性：同一輸入永遠同一輸出；結果快取在執行期，不寫檔、不進存檔。
- 台灣慣用譯名優先：專案詞典可覆寫音譯結果（例如 Nicole → 妮可）。

### 3.2 音素到譯音表

- CMUdict 的 ARPAbet（去重音標記、保留主重音位置）對到譯音表的音素欄與元音列；對照表 `text/translit-arpabet.tsv`
  （專案自製）。音節切分：以元音為核，前接輔音歸該音節；詞尾單獨輔音用表中「單獨輔音」列。
- 譯音表附註中要看拼寫的規則（例如非重音節元音按拼寫譯）以明文規則實作並逐條列在規格附錄（實作時補），
  每條配單元測試。

### 3.3 認出「這是玩家名」

- 前置 RE（本規格內完成，另記 phase 文件）：找出隊員角色記錄與名字欄位，得出當下 6 名隊員的英文名。
  以隊員名單做比對：只有與名單中某名字完全相同的字串才視為玩家名。
- 與 NPC 撞名（例如玩家取名 `BUCK`）：玩家名優先；同一字串若在規格 036 譯名表中，也用玩家名音譯
  （玩家自己的角色），並在 phase 文件記錄。

### 3.4 各路徑的顯示（分期）

| 期 | 路徑 | 顯示 | 前置 |
|---|---|---|---|
| 1 | ECL 敘事（056C）句中與單獨名字 | 「中文(英文)」；排不下退只中文；再排不下照 027 退英文 | §3.3；單獨名字改為命中需重做 phase-274 的 A/B |
| 1 | 探索隊伍欄、戰鬥右欄的一般列（`235A`） | 只中文；中文格數 ≤ 原名格數才畫，否則留英文 | §3.3 |
| 2 | 隊伍欄行動者（`21DE`）、挑選游標（`0388`） | 只中文，三種反白一起接，避免游標移動時中英切換 | 補兩者的 unit 證據 |
| 2 | 角色頁名字欄（20 格） | 「中文(英文)」≤ 20 格畫完整；否則只中文 | 名字列的清除與重繪證據 |
| 3 | 全寬隊伍表、物品頁標題、治療表、名冊、`leads`／`Save`／戰鬥訊息句 | 逐條另訂 | 各自的原版證據（見 §2 未知） |

- 窄欄的「只中文」畫在原名的格內（與規格 029 名稱呼叫端相同的原文格規則），不外溢。
- 所有顯示只在覆繪層，不改原版記憶體、存檔或比對。

## 4. 不做什麼

- 命名畫面的輸入回顯；存檔內容；以中文輸入名字。
- 第 3 期以外的路徑在各自證據齊全前不接。

## 5. 驗收

1. 音譯器單元測試：專案詞典命中、CMUdict 路徑、拼寫後備；多字名；決定性；字型外用字退回英文；
   固定一組測試名（含隊伍現有 6 名：ROARKE、CELESTE、FLAVIUS、JANELLE、PIERRE、NICOLE STEELE）的期望輸出。
2. 譯音表轉錄核對：每格與維基頁面版本（記錄 revision id）一致；授權檔齊全。
3. 第 1 期：同狀態 A/B（phase254 回歸＋phase-274 敘事樣本）差異只在名字處；前端端到端截圖：敘事中的
   「中文(英文)」與隊伍欄、戰鬥右欄的只中文。
4. 字型重建零缺字；一般版外洩掃描通過；發行包附 CMUdict 與譯音表授權。
