# 034 — 手冊查詢題的英文關鍵字列

狀態：**DRAFT**（2026-09-27，第二版）
日期：2026-09-27
前置：規格 002、005、024（手冊段落覆繪與 presenter）；phase-12（題庫結構）、phase-112（英文快照）、
phase-270（讀檔後的手冊問答路徑）、phase-276（答案比較語意）。

## 1. 為什麼要做

原版手冊查詢題要玩家輸入英文手冊某段的第 N 個字（N = 1–10）。目前畫面保留英文題幹（規格 002 的
使用者決定），下方覆繪中文手冊段落；中文段落沒有英文單字，沒有英文手冊或中文版 Data Card 的玩家
無法作答。

使用者決定（2026-09-27）：在中文段落下方另列該段英文原文的前 N 個字，標出第 N 個字。

與 AGENTS.md 的關係：
- 顯示的是手冊原文，等同玩家自己翻手冊；只在原版要求查手冊的畫面出現。
- 答案仍由玩家輸入、原版比較，不預填、不送鍵、不改判定，也不跳題。
- 不擴張成內建攻略：不在其他畫面、不在題幹以外的情境顯示。

## 2. 證據

- 英文原文：使用者本機的英文手冊快照 `workplace/buckrogers-original-manual-english.html`，SHA-256
  `e8528a31b66d76e7162abe358bff1f27d7d5a5d4070914beee470867e5`…（全文見 phase-112），是 OCR 文字，
  有錯字；至少一題的第 N 個字受 OCR 錯誤影響（已證實）。
- 以標題行定位：39 題中 27 題恰有一行完全相符，11 題沒有完全相符的行，1 題連包含關係都找不到
  （2026-09-27 量測，只記數量）。所以定位要用人工確認的錨點，不能只靠啟發式。
- 比較語意（phase-276，強推論）：玩家輸入與「答案轉大寫」整串逐字元相等；輸入程序不轉大寫，
  小寫輸入會判錯；答案最長 8 字元。
- 手冊段落版面：文字區 x 16、y 72，36 欄 × 14 列，每列 8 邏輯像素；`manualRows` 每個字元（中英皆同）
  佔 1 欄，逐字切列。

## 3. 契約

### 3.1 答案資料的邊界（修訂 phase-12「禁止匯出」的做法）

phase-12 原本只驗證答案欄長度、不解碼。本規格改為**可在本機離線解碼作核對**，規則如下；其餘沿用
「禁止匯出」：
- 答案、摘錄單字、錨點對應的單字，不得出現在規格、`docs/re`、commit、Issue、收據 JSON、除錯輸出、
  例外訊息與測試 fixture。測試只用合成紀錄。
- 核對工具在 Docker（`--network none`、輸入唯讀）內執行；資料段來源為 phase-12 的 `0EC0:0000`
  64 KiB 傾印（SHA-256 `28a0563b…`，見 phase-12），工具啟動時核對雜湊。
- 解碼結果只留在行程記憶體，不寫暫存檔、不進 log；失敗只輸出 `event_key`，不輸出預期值、候選字或差異。
- `workplace/manual-english/`（ignored）內的摘錄檔等同答案表，同樣不得外流；驗收的 PNG、RGBA、
  輸入排程只放 ignored `workplace/`，phase 文件只記雜湊與數量。

### 3.2 摘錄資料（只在本機）

- 錨點檔 `workplace/manual-english/anchors.tsv`（ignored，人工維護）：`event_key`、`book`（Log／Rule）、
  `page`、`line`（快照純文字化後的行號）、`evidence`（為何是這一行：頁碼、標題、掃描頁或上下文）。
- 更正檔 `workplace/manual-english/fixes.tsv`（ignored）：`event_key`、`index`（第幾個字）、`word`、
  `evidence`（引用手冊掃描檔名與位置；不得以「讓核對通過」當理由）。
- 產生工具 `tools/manual_english_excerpt.py`：
  1. 核對快照 SHA-256；
  2. 依錨點取該行之後的正文，計字從標題後第一個字開始；以空白切字，OCR 行尾連字號（`-` 接換行）
     合併成一字；
  3. 套用更正檔；
  4. 取前 N 個字，第 N 個字去掉頭尾標點（`.,;:!?"()`，撇號與連字號保留）後轉大寫；
  5. 以 §3.1 的方式核對「第 N 個字（處理後）等於轉大寫的答案」。
  - **逐題排除**：錨點缺漏、找不到 N 個字、核對不符的題不寫入摘錄，只回報 `event_key`；其餘照常產生。
- 摘錄檔 `workplace/manual-english/excerpt.tsv`：檔頭第一列為 provenance 註解
  （快照、START.EXE、GAME.OVR 的 SHA-256 與通過數），之後 `event_key`、`ordinal`、`words`
  （前 N 個字，第 N 個字為處理後的大寫形式，以單一空白分隔）。

### 3.3 執行期

- 介面：`LiveRuntime.SetManualEnglish(path string) error`，由 `buckrogers-play` 與 receipt runner
  （只接 `liveAll` 路徑）以旗標 `-manual-english` 傳入；不傳就關閉。公開發行包不附摘錄檔、預設關閉。
- 載入核對：`event_key` 唯一且都在 `text/manual-events.tsv`；`ordinal` 與事件表相同；`words` 恰為
  N 個字、只含 0x21–0x7E 的可列印 ASCII、第 N 個字長度 1–8；允許只含部分題目。任一列不符就整個
  功能關閉，`DebugSummary` 顯示「英文列：off（原因碼）」，不帶內容；正常時顯示「英文列：on（筆數）」。
- 呈現方式：**只用在 live 固定字格路徑**（`NewRuntimeManualOverlay` 直接接線的手冊呈現）。
  規格 024 的 sealed owner 與 E1 路徑不顯示英文列，兩者的 slot 契約不變。
- 壽命：英文列是 live runtime 內的獨立呈現，每次合成前讀手冊呈現目前的請求（`event_key` 與
  generation，唯讀）。請求改變（換題、錯答重抽）或手冊呈現關閉時，英文列立即重建或清除；
  不另訂失效規則。錯答重抽時舊英文列在手冊 Begin 時消失，新題的英文列在新 Request 之後出現。
- 合成：排在手冊呈現之後；只畫在手冊清除矩形內；色彩與手冊段落相同（沿用 `SetStyle`／`Frame`
  取得的前景與背景），以不透明方式覆寫自己的格。
- 字型：與手冊段落同一個字型（2× 為 16×16 倚天、3× 為 `manualThreeXFont`），每個字元佔 1 欄，
  與 `manualRows` 一致；不使用規格 031 的 `.orig-ascii`，規格 031 不變。

### 3.4 排版（列號 0 起算，列 r 的 y = 72 + 8r）

- k = 中文段落以 `manualRows`（36 欄）切出的非空列數。英文從第 k + 1 列開始（中間空一列：第 k 列）。
- 前綴與提示字串放正式 TSV `text/manual-english-panel.zh-TW.tsv`：
  - `manual.english.long` = `英文原文第{0}字（請用大寫輸入）：`
  - `manual.english.short` = `英文第{0}字（大寫）：`
  - `{0}` 為半形阿拉伯數字；第 N 個字前後加「「」「」」。
  - 字元由 `catalog_font.py chars` 納入字型子集；載入時預檢字型涵蓋。
- 長式：前綴後接前 N 個字，字間一個半形空白，第 N 個字寫成「「字」」；以字為單位換行，一個字與其
  括號不拆開，續行從第 0 欄起，行尾空白丟棄。
- 短式：一列，前綴後接「「字」」。
- 選擇：長式放得進第 k + 1 到第 13 列就用長式；否則用短式（需第 k + 1 列 ≤ 13）；再放不下就不顯示。
  k、N 都是靜態的，載入時預先排好；**必要條件：所有有摘錄的題都至少能用短式顯示**，不符則該題在載入
  時排除並記原因碼。（2026-09-27 以正式譯文量測，k 最大 11，短式皆可放下。）
- 原版手冊字型把小寫畫成大寫字形；摘錄本身就是大寫，不受影響。

### 3.5 不做什麼

- 不翻譯英文題幹；不在摘錄檔以外的來源取英文；執行期不讀答案。
- 不預填、不自動送鍵、不在非手冊題的畫面出現；不觸發 phase-276 的 `[bp-4] = 3` 直通分支。

## 4. 驗收

1. 單元測試（合成資料）：
   - 載入核對：缺欄、`event_key` 重複或不存在、序數不符、字數不符、非 ASCII、字長超過 8、字型缺字；
     關閉時的原因碼與 `DebugSummary` 不含內容。
   - 排版：k 的計算、長式換行與括號不拆、短式退回、放不下排除。
   - 壽命：請求改變時重建、手冊關閉時清除、錯答重抽的前後順序。
   - 功能關閉時與現行畫面逐位元相同；功能開啟但該題不在摘錄時亦同。
2. 靜態（本機）：產生工具的通過數與排除清單（只記 `event_key`）；摘錄、錨點、更正檔不在 Git 追蹤範圍。
3. 原版同狀態：
   - phase-270 讀檔後的手冊問答（`gq1`）與至少一筆不同序數的題目，2×／3× 差異只在手冊清除矩形內，
     英文列與中文段落不重疊。
   - 以畫面上英文列顯示的字作答（輸入字串取自英文層實際繪出的內容，不取自答案欄；排程只存 ignored），
     原版接受並回到站內，遊戲記憶體與既有正常作答收據相同。
   - 一條正常玩家路徑：進入、錯答重抽、答對返回，畫面不殘字。
