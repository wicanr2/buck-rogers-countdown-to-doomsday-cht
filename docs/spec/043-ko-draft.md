## 1. 為什麼要做

使用者決定（2026-09-29、09-30、10-01）：F4 循環加入韓文；以英文原文為源、繁中為語境參考，子代理批次翻譯並統一詞表；敘事與手札用해라체、
系統請求與提問用합쇼체、對白依角色；人名用韓文音譯、NEO、RAM 等組織名留英文；標示為機器輔助譯文、未經母語者校對；日韓手冊題段落從繁中段落轉譯；
缺譯顯示原版英文。2026-10-01 另定：Yes／No 用「예(Y)／노(N)」、GENNIE 用「개조인」、引號用「」『』。

本規格定義**韓文譯文資料、檢查、排版（以詞為單位換行）、字型、名字與驗收**。手冊 39 段與玩家名音譯不在本規格第一期（§3.9、§4）。

## 2. 證據

- 譯文（已證實，phase-302）：46 批、5,414 列、5,406 個不同 key、31 個家族檔，逐批 `check_done.py` 錯誤 0；合併後以 `ja_check.py` 邏輯預檢（覆蓋斷言 5,414／5,406、`source`、
  佔位符、`\n`、熱鍵、水平選單大寫與數字、拉丁字母子集、引號差、逐項寬度上限）錯誤 0，警告 144（ECL 寬度倍數）；用字 1,143 個（韓文音節 1,058）。
  ECL 寬度與繁中的比平均 1.29、第 99 百分位 1.88、最大 2.36，遠低於單頁上限 456。語意稽核 59 列旗標、採納 52 條修正。
- 字型（已證實）：發行用 `unifont_all-17.0.05.hex.gz` 有現代韓文音節 U+AC00–D7A3 共 11,172 個，**全部**是 16 寬（16x16）字模，KS X 1001 的 2,350 個常用音節包含在內；
  「」『』（U+300C–300F）16 寬；`←`（U+2190）、`→`（U+2192）只有 8 寬，由 `catalog_font.py` 置中轉 16 寬（與日文相同，zh-TW 已用）；
  `…`（U+2026）、`—`（U+2014）、`“ ”`（U+201C、U+201D）、`·`（U+00B7）同為 8 寬，程式以非 ASCII 記為 2 單位，畫面會有空隙，故譯文不用。
  韓文用字不含漢字，不受 Issue #36（JIS 漢字為日文字形）影響。授權同 042。
- 載入器（已證實，與 042 §2 相同）：A 類家族硬比對 zh-TW 的 `source` 欄；缺家族檔即停用整個語言；只有標頭的檔可過。DebugSummary 目前對韓文印
  `語言停用=ko(缺語言檔 skill-exit-confirmation.ko.tsv)`，補齊檔案後消失。
- 排版（已證實）：`ecl_text.go` `layoutEclTextP` 的 token 規則是「連續 ASCII 字母數字為一個 token，其餘每個字元各為一個 token，空白也是獨立 token」；
  因此韓文音節會在詞中斷行。手札 `logbook.go` 逐段呼叫同一函式；引擎片段被自動換行拆成兩列時（`engine_dispatch.go` `joinWrapped`）拆點可落在任意字元。
  韓文以空白分詞，詞中斷行可讀性差；日文 layout profile（`layout_profile.go`）有 `adjustBreak` 與 `closing` 接口，可擴充。
- 名字（已證實）：`tools/name_glossary.py` `read_glossary` 與 Go `LoadNameGlossary` 都拒絕含空白的 `chinese` 欄（Python：`" " in chinese`；Go：
  `strings.ContainsAny(e.Chinese, " ()（）")`）。韓文外國人名依外來語標記法以空白分隔名與姓（`벅 로저스`），所以兩端都要為韓文放寬（§3.8）。
  韓文 1 至 2 音節的人名可能等於普通詞（`짐` 是行李、`탈론`、`벅` 等），需要例外表。
- 語言接口（已證實）：`LangCycle` 與 `KnownLang` 已含 `ko`；`catalog_lang.py` 的 `KNOWN_LANGS` 含 ko；收據工具 `-lang`、`-lang-dir`、`-lang-font` 通用；
  `host-ui.zh-TW.tsv` 需新增 `lang.ko`。

## 3. 契約

### 3.1 檔案

與規格 042 §3.1 相同，語言碼 `ko`：31 個家族檔、`manual.ko.tsv`（只有標頭）、`name-glossary.ko.tsv`、`name-glossary-exclude.ko.tsv`，合計 34 檔；
key 集合等於 zh-TW；`source` 逐列沿用 zh-TW 同 key；覆蓋斷言釘定 5,414 列、5,406 個不同 key（`character.skill.*` 8 個 key 兩檔相同）。
審閱用的 `ko-coverage-exemptions.tsv`、`ko-name-exemptions.tsv` 不進發行包。

### 3.2 風格與用語

- 敘事、手札、系統狀態訊息用해라체（`-다`）；直接對玩家說的請求、提問與問候（載入提示、`어떻게 하겠습니까?`、`축하합니다.`）用합쇼체；
  「」內的話依說話者（廣播與正式演說用합쇼체；軍官簡潔命令；海盜與粗人半語；SCOT.DOS 與 RAM 的 AI 冷硬해라체；太陽王的侍從對他用敬語）。
  沙漠跑者首領與長者用하오체表現古風。英文短訊息沒有句號時韓文也不加。
- 띄어쓰기依標準正字法；助詞與詞尾黏在前詞，數字與量詞黏寫；拉丁字母詞後接名詞加一個半形空白（`NEO 요원`），後接助詞不加（`NEO는`）。
  助詞依拉丁字母詞的讀音尾音選（NEO→네오，RAM→램）。
- 執行期插入的名字或數字之後的片段不能依尾音選助詞：用不隨尾音變化的助詞（`의`、`에게`、`에서`、`도`、`만`）或括號並列形（`은(는)`、`이(가)`、`을(를)`、`와(과)`）；
  ECL 靜態句中的名字依實際尾音選助詞。
- 標點用半形 ASCII（`. , ! ? : ; ( )`），引號用「」『』，刪節號用 `...`，不用破折號、ASCII 雙引號 `"`、`~`、`·`、全形標點與全形英數。貨幣 CR 譯「크레딧」；
  數字用半形；`Yes`／`No` 用「예(Y)」「노(N)」；GENNIE 一律「개조인」；玩家冒險日誌一律「일지」；方位 북、동、남、서。
- 執行期在片段後接數字的標示（LAB、DECK、LEVEL、FLOOR、POD）以名詞收尾、數字放後面；靜態 ECL 句內含數字者照韓文語序。
- 拉丁字母：只保留 zh-TW 該列本身保留的詞，不得新增英文單字。
- 統一用語以 `workplace/ko-l10n/glossary.ko.tsv` 為準（含英文，不進 Git）；跨批次裁決見 phase-302。

### 3.3 檢查工具

- 新增 `tools/lang_check.py`：把 `ja_check.py` 的共用邏輯抽成依語言設定的模組（設定含：語言碼、字集檔、禁用字元、列首與列尾禁則集合、不產生檔案的家族、
  覆蓋斷言數字）；`ja_check.py` 改為呼叫它的薄包裝，命令列與測試不變。韓文設定：`charset.ko.txt`、禁用 §3.2 所列字元、**無**列首禁則集合（標點為 ASCII，
  已屬 `isEclClosing`）、定行家族首尾字元檢查只套用「不得以半形空白開頭或結尾」。
- 逐列檢查項目同 042 §3.3 第 1 至 11 項；第 5 項寬度、第 8 項名字雙向比對、第 11 項合成負例測試全部適用；另加兩項：
  12. 韓文特有：不得含相容字母（U+3130–318F）、Hanja（U+4E00–9FFF）、`~`、`·`、連續兩個以上空白（欄名列與 zh-TW 同樣有連續空白者除外）；
  13. 拉丁字母詞與韓文相鄰：拉丁字母詞（zh-TW 保留者）後接韓文時，若接的不是助詞或詞尾清單內的字串，必須有一個半形空白（清單在 `lang_check.py`，測試覆蓋）。
- `tools/ko_check.sh`（Docker 內）：比照 `ja_check.sh` 逐支列出 `--lang ko` 驗證器與 story 路徑呼叫，加 `ko_charset.py --check`；不含 `manual_catalog.py`。

### 3.4 排版（dosgolem）

韓文 layout profile 加兩項，預設 profile 與日文不變：

| 類別 | 規則 |
|---|---|
| 以詞為單位 | token 化時，連續的非空白、非名字單位字元（韓文音節、拉丁字母、數字、收尾標點）合為一個 token；token 寬度超過一列時退回逐字 token（長詞不使排版失敗） |
| 引擎片段兩列拆分 | `adjustBreak` 在拆點落於詞中時，往前找同一列內最近的空白，在該空白後拆；找不到空白或往前距離超過 12 單位則維持原拆點；拆在空白處時該空白不顯示 |
| 禁則 | 不另設；`isEclClosing` 的 ASCII 收尾標點（`,.!?:;)`）與「」的閉括號維持不放列首 |

手冊逐字貪婪填列、水平選單、劇情頁不換行，詞單位不適用。需改的程式：`layout_profile.go`（新增 ko profile 與詞 token 欄位）、`layoutEclTextP` 的 token 迴圈、
`adjustBreak`；`layoutLogbookUnitsP` 與 `EclTextWatcher` 已由 042 接 profile，不需再改。

### 3.5 載入與錯誤隔離

同 042 §3.5：A 類零失敗；B 類做靜態預檢（Go 測試，非閘門）並報告詞 token 造成的多列數；手札頁數與標題寬度以 Go 為準。

### 3.6 半形與全形

同 042 §3.6。韓文音節 2 單位；ASCII 標點與空白 1 單位；名字加註「한글(English)」，括號內英文半形；多段名字（`벅 로저스`）在窄欄只顯示韓文。

### 3.7 字型

- `tools/ko_charset.py` 產生 `font/charset.ko.txt`：可見 ASCII（U+0020–007E）∪ 現代韓文音節（U+AC00–D7A3，11,172 字，需 16 寬字模）∪ 「」『』（U+300C–300F）
  ∪ 8 寬置中箭頭 {U+2190、U+2192}；共 11,273 字。`--check` 重生後與檔案逐位元組比對。
- `font/characters.ko.txt` 由正式韓文譯文產生並進版控，必須是字集的子集；`tools/catalog_font.py --lang ko` 產生 `font/buckrogers-ko.golemfnt`，連建兩次 SHA-256 相同。
- 本機字型放 `workplace/lang-fonts/`。

### 3.8 名字

- `text/name-glossary.ko.tsv`（`chinese` 欄放韓文寫法；`basis` 為 `ko-glossary`）與 `name-glossary-exclude.ko.tsv`；來源為詞表 `name` 段 42 列，名與姓以**一個半形空白**分隔。
- `tools/name_glossary.py`：`lang_name_rules("ko")` 回傳分隔符為空白，`chinese` 欄對 ko 允許單一內部空白（不得首尾空白或連續空白）；`basis` 允許 `ko-glossary`。
- Go `LoadNameGlossary`：對 ko 允許 `chinese` 內含空白（以語言參數決定），其餘檢查不變；名字單位含空白時，`layoutEclTextP` 既有「單位超過一列寬才在單位內的空白拆」邏輯維持。
- 例外表收錄韓文普通詞與人名同形者（例如 `짐` 指行李、其他經掃描確認者），scope 用 key 樣式；列級豁免放 `ko-name-exemptions.tsv`。
- 玩家名：規格 045 之前 ko 的 `PlayerNames` 停用，名字顯示英文。

### 3.9 手冊題（本期不做）

同 042 §3.9：`manual.ko.tsv` 只有標頭；手冊題提示句為韓文，段落顯示原版英文；韓文段落從繁中段落轉譯並另訂規格。

## 4. 不做什麼

## 5. 驗收

1. `tools/ko_check.sh` 全綠；合成負例全部失敗；`ko_charset.py --check`、`catalog_font.py --lang ko` lint 通過。
2. 覆蓋斷言：31 個家族檔 5,414 列、5,406 個不同 key；`manual.ko.tsv` 0 列；`source` 逐列等於 zh-TW。
3. 載入：前端與收據工具載入後 ko 在 F4 循環內；DebugSummary 有 `lane[ko]`、無「語言停用=ko」。
4. 版面：§3.4 的單元測試（詞 token、長詞退回、拆點找空白、名字單位含空白）通過；zh-TW、zh-CN、ja 的 phase254 七條回歸與既有收據逐位元組不變；
   Go 靜態預檢報告附在收據；trace 重播閘門同 042 §5.4。
5. 串接：依既有 trace 批量產生串接後字串，機器驗證首尾字元與助詞（`은(는)` 等括號並列形出現次數、拉丁字母詞相鄰空白）；抽審至少 100 條並記錄通順率，基準寫在收據。
6. 同狀態收據（2×、3×）：規格 040 §5.3 的四個時點以 `-lang ko` 輸出，記憶體與 CPU 雜湊與 zh-TW 相同；另 16 個家族時點（phase-301 的清單）機器狀態相同；截圖無缺字與溢出。
7. 語義對照：phase-302 的「與 zh-TW 分歧清單」作為 A/B 對照；雙語審查抽樣至少 100 列，記錄錯誤率，不設數字閘門。
8. 覆蓋表：每個家族列出證據等級；README 與讀我.txt 只對前兩級宣稱「已韓文化」。
9. 前端與打包：冷開機切到韓文截圖；說明頁「目前語言」為「韓文（機器輔助）」；打包產物含 ko 字型並通過外洩掃描。
