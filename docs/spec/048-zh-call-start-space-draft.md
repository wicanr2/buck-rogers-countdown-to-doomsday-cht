## 1. 為什麼要做

原版把甲板提示分成多次呼叫畫：`…DECK `（尾端有空白）、`5`、`.`，其後多半接 ` WHERE DO YOU GO?`（72 則是四次呼叫，另 2 則沒有提問段，是三次）。規格 047 之後 zh-TW、zh-CN 畫成 `…你們身處甲板5。你們要往哪裡去？`，漢字與數字之間沒有空白。
`ecl-text` 的靜態譯文在漢字與數字之間一律有一個半形空白（漢字接數字 29 列、數字接漢字 21 列，聯集 31 列，兩種無空白寫法都是 0 列，例：`第 3 層甲板`、`漆著數字 1。`），數字與全形標點之間不留空白（13 列）；手札範本 `編號 38。` 同樣寫法。使用者決定這一處也照此辦理：`甲板 5。`。

## 3. 契約

### 3.1 範圍

zh-TW、zh-CN 的 ECL 文字視窗（`EclTextWatcher.ObserveEntry` 的續接呼叫）。語言碼取 `EclTextCatalog.lang`；載入函式已把空字串正規化為 zh-TW（規格 047 §3.1），所以 `zhDeckSpace()` 對語言碼只認 `zh-TW`、`zh-CN`，nil 安全。
ja（`デッキ5。` 日文數字與假名之間不加空白）、ko（`갑판 5.` 已有空白，規格 046 §3.4）、測試語言 zz 不變；ko 的詞級路徑原樣保留。

### 3.2 條件

以下全部成立才在本次輸出文字前補一個半形空白（U+0020）：

1. 這是續接呼叫：`!fresh` 且已有頁面（`p != nil`）。`p == nil` 的非 fresh 分支（前一則未命中、英文留在畫面上）不適用。
2. 這不是玩家名呼叫（`isPlayer` 為假）；音譯失敗落入 passthrough 的玩家名呼叫（`isPlayer` 仍為真）同樣不適用。本規格不改 `spaceNeeded` 的計算，也不改 `layoutPlayerName` 的引數（zh 的版面 profile 是 nil，`spaceNeeded` 本來就恆為假）；zh 旗標只作用在 `!isPlayer` 的一般路徑。
3. 本次輸出文字 `text`（原文為 `.`、`. ` 以外的 passthrough、catalog 譯文，或 key 為 `engine` 的引擎翻譯）的第一個字元是 ASCII 數字 `0`–`9`。引擎翻譯涵蓋但資料中 0 次；§3.5 的「引擎片段」指片段表內的靜態譯文，兩者不同。
4. 頁面最後一行畫出的文字（`p.Lines` 的最後一項）以 `甲板` 結尾。
5. 排版起點欄不等於 `eclUnitLeft(e.Left)`（規格 046 §3.4 條件 4：`e.CursorCol == e.Left` 的換列調整之後的值；原因：`layoutEclTextP` 只在「空白導致換行」時捨去行首空白，起點在列首時補的空白會成為列首縮排）。

條件 4 取代了「原文以空白結尾」與「前一個字元是漢字」的狀態判斷：原版的甲板提示原文結尾都是 `DECK `，譯文結尾都是 `甲板`（`ecl.2.32.03956`、`ecl.2.32.09000`、`ecl.2.33.08985`，zh-TW、zh-CN 都是），條件 4 直接以畫面上已畫出的文字判定，不新增頁面狀態。
`甲板` 被換列拆在兩列之間時（最後一行只有 `板`）不補；這是接受的限制（trace 中 74 次全在第 17 列、列尾最大 55 單位，沒有換列）。

### 3.3 排版與放不下

插入點：`ObserveEntry` 一般（非玩家名）路徑的 `if !done` 區塊內，與 ko 的 `spaced` 並列為第三條路：`spaced` 為真（詞級 profile，ko）時走原樣，zh 旗標不評估（詞級優先，避免雙空白與 `SpaceDropped` 重複）；否則 zh 旗標為真走本節；否則 `attempt(text)` 原樣。不併進 `spaceNeeded`，不改 `attempt`（它是所有語言、所有呼叫共用的閉包）。
`fullStop` 區塊不動：它要求原文逐位元等於 `.` 或 `. `，此時 `text` 第一個字元是 `.`，zh 旗標必為假；兩者互斥。

zh 旗標的求值次序（熱路徑，最便宜的先）：`zhDeckSpace()`（語言碼）、續接且 `p != nil`、`!isPlayer`、`text` 第一個字元是 ASCII 數字、起點欄不等於左欄、`p.Lines` 最後一項以 `甲板` 結尾。

本節路徑：先 `attempt(" "+text)`；含空白的結果成立的判準是「第一個畫出的列在起點列，且該列文字以空白起首」（空白把數字推到下一列、或空白本身換列被捨去時，第一個畫出的列不在起點列）；成立就採用。
不成立（排版失敗，或第一個畫出的列不在起點列）時，退回 `attempt(text)`，這次成功才 `EclTextStats.SpaceDropped` 加一；兩次都失敗沿用既有的 `Overflows` 流程。判準取 `attempt` 回傳的第一個放得下的名字註記階層，且只寫在本節路徑內，不放進 `attempt`。
次序是「全部名字註記階層先含空白、失敗再全部不含空白」，空白優先於名字註記（與規格 046 §3.4 條件 5 在程式裡的實際次序相同；zh 資料中以數字起首的 catalog 譯文為 0 列，passthrough 不走 `Variants`）。空白不是本呼叫變成英文的理由。
兩次結果相同（起點已在列尾、數字本來就換列）時 `SpaceDropped` 仍加一，接受這種計數偏高。

已知限制（空白對「下一次呼叫」的間接影響；窄帶由數字呼叫的起點欄決定，不是頁尾結束欄）：數字呼叫起點後剩餘寬度 R（單位）為 3 時，含空白的 ` 5` 放得下，其後的 `。`（規格 047，2 單位）多一單位而退回半形 `.`（`FullStopDropped` 加一）；R 為 2 時 ` 5` 剛好填滿，退回後的 `.` 被換到下一列列首，起點列若已是視窗末列則該 `.` 排版失敗、記一次 `Overflows`、窗口變英文。
trace 到不了：數字呼叫的起點欄是 36（72 則）、32、14，到右緣欄 77 的剩餘寬度最小 42 單位，距 R=3 至少 39 單位；補空白後頁尾結束欄由 55 變 56，距右緣至少 22 單位。單元測試記錄 R=3、R=2 兩個行為（R=1 時含空白的數字被推到下一列，依判準退回不含空白）。

### 3.4 狀態與其他呼叫

不新增 `EclTextPage` 欄位，不改 `owedSpace`、`lastRune` 的建立條件（仍只有詞級 profile，即 ko）。補的空白是該次呼叫段落文字（`Lines`）的前導空白，起點欄不變。
規格 047 的單獨句點呼叫（原文 `.` 或 `. `，`text` 不是數字）與本規格互斥。

### 3.5 不做什麼

- 字母起首的呼叫（資料 5 次：3 次前字是 `。`；2 次前字是漢字，其一是原版資料瑕疵，其一在列首）；字母與中文之間的空白習慣（靜態譯文漢字後接字母有空白 137 列、無空白 1 列）另案。
- 以 `第`、`編號`、`持有` 等漢字結尾的譯文（`ecl.4.66.08710`、`08952`、`ecl.3.48.02333`、`ecl.4.66.02889`）：trace 沒有它們之後的數字呼叫（0 次）；`ecl.4.66.02889` 之後的 `張紅卡、1 張綠卡，以及` 自己寫了 `1 張`，只補左側會讓同句內不一致，需連右側一併決定。
- 水平選單的 `你目前在甲板`、引擎片段與靜態譯文（`受到1點傷害` 等 13 列既有殘留）、手札範本欄位、玩家名單元、ja、ko、zz。

## 4. 驗收

1. 單元測試：
   - zh-TW、zh-CN：`DECK ` 加 `5` 補空白（得 `甲板 5`，其後的 `。` 與提問句各右移一單位）；`DECK `、`5`、`.` 得 `甲板 5。`；三次呼叫（無提問句）同；多列的甲板呼叫（最後一列以 `甲板` 結尾）補；第二個數字呼叫（`5` 之後的 `6`）不補；`5` 之後的 `。` 不補。
   - 不補的情形：前一次畫出的文字不以 `甲板` 結尾（`編號`、`第`、`。`、拉丁字母、譯文自帶尾端空白）；本次文字以字母或中文起首；`p == nil` 的非 fresh 分支；起點在左欄（換列）；fresh 呼叫；`甲` 與 `板` 被換列拆開；`甲板` 後插入純空白呼叫再接數字（最後一項是空白，不補）。`甲板` 後插入空文字呼叫再接數字會補（`Lines` 沒有新增）。
