## 3. 契約

### 3.1 產生流程

- 產生器 `tools/zh_cn_convert.py`（主 repo），在固定版本 Docker image 內執行：OpenCC 1.4.2 以 wheel 雜湊鎖定，
  建置 image 的 Dockerfile 與鎖定檔放在 `tools/docker/opencc/`；只有下載 wheel 的建置步驟開網路，轉換一律 `--network none`。
- 專案設定：官方 `tw2sp.json` 為基礎，在第一段用語群組最前面插入專案詞表；設定檔與其 SHA-256 記在 repo。
- 專案詞表 `text/zh-CN-phrases.tsv`：欄位 `tw`、`cn`、`kind`（`keep` 保留原詞、`map` 指定對應、`fix` 修正斷詞）、`reason`。
  用語偏好（文档、图像、数据、读取、信息、英尺）以 `map` 寫入。
- 逐列覆寫 `text/zh-CN-overrides.tsv`：欄位 `family`、`key`、`zh_tw_sha256`（該列 zh-TW 譯文雜湊）、`translation`、`reason`。
  zh-TW 譯文雜湊與記錄不符時產生器失敗，要求重審。
- 輸入：全部 `text/*.zh-TW.tsv` 的 translation 欄；輸出 `text/*.zh-CN.tsv`，key 集合與 zh-TW 相同，其他欄不動。
- 不變量（任一違反即失敗）：ASCII 字元、佔位符 `{n}`、`\n` 等控制碼、`(X)` 熱鍵、全形標點「」『』與 `•` 在轉換前後
  逐一相同。
- 決定性：同一輸入、同一 image、同一詞表與覆寫表，輸出位元組相同；repo 提供 `--check` 模式重新產生並比對，差異即失敗。
- 手工不得直接編輯 `*.zh-CN.tsv`；所有修正經詞表或覆寫表。

### 3.2 名字

- 036 譯名表：產生器同時輸出 `text/name-glossary.zh-CN.tsv`（chinese 欄以同一流程轉換，其他欄不動），執行期 zh-CN 的
  NameGlossary 載入它；轉換後同一 `person` 的寫法一致，否則失敗。
- 037 音譯：產生器輸出 `text/translit-zh-CN-map.tsv`（允許字集 329 字的繁→簡字級對照，一對一，碰撞即失敗）。
  zh-CN 的 PlayerNames 先以 zh-TW 音譯器產生，再逐字依對照表轉換；不用詞組級轉換。

### 3.3 驗證器與字型

- 兩支寫死 zh-TW 字面的驗證器改為：zh-TW 照舊比對字面；其他語言比對「以同一產生流程轉換 zh-TW 字面後的結果」。
- 其他驗證器以 `--lang zh-CN` 對產生的檔案執行，全部通過。
- 字型：`tools/catalog_font.py --lang zh-CN` 由 zh-CN 譯文建 Unifont 子集 `font/buckrogers-zh-CN.golemfnt`（打包時產生，
  不進 Git）；打包流程對每個啟用語言建字型。本機倚天不用於 zh-CN。

### 3.4 審閱

- 產生器輸出「套用詞條清單」（key、詞條、kind，不含前後文全文）；381 處用語套用由實作者逐一抽檢並記錄結論。
- 手冊段落中被詞組改寫的 12 列：實作者核對語意是否正確，只記 key 與結論，不在任何文件、Issue 或回報中輸出段落內容。

   音譯對照碰撞失敗。

3. 執行期：前端與收據工具載入後 zh-CN 在 F4 循環內（`Languages()` Enabled）；DebugSummary 無 zh-CN 停用與重建計數。
