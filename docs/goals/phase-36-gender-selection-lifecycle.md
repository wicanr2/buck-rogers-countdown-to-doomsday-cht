# 第 36 階段 Goal：性別選擇生命週期收據

狀態：完成

## 目標

以既有 dosgolem 輸出端文字事件收據，從固定原版狀態經正常 BIOS 鍵盤輸入進入性別選擇畫面，量測並固定以下玩家可見生命週期：

1. 向下移動選擇；
2. 向上移動選擇；
3. 按 `Esc` 返回上一層；
4. 各路徑停止點的 framebuffer。

本階段建立的是原版行為證據與可重播驗證，不加入繁體中文翻譯、不實作輸出端覆繪，也不替使用者決定 2×／3× 顯示倍率。

## 固定輸入

- dosgolem 工作分支：`buck-rogers-cht-output-overlay`
- 原版啟動程式：`workplace/original/BRcdoom/START.EXE`
- 原版覆疊檔：`workplace/original/BRcdoom/GAME.OVR`
- 起始狀態：`workplace/probe/after-bios-space-100m.state`
- 進入路徑：正常 BIOS `Enter` 輸入進入種族選擇，再以正常 BIOS `Enter` 接受預設種族並進入性別選擇。

正式收據必須記錄輸入檔 SHA-256、dosgolem commit、命令來源 SHA-256、鍵盤時程、停止時間、事件序列與 framebuffer SHA-256。

## 工作項目

- [x] 以可丟棄探測確認性別畫面的 `Down`、`Up`、`Esc` 時程與事件邊界。
- [x] 建立或補齊性別選擇生命週期的規格閘門；任何新工具程式碼都必須先達 READY。
- [x] 各正式路徑獨立重跑兩次，確認事件收據與 framebuffer 可逐位元重生。
- [x] 建立不含原版英文全文的受版控事件清冊與驗證器測試。
- [x] 更新研究紀錄、`CONTEXT.md`、`WORKLOG.md` 與文件索引。
- [x] 在 Docker 內完成專案測試、dosgolem 測試與靜態檢查。
- [x] 檢查容器生命週期、root-owned 殘留及兩個工作樹狀態。
- [x] 提交 dosgolem 本機分支（若本階段有變更），提交並推送專案 `main`。
- [x] 使用主機 `gh` 更新 GitHub Issues #4 與 #7。

## 完成條件

- 性別選擇的向下、向上與返回路徑都有正常玩家輸入的決定性收據。
- 同一路徑兩次正式執行的收據與 framebuffer 完全一致。
- 事件清冊只保存定位、雜湊、畫面屬性與語意角色，不收錄可替代原版內容的英文全文。
- 測試可拒絕事件次序、文字雜湊、呼叫端、屬性或 framebuffer 遭竄改的收據。
- 文件清楚區分已證實行為、尚未翻譯／覆繪的範圍，以及仍待使用者決定的顯示倍率。
- 專案 `main` 已推送且 GitHub Issues 已留下本階段可追溯摘要。

## 不在本階段範圍

- 中文翻譯定稿與字型排版。
- 輸出端繁體中文覆繪。
- 手冊段落顯示與答案流程。
- 選定 2× 或 3× 顯示倍率。
- 建立發行包或公開原版資產。
