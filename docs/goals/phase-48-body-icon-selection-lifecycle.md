# 第四十八階段：角色身體圖示選擇生命週期

狀態：已完成

## 目標

沿用第四十七階段正常 Escape→`Y` 路徑進入角色身體圖示選擇畫面，辨識圖示選取移動、
套用、完成或返回操作，建立 content-safe、可重播且失敗即關閉的正式收據。

## 範圍

- 由同一固定 state 走完整正常 BIOS 前綴到角色身體圖示畫面，再由相同基線獨立探測
  方向鍵、Enter、Escape 及畫面明示的完成操作。
- 以事件次序、identity、色彩、座標與完整 framebuffer 判斷選取與轉場，不猜測控制規則。
- 正式驗證至少涵蓋一條圖示選取移動，以及一條可判定的套用、完成或返回路徑。
- 每條正式分支各從相同 state 獨立重播兩次，固定 BIOS 排程、事件 step、原版與命令雜湊及
  64,000-byte indexed framebuffer。
- 建立 dosgolem 診斷規格、content-safe 清冊、嚴格 verifier、正反例測試與研究文件。
- 完成後提交 dosgolem 本機分支、推送專案 `main` 並更新 GitHub Issues。

## 不在本階段

- 不推導所有圖示的語意、角色裝備規則或未走到的後續角色建立流程。
- 不使用 direct-entry、記憶體注入或測試跳關。
- 不保存原版英文全文，不把圖形像素誤列為文字翻譯來源。
- 不翻譯此畫面、不接 renderer、不選定 2×／3×。

## 成功定義

1. 正常輸入證實至少一條選取移動及一條可判定的套用、完成或返回結果。
2. 正式分支各雙重重播逐 byte 相同；靜態文字事件與圖形重畫已分開分類。
3. verifier 對輸入、事件、step、identity、畫面、原版與命令雜湊漂移失敗即關閉。
4. dosgolem 規格達 CONFORMED；專案測試、正式 Go packages、`go vet` 與相關 race detector
   通過。
5. 專案 `main` 已推送、Issues 已更新，兩個工作樹與 Docker 生命週期乾淨。

## 退出條件

- 若完成操作不是單一按鍵，只保存實測到的控制證據，將未證實分支留待下一窄切片。
- 若完成後進入下一畫面，只追到第一個穩定玩家可見邊界，另開切片處理其互動。
- 若流程會寫入檔案，只在唯讀原版與明確可寫 overlay 下重播。

## 完成結果

- 已證實四方向鍵皆改變圖示選取；正式固定 Right 分支。
- Enter／Escape 皆顯示同一圖示確認提示；Enter→`N` 回到逐 byte 相同基線，Enter→`Y`
  進入儲存詢問畫面。
- 三條正式分支各雙重重播逐 byte 相同；三份清冊、嚴格 verifier 與正反例測試已建立。
- 專案 90 項測試與 dosgolem 正式 packages test／vet／race 全數通過，spec 029 已 CONFORMED。
- 本階段沒有翻譯、接 renderer、回答儲存詢問或替使用者選定 2×／3×。
