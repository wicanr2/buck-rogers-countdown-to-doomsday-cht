# 第七十四階段：技能配置底部操作列輸出路徑清冊

狀態：完成

## 目標

針對職業技能與技術技能配置畫面底部仍顯示英文的 ADD、SUBTRACT、PREV、NEXT、DONE，使用
dosgolem 正常玩家路徑與可追溯執行證據，找出其原始輸出來源、繪製時機、座標、色彩及選取／
禁用生命週期，形成可供下一階段 DRAFT 規格使用的 content-safe 清冊。

## 範圍

- 從第 71、73 階段的正式畫面與相同 savestate 重生操作列基準。
- 證實五個標籤是文字 dispatcher、預烘像素、逐字模呼叫或其他路徑；保留原始位址空間、
  callsite／寫入端與推論等級。
- 以至少初始畫面、Left／Right 移動及可用／不可用狀態，量測標籤色彩與重畫生命週期。
- 正式清冊只保存雜湊、位址、幾何、狀態與證據引用，不收錄可還原原作的大量文字。

## 不在本階段

- 不先行翻譯或接入 production overlay，不修改原版輸入、技能點、選單焦點或完成判定。
- 不假設職業技能與技術技能共用相同輸出身分；必須由執行證據確認。
- 不選定產品預設 2×／3×，不處理手冊題目版面。

## 完成條件

1. 五個玩家可見標籤各有可回查的原始來源、畫面矩形、色號與至少一個正常玩家路徑事件。
2. 初始、焦點移動及禁用／可用差異有決定性收據；無法觸發的狀態明確標為未知。
3. 清冊與 verifier 能拒絕位址、幾何、雜湊、狀態或來源漂移。
4. 證據足以判斷下一階段應擴充通用 watcher、建立畫面錨點 watcher，或維持未支援；不以猜測
   直接進 production。
5. 專案回歸與相關 dosgolem 測試通過；專案 `main` 推送並更新相關 GitHub Issues。

## 退出條件

- 若路徑需要新增 dosgolem 診斷能力，先建立最小 content-safe probe，不把診斷 hook 當正式覆繪。
- 若標籤來自資產而非程式文字，不匯出或提交原版資產，只保存雜湊、矩形與執行期定位。
- 若焦點或可用狀態未能由正常輸入觸發，維持 unknown，不以畫面顏色推定控制流語意。

## 完成收據

- 已證實五個標籤共用 `0763:026B` 逐字路徑，後續由 `0763:1809`
  的 8×8 glyph renderer 輸出；它們不是原有高階 dispatcher 事件。
- 職業三標籤、技術五標籤的初始與每次 Right 焦點路徑均已決定性重生；
  一般／焦點 caller、色彩、字格與安全矩形已固定於
  `text/skill-action-bar-events.tsv`。
- 正常輸入未觀測到獨立 disabled variant，故依退出條件維持 `unknown`，不影射為
  已證實的可用狀態。
- 清冊 verifier 會拒絕 schema、位址、雜湊、幾何、色彩與證據等級漂移；
  dosgolem spec 213 以 DRAFT 登記下一階段的 guarded glyph-event watcher。
- 本階段沒有翻譯或接入 production overlay，也沒有選擇 2×／3× 或手冊版面。
