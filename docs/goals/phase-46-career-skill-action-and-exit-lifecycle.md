# 第四十六階段：職業技能動作選單、減點與確認離開生命週期

狀態：已完成

## 目標

沿用第四十五階段相同固定 state 與正常角色建立路徑，辨識技能配置畫面底部動作選單的
Left／Right 次序，證實一次「先加後減」是否可逆，並量測仍有未用點數時 Escape→`Y` 的
實際離開終點，建立 content-safe、可重播且失敗即關閉的正式收據。

## 範圍

- 由同一配置畫面分支探測 Left／Right 後 Enter，透過事件與 framebuffer 判斷動作位置，
  不憑不可見反白文字猜名稱。
- 減點分支必須先以正常 Enter 合法加一點，再用方向鍵選擇候選動作並 Enter；比較剩餘點數、
  選取列與完整終點畫面是否回到配置前基線。
- 離開分支使用 Escape→`Y`，只追到第一個穩定玩家可見終點，記錄是否離開、轉場或寫入資料。
- 正式分支各從相同 state 獨立重播兩次，固定 BIOS 排程、事件 step／identity、原版與命令
  雜湊及 64,000-byte indexed framebuffer。
- 建立 dosgolem 診斷規格、content-safe 清冊、嚴格 verifier、正反例測試與研究文件。
- 完成後提交 dosgolem 本機分支、推送專案 `main` 並更新 GitHub Issues。

## 不在本階段

- 不自動分配全部技能點，不推導技能上限、bonus、total 或職業規則。
- 不以記憶體注入、直接設定點數或跳關取代正常玩家輸入。
- 不把底部不可見選取文字直接列為已證實譯文；不保存原版英文全文。
- 不翻譯技能配置畫面、不接 renderer、不選定 2×／3×。

## 成功定義

1. 至少一條正常輸入路徑證實加點後減點的事件與終點效果，或以明確負面證據排除候選。
2. Escape→`Y` 的第一個穩定玩家可見終點已辨識，且不把確認提示誤當成已離開。
3. 正式分支各雙重重播逐 byte 相同；verifier 對輸入、事件、step、identity、畫面與雜湊漂移
   失敗即關閉。
4. dosgolem 規格達 CONFORMED，專案測試、正式 Go packages、`go vet` 與相關 race detector
   通過。
5. 專案 `main` 已推送、Issues 已更新，兩個工作樹與 Docker 生命週期乾淨。

## 退出條件

- 若 Left／Right 動作語意仍無法由玩家可見結果區分，只保存位置與負面證據，不猜名稱。
- 若 Escape→`Y` 進入後續角色流程，只停在首個穩定畫面，另開切片處理其互動。
- 若離開會觸發存檔或不可逆資料寫入，只在唯讀原版加可寫隔離 overlay 中重播。

## 完成結果

- 正常輸入證實 Enter 加點後 Right→Enter 可把點數完整還原；Left 會環回離開位置。
- Escape→`Y` 已進入穩定的技術技能配置畫面，不再停在確認提示。
- 兩條正式分支各雙重重播逐 byte 相同；兩份清冊、嚴格 verifier 與正反例測試已建立。
- 專案 85 項測試及 dosgolem 正式 packages test／vet／race 全數通過，spec 027 已 CONFORMED。
- 本階段沒有翻譯、修改技能規則、接 renderer 或替使用者選定 2×／3×。
