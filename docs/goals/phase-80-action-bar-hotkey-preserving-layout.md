# 第八十階段：技能操作列快捷字母保留與混合寬度版面

狀態：完成

## 目標

依使用者決定，技能操作列保留括號內的拉丁快捷字母並維持白色，中文標籤沿用原版
一般文字色。以真實 framebuffer、原版事件與正式字型驗證混合半形／全形的版面，
不得裁切、互疊或覆蓋金色框線。

## 已確認的產品決定

- 排除「兩個中文字全綠」與「第一個中文字白色」兩個舊候選。
- normal 顯示採 `(快捷字母)中文標籤`；快捷字母為白色，中文為原版一般標籤色。
- focus 狀態仍須保留原版黑字白底的辨識語意。
- 不因版面不足而省略快捷字母、裁掉中文或改寫遊戲輸入語意。

## 範圍

- 從既有事件／玩家路徑證據核對 `Add`、`Subtract`、`Prev`、`Next`、`Done` 的字母身分；
  可見助記字母與已證實可操作快捷鍵須分開標示。
- 量測正式 Unifont 子集的 ASCII 與繁中文字形墨跡，建立可丟棄的 2×／3× 真實畫面 prototype。
- 驗證最窄的 `Add` 區段能否安全使用右側空白，並逐項檢查相鄰標籤、動態數值與框線。
- 依證據修訂 Phase 77–79 的決策狀態與 dosgolem spec 215；只有幾何及資料契約充分時才升 READY。

## 不在本階段

- 不選定全專案正式 2×／3× 倍率，不決定手冊版面。
- 不修改原版快捷鍵判定、技能規則、VRAM、存檔或輸入流程。
- 不把原版遊戲、手冊或可還原的大量原文加入版控。

## 完成條件

1. 每個顯示字母均有原版輸出證據；若尚未證實鍵盤可操作，只稱為助記字母。
2. 2×／3× prototype 均以正式字型及真實 framebuffer 產生，並證實所有墨跡不越過批准範圍。
3. normal 只有快捷字母為白色，中文為 palette 10；focus 保留黑字白底且整組原子取代。
4. catalog、幾何與 renderer 契約失敗即關閉，相關測試通過。
5. 專案 `main` 推送，GitHub Issues 回寫本階段證據與剩餘限制。

## 退出條件

- 若括號、字母與兩字中文在原版 command band 無法安全共存，停在 prototype 並以實圖請使用者
  決定替代版面；不得自行縮字、裁字或侵入框線。
- 若只能看到字母但未證實其輸入作用，不把視覺證據冒稱為快捷鍵控制流證據。

## 完成收據

- 五筆正式顯示文字保留 `(A)`／`(S)`／`(P)`／`(N)`／`(D)`，只有字母使用 palette 15。
- 2×／3× 真實 framebuffer prototype 證實 28 logical-pixel 版面；`Add` 使用原版兩標籤間
  的單一空白格後仍不重疊，y 軸維持 `[192,200)`。
- 專案 149 項 Python 測試通過；dosgolem 核心測試固定混合前進、配色及 group 生命週期。
- 字母直接鍵盤作用仍為 unknown；spec 215 升 READY，完整 runtime 玩家路徑留待下一階段。
- dosgolem 本機分支提交為 `8bfd5b4`，依規範未推送遠端。
