# 第三十九階段：職業選擇生命週期收據

狀態：完成

## 目標

沿用第三十八階段的正常玩家輸入路徑，量測職業選擇畫面接收方向鍵與 Escape 後的文字事件、反白轉移、畫面返回及 framebuffer 結果，建立可重播且失敗即關閉的正式收據。

## 範圍

- 由既有固定狀態依序送出三次 Enter，抵達職業選擇畫面。
- 分別量測 Down／Up 與 Escape 的 BIOS 輸入生命週期。
- 保存每筆文字事件的原始定位、呼叫端、文字身分、色彩、列欄與推論等級。
- 在 dosgolem 分支加入本案所需的最小、通用或遊戲限定機制，依 DRAFT → READY → implementation → CONFORMED 流程留下規格。
- 建立重播驗證器、測試與正式 JSON／framebuffer 收據。
- 更新研究紀錄、目前狀態與 GitHub Issues。

## 不在本階段

- 不加入職業名稱繁中翻譯或 renderer 接線。
- 不替使用者決定 2×／3× 顯示倍率。
- 不繞過原版角色建立流程、直接跳入內部畫面。
- 不把尚未驗證的職業規則或欄位語意寫成已證實結論。

## 成功定義

1. Down／Up 與 Escape 都由正常 BIOS 輸入重播，並各至少重跑兩次得到相同事件與 framebuffer。
2. 方向鍵造成的 normal／selected 文字事件與反白轉移有 typed、可稽核清冊。
3. Escape 的目的畫面與清除／重繪順序有玩家可見證據；若無法判定則明確標為未知。
4. 收據驗證器對遺漏、重排或不符身分的事件失敗即關閉，並有正反例測試。
5. dosgolem 規格達 CONFORMED，相關測試、`go vet` 與 race 測試通過。
6. 專案測試全數通過、工作樹權限與 Docker 清理狀態正常，成果推送至 `main` 並回填 GitHub Issues。

## 退出條件

- 若現有 dosgolem 尚不能表達必要輸入或收據資料，先將缺口寫入規格並補足最小能力，不以 DOSBox 圖片冒充正式收據。
- 若實測出現會改變玩家體驗、資料格式或中文覆繪架構的新分支，停止該分支並交由使用者決策；不依賴該決策的證據工作仍可繼續。
