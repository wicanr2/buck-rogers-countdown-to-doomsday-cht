# 第六十一階段：手冊單頁容量失敗即關閉驗證

狀態：完成

## 目標

將 spec 002 已記錄的 36 欄×17 行＝612 字單頁容量，落成正式手冊 catalog 驗證契約；
防止未來新增或修改譯文時靜默超限、截斷，或在尚未設計分頁輸入前流入 runtime。

## 範圍

- 先核對正式 catalog parser 與第十七階段 prototype 的字元計數語意。
- 在 `tools/manual_catalog.py` 驗證每筆正式譯文不超過 612 個顯示字元。
- 新增邊界正例與超限負例，並重跑完整專案測試。
- 更新 spec、研究紀錄、目前狀態與 GitHub Issues。

## 不在本階段

- 不選定 2×／3×，不接手冊 renderer，不將 spec 002 升為 READY。
- 不新增分頁按鍵、頁尾提示、截斷策略或自動送鍵。
- 不改原版題目、答案驗證、輸入、記憶體或存檔。

## 完成條件

1. 612 字邊界由常數與測試固定，612 字通過、613 字失敗即關閉。
2. 正式 22 筆 catalog 與完整專案回歸通過。
3. 研究文件可追溯規格、程式、測試與驗證命令。
4. 專案 `main` 已提交推送，相關 GitHub Issues 已更新；dosgolem 無變更時不製造空提交。

## 退出條件

- 若 parser 或 prototype 的「字元」語意不一致，先保留 DRAFT 並訂正證據，不猜測容量。
- 若現有正式資料已超限，停止實作並回到譯文／版面 DRAFT，不默認截斷。

## 完成摘要

- 正式 validator 由 36 欄與 17 列導出 612 字上限；612 字通過、613 字失敗即關閉。
- 現有 22 筆正式 catalog 通過，完整測試由 101 增至 103 項並全數通過。
- 未新增分頁互動、截斷或 runtime 行為；spec 002 維持 DRAFT，倍率仍待使用者選定。
