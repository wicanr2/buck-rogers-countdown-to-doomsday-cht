# 第五十九階段：手冊執行期繁中覆繪倍率門檻

狀態：進行中（等待使用者確認）

## 目標

以已完成的 2×／3× 手冊段落與功能選單對照、第 57 階段雙倍率 runtime 收據，
請使用者確認正式產品輸出倍率。確認後才能將手冊繁中段落覆繪規格升為 READY，
並開始正式 dosgolem runtime renderer 與正常玩家路徑驗收。

## 已知事實

- 2× 輸出 640×400，原版 8×8 格變為 16×16，16×16 字模填滿字格。
- 3× 輸出 960×600，原版字格變為 24×24，16×16 字模置中，四邊各留 4 px。
- 兩案都使用 36×17 手冊正文格線，每頁 612 字；頁數與容量不變。
- 手冊段落、功能選單與第 57 階段 runtime 收據都證實兩種倍率幾何安全。
- 2× 的文字相對畫面較大、字距緊密，且較接近 PC-98 Golden Box 常見 640×400／
  16×16 CJK cell 閱讀密度；3× 畫布較大，但字模相對較小且字間留 8 px。
- dosgolem 已支援兩倍率，所以實作成本不再是差異。

## 決策前沿

現在只有一個會阻擋後續正式實作的父層決策：正式輸出採 2× 或 3×。

- 建議：2×。理由是同頁容量不變時文字更大、字距更緊密，也與參考的 CJK Golden Box
  閱讀密度較一致。
- 3× 也可行；影響是正式畫面、收據與後續玩家驗收都改以 960×600 、較小的相對字級為準。
- 決策可逆，但之後改選需重做畫面收據、layout spec 與玩家偏好驗收。

## 確認後解鎖

1. 將 `docs/spec/002-manual-paragraph-overlay-draft.md` 的倍率、分頁格線與頁尾顯示契約升為 READY。
2. 將已完成的 manual runtime watcher 接到長存 `xlate.Layer`，只在完整題目身分後顯示段落。
3. 以正常玩家路徑驗證進入、錯答重抽、舊 generation 失效、輸入留在原版與安全矩形差異。
4. 完成後提交、推送 `main` 並更新 GitHub Issues。

## 停止線

- 使用者確認前，不把任一倍率寫成預設或正式規則，不升 READY。
- 不自動作答、不繞過手冊驗證、不改原版輸入與答案比對。
