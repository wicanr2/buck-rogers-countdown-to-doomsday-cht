# 第四十三階段：重擲提示輸入與動態欄位重畫生命週期

狀態：已完成

## 目標

從第四十二階段相同固定 state 與四次正常 BIOS Enter 路徑出發，辨識角色資料頁重擲提示
實際接受的正常輸入，量測重擲或接受結果造成的文字事件、動態欄位重畫與終點 framebuffer，
建立 content-safe、可重播且失敗即關閉的生命週期收據。

## 範圍

- 先從相同固定 state 以獨立分支測試提示畫面可能的 BIOS 鍵，不修改原版記憶體或規則。
- 以事件數、exact identity、framebuffer 差異與後續提示狀態判斷按鍵語意，不以畫面字樣猜測。
- 若確認重擲分支，固定同一 snapshot、輸入排程及原版亂數狀態，獨立重播兩次。
- 保存每筆新增事件的 step、length、SHA-256、caller、色號、座標、語意角色與證據等級；
  正式檔案不保存英文全文。
- 建立嚴格 verifier、正反例測試、dosgolem 診斷規格與研究文件。
- 完成測試與衛生檢查後，提交 dosgolem 本機分支、推送專案 `main` 並更新 Issues。

## 不在本階段

- 不翻譯角色資料頁，不建立新的繁中 catalog 或 runtime renderer。
- 不修改能力值、職業技能、亂數演算法、角色規則或存檔。
- 不以 direct-entry、記憶體注入或反覆挑選有利骰值取代正常玩家輸入。
- 不選定 2×／3×，不把固定 snapshot 的結果外推為自然開局的一般骰序。

## 成功定義

1. 由正常 BIOS 輸入證實至少一條提示分支的按鍵語意與玩家可見結果。
2. 若涉及亂數，兩次正式重播使用相同 snapshot 與等價輸入，並明示 seed／狀態證據邊界。
3. 新增事件與 framebuffer 差異具有 exact、content-safe、可回查的生命週期清冊。
4. verifier 對輸入排程、事件數、次序、step、identity、畫面與輸入雜湊漂移失敗即關閉。
5. dosgolem 規格達 CONFORMED；正式套件測試、`go vet`、相關 race detector 與專案測試通過。
6. 專案 `main` 已推送、Issues 已更新，兩個工作樹與 Docker 生命週期乾淨。

## 退出條件

- 若候選鍵都沒有可判定效果，保存負面證據並回到輸入 consumer 的窄幅逆向，不猜按鍵。
- 若重擲結果無法由相同 snapshot 決定性重生，先定位可控制的原版亂數狀態；不得重擲挑結果。
- 若輸入直接進入姓名、裝備或其他新子系統，只量到可見轉場邊界，另開後續窄切片。
