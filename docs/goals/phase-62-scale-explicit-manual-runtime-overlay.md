# 第六十二階段：明示倍率的手冊執行期繁中覆繪

狀態：進行中（等待使用者確認版面）

## 目標

在不選定正式 2×／3× 的前提下，將既有手冊 `DisplayRequest` 接到長存的 dosgolem
`xlate.Layer`；呼叫端必須明示 2 或 3，並以真實手冊固定狀態證明繁中段落只在輸出端繪製。

## 範圍

- 由已證實的安全矩形 `[7,312)×[7,184)`、正文 36×17 與單頁 catalog 契約，建立獨立
  READY 子規格。
- 在 `apps/buckrogers/` 實作遊戲專屬的手冊覆繪 presenter，不把題目位址或座標放入通用
  `xlate`。
- 接到既有 manual watcher、原版矩形清除事件與 machine frame callback。
- 以同一真實固定狀態分別重跑 2×／3×，驗證請求、像素、安全矩形、失效與原版語意隔離。
- 完成後更新專案證據、Goal、GitHub Issues；dosgolem 只提交本機 branch，不推其遠端。

## 不在本階段

- 不設定預設倍率、不替使用者決定正式採用 2× 或 3×。
- 不新增多頁內容、分頁按鍵、頁尾提示或自動答案。
- 不修改原版 EXE、VRAM、答案驗證、輸入、記憶體、檔案與存檔。
- 不把固定狀態收據外推成完整正常玩家路徑驗收。

## 完成條件

1. 子規格經證據審查達 READY 後才進 production implementation。
2. 2×／3× 都能由同一 typed request 建立單頁覆繪，缺字、超限、非法倍率與越界失敗即關閉。
3. 真實固定狀態兩倍率各至少重跑兩次，輸出決定性，安全矩形外 0 px 差異。
4. 原版事件、輸入、framebuffer、記憶體與檔案語意不因 presenter 改變；清除／新 generation
   不留下舊中文段落。
5. dosgolem 正式測試、race detector 與專案驗證通過；兩個儲存庫依授權邊界完成提交。
6. 專案 `main` 已推送，相關 GitHub Issues 已更新。

## 退出條件

- 若固定狀態缺少繪製後 frame 或清除／換題事件，不偽造正常路徑證據；先只完成可證實層級。
- 若需要決定倍率、分頁操作或改原版輸入，暫停該分支等待使用者，不擅自選擇。
- 若實作暴露安全矩形或 watcher 契約缺口，規格退回 DRAFT，先補 RE 證據。

## 本輪進度與新前沿

- 真實畫面審查證實第 17 階段整框 prototype 會遮住原版頁碼、英文標題與序數，不能直接
  進 production。
- 已重生保留上方題目的 2×／3× 對照；下方正文為 36×14＝504 字，正式最長 236 字仍單頁。
- production presenter 暫停於共同決策閘門；等待使用者選擇「保留原版題目」或「整框替換並
  另設計題目提示」。本輪不修改 dosgolem。
