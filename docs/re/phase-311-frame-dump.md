# 第三百一十一階段：自動模式畫格輸出與實機錄影版推廣片（規格 049）

日期：2026-10-01
狀態：規格 049 的實作與驗收；dosgolem `0bc270a`（fork 分支 `buck-rogers-cht-output-overlay`）。實機錄影版推廣片已在本機產出，尚未上傳 Release。
推論等級：**已證實**＝重跑並比對輸出；**未知**＝未量。
原版遊戲只在 ignored 的 `workplace/`，本文只記數字與判定。

## 1. 實作（已證實）

| 項目 | 內容 | 位置 |
|---|---|---|
| 旗標 | `-frame-dir DIR`、`-frame-every N`（預設 2，範圍 1 至 60） | `cmd/buckrogers-play/main.go` |
| 驗證 | `checkFrameDump`：沒給 `-frames`、`-frames` 為負、間隔超出範圍、沒給目錄卻給間隔、腳本含 `scale` 都是用法錯誤 | `frame_dump.go` |
| 寫入 | `finishFrame` 開頭呼叫 `maybeWrite`；不到間隔時不呼叫 `Compose`；尚無畫格時略過；`O_EXCL` 建檔、失敗刪半成品 | `frame_dump.go` |
| 檔名 | `frame-%08d.png`，編號是遊戲畫格（從 1 起），間隔倍數才有 | 規格 049 §2 |
| 結尾 | 印 `frame-dump dir=… every=N count=C first=F last=L` | `main.go` |

單元測試 `frame_dump_test.go` 九個：錯誤矩陣、目錄規則、檔名與像素往返、compose 呼叫次數、尚無畫格、compose 錯誤、尺寸不符、編碼失敗刪半成品、已存在的檔不被刪。`cmd/buckrogers-play` 整個套件測試通過，`go vet`、`gofmt` 無輸出。測試套件要有 DISPLAY（ebiten 在 import 時初始化），本機用容器內 Xvfb。

## 2. 整合驗收（已證實）

腳本同一條前 1,200 格，發行設定（Unifont、發行包 `text/`、2 倍），五次執行：

| 執行 | 旗標 | 結果 |
|---|---|---|
| `a-off` | 無 | 基準：`memory`、`cpu`、`indexed`、`palette`、`compose` 雜湊，`-shot`、`-wav` |
| `b-n3` | 每 3 格 | 400 張，`first=3 last=1200`；雜湊、`-shot`、`-wav` 與 `a-off` 逐位元組相同（不變量 1） |
| `c-n1` | 每 1 格 | 1,200 張，`first=1`（開機第 1 格已有畫格）；其餘同上 |
| `b2-n3` | 每 3 格（重跑） | 400 張的 SHA-256 清單與 `b-n3` 相同（不變量 5） |
| `e-help` | 每 3 格，第 600 格開說明頁、第 690 格關 | 400 張；第 597 格同 `c-n1`，第 600、648、690 格不同（說明頁畫格有輸出）；`-wav` 少 291,200 位元組 |

- 共有畫格（`b-n3` 對 `c-n1`，3 的倍數）400 張逐位元組相同：`Compose` 次數不影響輸出（不變量 2）。
- `b-n3` 的最後一張 PNG 解碼後與 `-shot` 的裸 RGBA 相同（不變量 4）。
- `-wav` 在無說明頁時總長 3,840,044 位元組，即 44 位元組標頭加 48 kHz 雙聲道 16 位元 20.000 秒，等於 1,200 格 / 60。`e-help` 少的 291,200 位元組等於 91 格乘每格 3,200 位元組，與說明頁開著的 91 格（第 600 至 690 格）一致：說明頁期間 `Advance` 與 `renderAudio` 被跳過（不變量 6）。
- 磁碟用量：2 倍、每 1 格約 9 KB／張；3 倍、每 2 格的 5,700 張共 152 MB，約 27 KB／張，30 fps 每分鐘約 48 MB。
- 牆鐘速度：2 CPU 容器內約 21 至 41 格／秒，低於 60，但畫格以遊戲畫格計，輸出與速度無關。

## 3. 實機錄影（已證實）

`tools/promo/record.sh`：同一份發行設定，3 倍、每 2 格，11,400 格（190 秒遊戲時間），輸出畫格與 `-wav`，約 9 分鐘牆鐘。輸入腳本從冷開機走到標題、主選單、載入隊伍、救世站、港口、發射、太空殘骸、登船與鬼魂場景，腳本中的 `lang` 動作在遊戲第 7700、7775、7850、9760 格切語言。

- 切語言不改變遊戲：有 `lang` 動作的錄影（`rec1`）與無 `lang` 的探勘執行（`q2`）在第 11,400 格的 `memory_sha256`、`cpu_sha256` 相同（規格 040 §5.4 的前端不變量，這次在長路徑上再驗一次）。
- 手冊查詢題：腳本在冷開機後會遇到手冊查詢題，題目隨輸入時序而變。前一版探勘腳本的作答對不上這次的題目，遊戲在第 5,500 格結束（強推論：答錯後結束；未另做對照）；改用本機手冊摘錄核對題目重新作答後可通過。**作答只存在 ignored 的 `workplace/`，不進 Git。**題目與作答畫面（第 3,100 至 4,000 格）不入片，`play-make.sh` 以 `BAN` 範圍擋住與它重疊的分鏡。

## 5. 踩到的

| 症狀 | 原因 |
|---|---|
| ffmpeg 報 `Failed to configure output pad on auto_scale`、`Resource temporarily unavailable`，換濾鏡組合都一樣 | 容器 `--pids-limit 64`：ffmpeg 預設的執行緒數超過上限，執行緒建立失敗（EAGAIN）被濾鏡層回報成配置失敗。`--pids-limit 256` 並限 `-filter_threads 2`。與像素格式無關，別去調 `format=`。 |
| 迴圈只跑第一段分鏡 | `while read` 讀 TSV 時 ffmpeg 吃掉標準輸入；加 `-nostdin`。 |
| 語言切換在奇數畫格，分鏡找不到畫格 | 畫格每 2 格輸出，`lang` 動作在奇數格生效時，切換後的第一張是下一個偶數格；分鏡邊界要取偶數。 |
| 舊腳本在新建置上走到第 5,500 格就結束 | 手冊查詢題因輸入時序不同而換題，舊作答不適用。腳本的手冊作答要隨建置與時脈重新核對。 |
