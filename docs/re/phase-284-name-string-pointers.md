# 第二百八十四階段：印字呼叫的名字字串指標

日期：2026-09-29
用途：規格 038（玩家角色名判定與顯示）§3.2／§3.3 的原版證據：ECL 印字 `0763:056C` 與引擎 dispatcher
`0763:0424` 進入時，字串指標指向哪裡，以及能否從結構上分出「玩家名」與「一般文字」。
原始紀錄、腳本與重播輸出只在 ignored `workplace/phase284-name-pointer/`。原版樹 `workplace/original/BRcdoom`
（`GAME.OVR` SHA-256 前綴 `3a4ad4856c08fe59`，`START.EXE` 前綴 `58a34a38b1db4552`），唯讀。

## 方法

- 探針 `tool/main.go`（獨立 module，`replace` 指到 `workplace/dosgolem-clean`，不改該樹）。從 phase-257 的
  `cp/<前一步>.state` 載入，照原紀錄的按鍵與步數重播一步，在 `0763:056C`／`0763:0424` 進入時記下：
  呼叫端與其 CodeKey（`apps/buckrogers.OverlayUnits`）、字串 far pointer、指標落點、`[DS:4EC5]` 鏈（DGROUP 0EC0）
  與隊員數 `[DS:3BCC]+0x33E`、`[DS:4EC1]`、ECL 運算元表（見 §2）。另有寫入監看（`-watch`）、讀取監看（`-rwatch`）
  與指令軌跡（`-it-from/-it-to`）。探針自身的讀取不觸發讀取監看。
- 重播 118 步，115 步的 W／D 事件步數序列與 phase-257 原紀錄逐列相同，只採用這 115 步；另 3 步
  （`b5`、`d21`、`x1`）因前一狀態挑錯而不一致，已剔除（`runs/aux/mismatch/`）。
- 採用範圍：`0763:056C` 事件 2,421 筆，其中 ECL 印字呼叫端（`OVR:00904:0B79`／`0B4A`）125 筆；`0763:0424` 事件 5,241 筆。
- 讀取監看的正對照：同一步監看 ECL 變數區 `3ADB4–3ADC8`，讀到 `OVR:1CA15:149E`／`14D6` 逐字讀取（§2），
  確認「記錄區零讀取」不是監看失效。
- 全部在 Docker、`--network none`、`--cpus 2`、`--memory 3g`。

## 1. ECL 印字 `0763:056C`（Q1）

| 項目 | 結果 | 等級 |
|---|---|---|
| ECL 呼叫端（`OVR:00904:0B79` 旗標 1、`0B4A` 旗標 0）的字串指標 | 125 筆全部為 `0EC0:6EDC`（`DS:6EDC`）。同 unit 的 `OVR:00904:1215`（選單提示，2 筆）另在堆疊 | 已證實 |
| 玩家名（36 筆，6 人皆有）的指標 | 全部 `DS:6EDC`，**沒有一筆指向鏈上記錄** | 已證實 |
| 一般 ECL 文字（`YOU ARE AT A LADDER.`、` ATTACKS.`、長敘事、數字等 89 筆）的指標 | 同樣 `DS:6EDC` | 已證實 |
| `DS:6EDC` 的性質 | ECL 直譯器的「第 1 個運算元字串緩衝」：`DS:6DDC + idx×0x100`，idx=1 | 已證實（§2 軌跡） |
| 引擎端 `056C`（戰鬥訊息 `OVR:27BBE:0AE5`、`OVR:114F6:05A4` 等） | 堆疊暫存（`SS:3Bxx–3Fxx`）或 `OTHER`（`OVR:27BBE:05E7` 武器名）；名字只以嵌入整句出現（例 `<名字> makes his tactics roll.`，9 筆） | 已證實 |

### 1.1 `DS:6EDC` 的內容從哪來（已證實，指令軌跡＋讀寫監看）

ECL 運算元載入器在 overlay unit `1CA15`（本次段 2DEB／2FCF）。先清緩衝 `1CA15:135C`
`C6 85 DC 6D 00`（`mov byte [di+6DDC],0`），再依運算元型別填入：

| 運算元型別 `[DS:6D99+idx]` | 位址 | 來源 | 樣本 |
|---|---|---|---|
| `0x80` | — | 位元組碼內嵌字面文字（`1CA15:00FA` `3C 80 75 39`） | 83（全部是一般文字） |
| `0x81` | `7C00` | **直接**把 `[DS:4EC1]` 指向記錄的 +0x00（Pascal 字串）整串複製進緩衝：`1CA15:13EB` `81 7E 06 00 7C 75 22 C4 3E C1 4E 06 57`（`cmp word [bp+6],7C00`／`les di,[4EC1]`），複製由 RTL `0CF4:0655/0661` 自 `5747:0002` 讀出 | 1（n1：`FLAVIUS`，讀取監看見 `57472–57479`） |
| `0x81` | `7Axx–7Bxx` | ECL 字串變數：C 字串於 `[DS:3BD0]:(位址+0x8600)`（16 位元環繞；本次 `3AC1:01A4` 為 `7BA4`），`1CA15:149E` `26 80 BD 00 86 00` 逐字讀、每字以字串相加附加到緩衝 | 名字 35（`7BA4` 34、`7BCC` 1）；非名字 3（`7B90` `BELOW`、`7BB8` `GIRL`／`HIM`）；名字與文字相接 1（`7B90`，門禁句） |
| `0x01` | `4C4A` | 數值變數轉字串 | 2（數字） |

- ECL 變數 `7BA4` 的名字由 ECL 指令寫入（d6206，#21,898,979,331）：`OVR:00904:2DCF` 起依 `[DS:6D13]` 分派，
  值 `09` 走 `OVR:00904:2E20` `3C 09 75 07 0E E8 7F D4` → handler `OVR:00904:02A7`；該指令第 1 運算元為
  `0x81@7C00`（見上表，自 `[4EC1]` 記錄複製名字到 `DS:6EDC`，讀取監看見 `5747:0002` 起 8 位元組），
  再由 `OVR:1CA15:1104`（`26 88 …` 寫 `3AC1:7BA4` 起）寫成 C 字串。位元組碼 `09 81 00 7C 81 A4 7B`（pc `91CF`）。
  等級：寫入點與來源已證實；「opcode 09 是字串存入」為強推論（只見此一例）。
- `7BA4` 不一定是 `[DS:4EC1]` 目前角色：d65 的 `ROARKE`（`7BA4`）印出時 `[4EC1]` 指 FLAVIUS（已證實，1 例）。
  其餘 34 筆名字樣本 `[4EC1]` 與名字記錄相同。
- `7BCC` 的寫入者未追（1 例），推測同上（假說）。

結論：ECL 名字與一般文字共用同一個運算元緩衝 `DS:6EDC`，內容已被複製；指標本身不能分辨名字。

## 2. 引擎 dispatcher `0763:0424`（Q2）

| 呼叫端 | 起始欄（`args[5]` 低位元組） | 指標 | 筆數 | 等級 |
|---|---|---|---|---|
| `OVR:2BA60:235A` | 23（戰鬥右欄） | 鏈上記錄 +0x00，index < 隊員數，且與畫面名字同一筆 | 686 | 已證實 |
| `OVR:2BA60:235A` | 23 | 鏈上記錄 +0x00，index ≥ 隊員數（怪物） | 821 | 已證實 |
| `OVR:2BA60:235A` | 8／17 | 鏈上記錄 +0x00，隊員 | 5、65 | 已證實 |
| `OVR:2BA60:21DE` | 17 | 鏈上記錄 +0x00，隊員 | 11 | 已證實 |
| `OVR:081D9:1A07`／`1A1F` | 1／18 | 鏈上記錄 +0x00，隊員 | 21、21 | 已證實 |

- 指標的 seg:off 與鏈上 far pointer（`+0xFF` 存的 off, seg）逐欄相同，1,630 筆無例外（不只線性位址相同）。
- 欄 23 樣本 63 個重播步，6 名隊員全有；列 1、10、12、16（另列 15 有 3 筆）；怪物 6 種。
- 欄 23 的其他字串（`Hitpoints`、`AC`、`(blinded)`、`and is Dying`；呼叫端 `OVR:27BBE:051D`、`0560`、`06E7`、
  `OVR:114F6:062D`）都在堆疊暫存，不是名字。
- 名字經 dispatcher 且不在記錄上的只有 `0763:1282` 的 `<名字> leads <怪物名>.`（2 筆，堆疊，整句），不屬欄 23。
- 同名怪物（例如多隻 `TERRINE WARRIOR`）各指向自己的記錄；用「名字字串相等」只能判定是否同名，判定隊員要用
  「指標等於前 N 筆之一」或 +0x4C。

## 3. 區分名字與一般文字的結構訊號（Q3）

| 路徑 | 訊號 | 等級 |
|---|---|---|
| dispatcher（`235A` 等） | 指標直接等於鏈上前 N 筆之一 → 隊員名；等於第 N 筆以後 → 怪物名。不需比字串 | 已證實 |
| ECL `056C` | `056C` 進入時讀 ECL 運算元表：`[DS:6D9A]`（第 1 運算元型別）、`[DS:6DDA]`／`[DS:6E1A]`（位址高／低位元組） | 已證實（125 筆全部與內容一致） |
| ECL，型別 `0x80` | 字面文字，83 筆無一是名字 → 可判定「不是玩家名」（例如玩家取名與 ECL 短片段同形時） | 強推論（機制已證實；樣本內無同形名） |
| ECL，型別 `0x81@7C00` | 直接取自 `[4EC1]` 記錄的名字 | 已證實（1 例＋程式碼） |
| ECL，型別 `0x81@7Axx–7Bxx` | ECL 字串變數；可能是名字、代名詞或「文字＋名字」合成，仍需與隊伍快照比對內容 | 已證實 |

- 沒有專門的「名字替換」opcode；名字是以一般運算元（`0x81` 變數）進入印字。
- 運算元表位址是 DGROUP 固定偏移（本次 DS=0EC0，所有 `056C` 事件 DS 皆為 0EC0）；覆繪程式應以 hook 當下 DS 讀取。
- dispatcher `0763:0424` 進入時的 DS：原始紀錄 5,241 筆全部為 `0EC0`（已證實，限本次重播涵蓋的畫面）。

## 4. 對規格 038 的含意

- §3.3 戰鬥右欄：可以用「指標 == 鏈上前 N 筆」判定玩家名，比字串比對更強，也自然排除怪物與同形字串。
- §3.3 ECL：`DS:6EDC` 是共用緩衝，不能用指標判定；可用「型別 `0x81` 且內容等於快照中名字」判定玩家名，
  型別 `0x80` 一律照 catalog。這能取代 §3.2 第 2 條「一般文字查表位置」的描述。
- 門禁句類（變數內已是「文字＋名字」）仍在 §4「不處理」範圍。
