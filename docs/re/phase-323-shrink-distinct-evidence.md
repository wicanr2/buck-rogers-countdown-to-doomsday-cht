# 第三百二十三階段：ja、ko 縮小字模相同組的量測（規格 057、058 的證據）

日期：2026-10-03
狀態：量測完成，規格 057、058 為 DRAFT。這份文件只記量測；實作與驗收收據另寫在規格 CONFORMED 時的 phase 文件。
推論等級：**已證實**＝重跑並比對輸出；**強推論**＝由輸出目視推得；**未知**＝未量。

## 1. 起因

規格 056 的 phase-322 §4.2 列出縮小後字模相同的組：ja 在 L2 有濁點消失（`カ`／`ガ` 同形），ko 在 2× L2 有 315 組音節同形。使用者 2026-10-03 回覆：ja 的濁音要與清音可分；ko 的音節字模相同不同意，需要完善韓文顯示；依語言開對應規格。

## 2. 方法（已證實）

- 輸入：dosgolem `bba48d9`；正式字型 `buckrogers-ja.golemfnt`（SHA-256 `67fd7ac928120b50b0ba701def0741921c8c18110d6ba083a3df821e5adb1c06`）、`buckrogers-ko.golemfnt`（`dea3568a0f764b604764e835083dbc45e1c9ff3569bbf9f46d9a1a58f4ae674a`）；Buck `text/` tree `3ac90be6aaf48e34a30196ec7526919b56194fcc`。
- 字元集：規格 056 §5.1 靜態檢查的字元集（`translit-chars.<lang>.tsv` 的允許字集與 `name-glossary.<lang>.tsv` 的譯名用字，ASCII 另計），取其中全形且來源字模有墨者：ja 88 字、ko 2,128 字。來源字模位元組相同的字：ja 0 組、ko 0 組。
- 衍生：16×16 底字型對目標尺寸 W×H 的面積規則，門檻 n/d：目標像素有墨面積 × d ≥ n × 面積才點亮（規格 056 為 n/d = 1/2），與 `resampleInk` 同一計算；不套用保底規則（量測的字模都有墨）。
- 腳本：`workplace/phase323/zz_exp_test.go`（SHA-256 `2ed7d0d407b568db1b27bea9fec0027de15f1418e054cae91f39d0f63f1720d4`，暫時性實驗檔，不進 dosgolem）；`workplace/phase323/runexp.sh '<測試 regex>'` 從 `bba48d9` 的 `git archive` 乾淨匯出，加入實驗檔，在 Docker 內（`--network none`，唯讀掛載）執行。
  測試：`TestZZExp`（ja、ko 的尺寸與門檻格）、`TestZZExp2`（ko 3× 與半形 ASCII）、`TestZZExp3`（ko L2 候選格）、`TestZZExp4`（兩個語言的選定組合）、`TestZZExp5`（現行 L2 的相同組樣本）、`TestZZExp6`（ja 清濁對與來源相同字）、`TestZZExp7`（字模像素）、`TestZZExp8`（ko 母音對）、`TestZZExp9`（字模間距離）、`TestZZSheet`（對照圖，`ZZ_OUT` 指定輸出目錄）。

## 5. 半形 ASCII（已證實，不在規格 057、058 範圍）

94 個可列印 ASCII 從 8×16 半形字型衍生：門檻 1/2 時 4×8 有 `0`／`O`、`1`／`l`、`[`／`|` 三組，4×12 為 0 組，6×12 有 `H`／`M`，6×14 有 `M`／`W`，6×16 有 `8`／`B`、`M`／`W`，8×16（L0）為 0。這是所有語言共有的問題，另案。
