## 畫面不是先清空再重建

窄時間窗取樣顯示，Enter 被取走後舊題畫面不會先整面清空。#301,127,834（新題首 entry
前一步）相對原始題目只差輸入游標區 64 px；到 #301,155,000 才出現新頁碼的 26 px 差異。
`026F:029C` 直到 #301,166,163 才進入，之後標題列才改變。也就是新題前三筆文字與舊題
共同存在一段時間，局部矩形清除不是整題 generation 的起點。

因此以下兩種策略已被實際反例排除：

1. 等畫面成為空白才使舊中文覆蓋失效；原版沒有這個中間畫面。
2. 看到任一新字串或頁碼就立刻畫新中文；稍後的局部清除仍可能破壞過早畫出的內容。

## DRAFT 失效契約

以下是由本路徑支持的最小設計，尚未進 production：

1. 只在 `0763:0424` 由固定呼叫端 `2A33:01ED` 輸出精確題首
   `In the Log Book on page` 時開始新手冊題目世代；立即移除舊中文段落及其 metadata。
2. 新世代逐筆累積頁碼、英文標題與序數。欄位缺失、重複、順序錯誤或跨世代時失敗即關閉。
3. `2A33:0309` 的 `word?` 只在第七階段的 guarded post-call 條件成立後，才代表整題英文
   已畫完；此時才以三欄精確匹配 catalog 並覆繪繁中段落。
4. 中途的 `026F:029C` 仍使相交 overlay 失效，但不得單獨建立新題世代，也不得觸發舊
   metadata 重用。若它在 `word?` 前發生，只維持 pending，不畫中文。
5. 空字串、輸入游標或答題內容均不可當成題目身分；覆繪不得送鍵或代答。

題首呼叫端與字串在本遊戲這條路徑已證實；是否涵蓋所有手冊入口仍是**強推論**，正式
adapter 必須以未命中即不顯示及正常玩家路徑 A/B 測試護欄。`word?` 的 guarded post-call
組合沿用第七階段已證實的 stack 契約；本階段沒有新增通用 dosgolem API。

## 結論與剩餘缺口

舊題失效與新題顯示現在已有不依賴畫面空白或亂數內容的事件邊界：題首 entry 開新世代，
終端 `word?` post-call 才允許顯示。這足以把錯答 generation 測試列入 adapter 的 READY
前置，但尚未完成 adapter、中文覆繪 A/B、分頁輸入或使用者的 2×／3× 決策，所以規格維持
DRAFT。
