# 第四十二階段：確認職業後的角色資料文字路徑

## 結論

從 #99,999,999 固定 state 依序送出四個正常 BIOS Enter，原版接受預設種族、性別與職業，
先把職業 selected 列重畫成 normal，接著輸出角色資料／重擲能力值畫面。相較第三十八階段
的 22 筆既有前綴，本階段新增 96 筆 guarded post-call 完成事件。

畫面包含固定欄位標籤、空白姓名、種族／性別／職業等角色值、能力值、職業技能、動態數值、
重畫及最下方的重擲提示。這些事件不能一律視為可翻譯字串；`text/post-class-events.tsv` 以
`event_role` 明確區分其輸出角色，正式資料只保存 identity 與語意分類，不保存英文全文。

## 事件結構

新增事件 #1 是原職業列的 normal-style 重畫；#2–20 建立角色資料頁固定標籤；#21–28 輸出
空白姓名與角色身分／摘要值；#29–42 是七組能力縮寫與初始值；#43–49 補上摘要動態值；
#50–65 輸出八組職業技能與數值；#66–72 覆寫七個能力值；#73–95 再畫摘要與技能區動態值；
#96 輸出重擲提示。每筆完整 step、caller、長度、雜湊、色號及座標見清冊。

一次性 framebuffer 檢視用來辨識上述版面角色；原版二進位短字串雜湊反查沒有找到靜態直接
副本，沒有因此猜測壓縮或解碼機制。這不妨礙以 runtime 完成事件建立 exact identity。

## 亂數邊界

同一 state 的兩次事件與畫面完全一致，已證實此 snapshot 可重生同一組能力值與衍生值；但
本階段沒有獨立定位 seed、亂數實作或呼叫次數。因此只把「固定 snapshot 的可重播輸出」列為
已證實，不把相同數值外推到自然開局、其他 state 或其他職業，也不把固定測試結果寫回正式
遊戲規則。
