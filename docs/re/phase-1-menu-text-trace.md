# 第一階段：功能選單文字輸出追蹤

日期：2026-09-20  
範圍：由[輸入與啟動收據](phase-1-input-and-startup.md)的固定狀態、BIOS 空白鍵與原版
流程到達的第一個功能選單。這是原版觀測證據，不是中文覆繪規格或實作授權。

## 玩家可見檢查點

在 #100,000,000 的 Mode 13h 畫面可辨識原文選項：

```text
ADD CHARACTER TO TEAM
LOAD SAVED GAME
BEGIN MOUSE INITIALIZE
EXIT TO DOS
CHOOSE A FUNCTION
```

這是對螢幕可見短字串的人工轉錄；不是抽出、保存或散布完整原版文字資料。

## 位址空間契約

本文件的 `0763:xxxx` 是 **dosgolem 執行期實模式段:位移**。它來自在真實原版執行期間
的 CPU 追蹤，不能與 `START.EXE` 的 IDA 資料庫線性位址互換，也不能據此替換 IDA 原始
定位或宣稱已靜態定位到 `GAME.OVR` 的檔案偏移。

| --- | --- | --- | --- |
| 正常流程入口 | #71,000,214，INT 16h AH=00 從 BDA 取走 `0x20` | 已證實 | 原版在固定狀態接受空白鍵；不是 IRQ1 `-press` 或記憶體 poke。 |
| 資料載入 | #71,004,511 seek `GAME.OVR` 到 96,666；#71,004,516 讀 14,998 bytes；#71,004,529 再讀 696 bytes | 已證實 | 選單轉場期間原版確實讀取覆蓋檔；尚未知哪一段含高層文字。 |
| 原始輸出 callsite | #71,130,187，`0763:1855` 寫 `A0000:838A`：`00 → 0A` | 已證實 | 原版正在執行時將一個可見文字像素寫入 Mode 13h VRAM。模組檔案歸屬仍未知。 |

| 每字元資料 | 繪製期間 `DS:SI=3D21:000A`，在 `0763:1843` 出現資料值 `0x005E`，隨後以位元遮罩繪出 | 強推論 | 這是目前字形／glyph 資料的執行期來源；未證實為原文 ASCII、編碼表、或高層字串起點。 |

| 清除／捲動時機 | 本路徑只量到由標題轉為選單的重繪；未孤立出清除或捲動事件 | 未知 | 不得假設覆繪可永久保留，亦不得把「未觀測」寫成「沒有清除／捲動」。 |

## 可重生追蹤收據

原始輸出位址的直接證據在被忽略的
`workplace/probe/menu-text-entry-writes.log`；以 `-watch A0000-AFFFF` 取得。暫存器收據
在 `workplace/probe/menu-text-entry-summary.log`；它使用 `-regs-at 0763:1855` 和
`-regs-from 71130000`。這兩個收據均由 dosgolem commit
`d9c0c27ca9af8239c7e96272a7165e03d7da04bf` 從同一 `start-70m.state` 重生。

`0763:03C8` 曾由堆疊觀察成可能的呼叫端，但後續定址追蹤沒有在量測窗中命中；因此它是
**未知**，不列為 call graph 事實，也不以推測名稱覆蓋任何原始位址。

## 對下一階段 DRAFT 的最小充分資料

已足以撰寫的 DRAFT 邊界如下：僅可把「固定原版輸出事件、原始執行期地址、觀測到的
VRAM 受影響矩形／像素、原文顯示鍵與畫面生命週期」列成待審核欄位；初始 interception
候選可包含 `0763:1855` 所屬的原始 pixel primitive，但不得在此階段把它當成穩定的
中文句子 hook。DRAFT 必須明列高層字串來源、完整 glyph 寬度、font 對應、清除與捲動
為未解證據，並在進入正式程式路徑前升為 READY。

因此，本階段沒有寫入 `apps/buckrogers/`、`text/`、`font/` 或 dosgolem 程式碼，也沒有
顯示任何中文。這保留了原版輸出端覆繪的邊界，而非改寫遊戲語意。
