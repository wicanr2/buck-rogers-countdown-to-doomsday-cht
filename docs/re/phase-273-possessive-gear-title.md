## 2. unit 換算（強推論）

- 同一次執行結束時的記憶體（`gt -until 1 -mem-out`）：`216E` 是 unit `2BA60`（stub `21F`，
  code size `24F1`），`24AA` 是 unit `21832`（stub `1E2`）。印字與結束之間沒有逐步確認 overlay
  換入，所以是強推論；與 phase-266 其他狀態的對應相同。
- 位址：`OVR:2BA60:2391`（所有格）、`OVR:21832:1C20`（Gear）、`OVR:21832:1C41`（Ready Item）。`OVR:2BA60:235A` 已是名稱呼叫端。

## 3. 字串來源（已證實，位元組）

- 掃描方法：在 `GAME.OVR`、`START.EXE` 找位元組序列 `02 27 73`（長度 2 的 Pascal 字串 `'s`）。
  `GAME.OVR` 只有檔案位移 0x2DD1B（十進位 187675）一處；`START.EXE` 沒有。
- 0x2DD1B − 0x2BA60 = 0x22BB，落在 unit `2BA60` 的程式範圍內，位於 `2391` 之前（0x22BB 小於 code size 0x24F1），
  符合 Turbo Pascal 把字串常數放在使用它的函式前面的配置（強推論，未反組譯確認引用）。
- 片段抽取工具只收「含兩個以上連續英文字母」的字串，所以 `'s` 原本不在 catalog。
