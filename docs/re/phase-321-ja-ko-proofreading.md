## 2. 流程（已證實）

| 階段 | 做法 | 規模 |
|---|---|---|
| 輸入 | `<lang>-l10n/batches/` 的 46 個批次（英文、繁中、寬度上限、控制碼）併回現行 `text/` 的繁中與 ja／ko 譯文；繁中有 10 列自批次製作後已改，輸入用現行值。每批附該批用到的詞表列。基線：全部批次的現行譯文通過 `check_done.py` 規則與正式字集。 | 每語言 46 批加手冊 1 份 |
| 第一輪：校對 | 每批一個 sonnet 代理，只回修正列（key、新譯文、等級 A 意思錯／B 語言錯／C 偏好、理由）。指令明列已定案寫法與詞表處理原則（同概念的表記差異不改，避免全案不一致）。交出前跑 `check_fix.py`（`check_done.py` 規則、手冊用 `manual_lang.py` 規則、正式字集 `font/charset.<lang>.txt`）。 | 94 個批次代理，另 2 個音譯代理 |
| 第二輪：裁決 | 另一位獨立審查者（opus）看英文、現行、提案與理由，判 accept、reject、alt。裁決輸入附「新舊差異片段在全案的出現次數」，用來擋掉只改單列、破壞全案一致的詞表對齊。另加連帶檢查列：同英文雜湊的其他家族列、另一語言同 key 被判 A 的列，由裁決者獨立判斷同樣問題是否存在。 | 9 份（ja 5、ko 4），每份至多 30 列 |
| 合併 | 採用的列以 key 套進 `text/<family>.<lang>.tsv` 的 `translation` 欄，其餘欄與檔案位元組不動；同雜湊同譯文的兄弟列同步。 | 見 §3 |
| 驗證 | `tools/ja_check.sh`、`tools/ko_check.sh`、`font/characters.<lang>.txt` 重建、dosgolem 全套件與 trace 重播閘門（§4）。 | |

所有 Python 都在 Docker（`python:3.12-slim`、`--network none`、目前 UID/GID）執行，工具在 ignored 的 `workplace/proof41/`。代理邊界寫在每個 prompt：只寫自己的輸出檔，不 commit、push、清理、重編，不用 docker prune 與 rmi。
有一個代理為查詢某個字串的前後文，在主機以 python3 唯讀讀了原版 `START.EXE` 約 80 位元組，沒有寫任何檔；它自己回報為流程偏差，未造成影響。
代理用量為估計值：96 個 sonnet 代理平均每個約 12 萬 token（合計約 1,200 萬），9 個 opus 裁決代理合計約 70 萬。

## 7. 做法教訓

- 提示「詞表一律照用」會讓校對者把詞表對齊當成 A 或 B 級錯誤；詞表是各批新增的草案，同一英文詞可有兩種寫法時，對齊會造成全案不一致。第二輪必須附全案出現次數，並在第一輪指令寫明「同概念的表記差不改」。
- 兩個家族共用同一個英文雜湊時（選單與引擎片段、物品與引擎片段），改一邊必須連帶檢查另一邊；裁決輸入要自動帶出兄弟列，合併後再補同步，否則同一個字串在兩條顯示路徑出現兩種寫法。
- 校對者用「同英文在別處的譯法」佐證時，常引用尚未校對的別批；第二輪的獨立審查者才看得到全貌。
- 修正檔的檢查要與正式檢查同源（同一份 `check_done.py`、同一份正式字集），否則代理通過的修正會在合併後被正式檢查擋下。
